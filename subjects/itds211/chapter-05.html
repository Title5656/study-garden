3.1 · Memory hierarchy (ภาพรวมลำดับชั้น)

จะได้หน่วยความจำทั้งเร็ว ใหญ่ และราคาต่ำพร้อมกันอย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 1–3 เปิดดูต้นฉบับในเครื่อง ↗

บทนี้เชื่อมเรื่องเทคโนโลยีหน่วยความจำ การออกแบบแคช การวัดประสิทธิภาพ ความทนทาน เครื่องเสมือน หน่วยความจำเสมือน และตัวควบคุมแคชเข้าด้วยกัน ปกและ Course Outline ระบุตำแหน่งของบทหลังภาษาแอสเซมบลีและก่อนระบบ I/O ส่วน Chapter Overview ชี้ว่า associative cache และ finite state machine เป็นเนื้อหาของบทด้วย จึงต้องเรียนถึงวิธีควบคุมการทำงานจริง ไม่หยุดที่ความหมายของแคช.

3.2 · Locality and hierarchy (การใช้ซ้ำและลำดับชั้น)

ทำไมเก็บข้อมูลเพียงบางส่วนใกล้ CPU แล้วโปรแกรมยังเร็วได้?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 4–8 เปิดดูต้นฉบับในเครื่อง ↗

Principle of locality (หลักการใช้พื้นที่ใกล้เดิม) หมายถึงในช่วงหนึ่งโปรแกรมมักใช้เพียงส่วนเล็กของ address space (พื้นที่หมายเลขที่อยู่ทั้งหมด). Temporal locality (การใช้ซ้ำในเวลาใกล้กัน) เช่นคำสั่งในลูปและตัวแปรนับรอบ; spatial locality (การใช้ตำแหน่งใกล้กัน) เช่นคำสั่งถัดไปและสมาชิกอาร์เรย์ที่ต่อกัน. [อธิบายเสริม] เหมือนหยิบหนังสือเล่มเดิมซ้ำและหยิบหน้าถัดไป จึงคุ้มที่จะวางทั้งเล่มไว้ใกล้มือ.

Memory hierarchy (ลำดับชั้นหน่วยความจำ) คัดลอกข้อมูลที่ใช้และข้อมูลข้างเคียงจากดิสก์ขึ้น DRAM หรือ main memory (หน่วยความจำหลัก) แล้วคัดบางส่วนขึ้น SRAM ที่ใช้เป็นแคช ภาพพีระมิดเรียง registers (ที่เก็บใน CPU), cache, main memory เป็น inboard memory; ถัดลงมาเป็น magnetic disk และสื่อแสง CD/DVD/Blu-ray; ชั้นล่างเป็น magnetic tape สำหรับ off-line storage. ใกล้ยอดยิ่งเร็วและเล็ก ลงล่างยิ่งจุได้มากแต่เข้าถึงช้ากว่า.

ภาพ Cache and Main Memory มีลูกศรสองทิศ CPU↔cache ส่งระดับ word ส่วน cache↔main memory ย้ายเป็น block หรือ cache line (บล็อกข้อมูลที่คัดลอกเป็นหน่วยเดียว อาจมีหลายเวิร์ด). ภาพสามชั้นต่อ CPU↔L1↔L2↔L3↔main memory; L1 เร็วที่สุดแล้วช้าลงทีละชั้น. Hit (พบข้อมูล) คือชั้นบนตอบคำขอได้; miss (ไม่พบ) ต้องนำบล็อกจากชั้นล่างขึ้นมา แล้วจึงส่งข้อมูลที่ต้องการ. Hit ratio = จำนวน hit/จำนวนครั้งเข้าถึง; miss ratio = จำนวน miss/จำนวนครั้งเข้าถึง = 1−hit ratio; miss penalty (เวลาเสียเพิ่มเมื่อพลาด) รวมการรอให้ได้บล็อกที่ต้องใช้.

3.3 · SRAM and DRAM (เทคโนโลยีหน่วยความจำ)

ทำไมหน่วยความจำหลักใช้ DRAM แต่แคชใช้ SRAM?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 9–13 เปิดดูต้นฉบับในเครื่อง ↗

Static RAM หรือ SRAM (แรมแบบสแตติก) เก็บสถานะด้วยวงจรและไม่ต้อง refresh แบบ DRAM ขณะมีไฟ; Dynamic RAM หรือ DRAM (แรมแบบไดนามิก) เก็บประจุใน capacitor (ตัวเก็บประจุ) โดย transistor (ทรานซิสเตอร์) ควบคุมการเข้าถึง ประจุรั่วจึงต้อง refresh (อ่านแล้วเขียนคืนเป็นระยะ) เป็นแถว. ทั้งสองเป็น volatile memory (ไฟดับแล้วข้อมูลไม่คงอยู่). ตารางต้นฉบับเป็นตัวเลขยุคของเอกสาร ใช้แสดงข้อแลกเปลี่ยน ไม่ใช่ราคาเสนอซื้อปัจจุบัน.

ภาพ DRAM แสดงหลาย bank (กลุ่มหน่วยความจำที่ทำงานแยกกัน) แต่ละ bank มี rows (แถว) และ columns (คอลัมน์). Act เปิดแถว, Pre เตรียมปิด/เตรียมแถวใหม่, Rd/Wr เลือกอ่านหรือเขียนคอลัมน์. Row buffer (ที่พักข้อมูลทั้งแถว) ทำให้ใช้หลายเวิร์ดจากแถวเดียวกันและ refresh ขนานกันได้. Burst mode (ส่งต่อเนื่องเป็นชุด) ส่งเวิร์ดถัดไปจากแถวที่เปิดอยู่โดยไม่เริ่มเข้าถึงเต็มกระบวนการทุกครั้ง. Synchronous DRAM (DRAM ที่ทำงานตามนาฬิกา) ช่วยส่งต่อเนื่องและเพิ่ม bandwidth (ปริมาณข้อมูลต่อเวลา); banking เปิดโอกาสทำหลาย bank ซ้อนหรือพร้อมกัน.

Double data rate หรือ DDR (ส่งข้อมูลทั้งขอบขึ้นและขอบลงของนาฬิกา) เพิ่มอัตราส่งโดยไม่ต้องเพิ่มความถี่นาฬิกาเป็นสองเท่า. QDR ในสไลด์แยกทางเข้าและออกแบบ DDR. ตารางพัฒนาการแสดงความจุต่อชิปเพิ่มและราคาต่อ GB ลด ส่วนกราฟ Trac และ Tcac ลดลง แต่ความเร็วไม่เพิ่มตามความจุในอัตราเดียวกัน. [อธิบายเสริม] Trac อ่านว่าเวลาเข้าถึงโดยอ้างอิงการเลือกแถว และ Tcac โดยอ้างอิงคอลัมน์; กราฟไม่มีตารางค่าที่ละเอียด จึงใช้ดูแนวโน้มแทนการอ่านเป็นค่ารับประกัน.

3.4 · Memory bandwidth (ส่งบล็อกให้เร็วขึ้น)

ถ้าต้องอ่านสี่เวิร์ด จะรอ DRAM สี่รอบเสมอหรือไม่?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 14 เปิดดูต้นฉบับในเครื่อง ↗

ภาพเปรียบเทียบ one-word-wide memory (หน่วยความจำกว้างหนึ่งเวิร์ด), wider memory (กว้างหลายเวิร์ด) และ interleaved memory (กระจายเวิร์ดสลับ bank). แบบกว้างสี่เวิร์ดส่งข้อมูลทั้งสี่พร้อมกันบนบัสกว้างแล้วใช้ multiplexer (วงจรเลือกข้อมูล) ส่งต่อให้ CPU; แบบสี่ bank เริ่มอ่านหลาย bank ซ้อนกันแต่ทยอยส่งบนบัสเดิม. สำหรับบล็อก 4 เวิร์ด เวิร์ดละ 4 ไบต์ แบบกว้างใช้ 1 รอบส่งที่อยู่+15 รอบอ่าน+1 รอบส่งข้อมูล=17 bus cycles จึงได้ 16/17≈0.94 ไบต์/รอบ ส่วน 4-bank ใช้ 1+15+4×1=20 รอบ ได้ 16/20=0.8 ไบต์/รอบ. ความเร็วรวมไม่ได้วัดจาก latency ของเซลล์เพียงอย่างเดียว; ความกว้างบัสและการทำงานซ้อนกันมีผลด้วย.

3.5 · Flash storage (เก็บประจุให้คงอยู่)

จะเก็บข้อมูลเมื่อไม่มีไฟโดยไม่ใช้จานหมุนได้อย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 15–16 เปิดดูต้นฉบับในเครื่อง ↗

Flash (แฟลช) เป็น nonvolatile semiconductor storage (ที่เก็บข้อมูลวงจรที่ไม่สูญข้อมูลเมื่อปิดไฟ). สไลด์เปรียบว่ารวดเร็วกว่าดิสก์ 100–1000 เท่า เล็ก กินไฟน้อย ทนแรงกระแทกกว่า และราคา/GB อยู่ระหว่างดิสก์กับ DRAM ในบริบทของเอกสาร ภาพการ์ดหน่วยความจำและอุปกรณ์แฟลชแสดงการใช้งานจริง ไม่ใช่วงจรแคช SRAM.

NOR flash (แฟลชจัดเซลล์ลักษณะ NOR) เหมาะกับ random access (เลือกตำแหน่งอ่านได้โดยตรง) จึงใช้เก็บคำสั่งใน embedded system (ระบบคอมพิวเตอร์ฝังในอุปกรณ์). NAND flash (แฟลชลักษณะ NAND) หนาแน่นกว่า ราคาต่อ GB ต่ำกว่า อ่าน/เขียนตามหน่วยหน้าและลบเป็นบล็อก ใช้ในสื่อเก็บข้อมูลและ USB keys. สไลด์เขียนกว้าง ๆ ว่า random read/write สำหรับ NOR และ block-at-a-time สำหรับ NAND; การเขียนแฟลชยังติดเงื่อนไขการลบและหน่วยโปรแกรม ไม่เหมือนเขียน DRAM ได้อิสระ.

เซลล์มีวงรอบเขียน/ลบจำกัด จึงต้องมี wear leveling (กระจายการสึกหรอ) ย้ายการใช้ไปบล็อกที่ถูกเขียนน้อยกว่า. ข้อความ “not suitable for direct RAM or disk replacement” ควรอ่านว่าไม่ควรแทนแบบไม่จัดการข้อจำกัด ไม่ใช่ข้อสรุปว่าใช้สร้างอุปกรณ์แทนดิสก์ไม่ได้. [อธิบายเสริม] เหมือนสมุดที่ลบได้จำกัดครั้ง จึงไม่เขียนซ้ำอยู่หน้าเดียวตลอด.

3.6 · Disk storage and access (จานหมุนและเวลารอ)

ทำไมอ่านข้อมูลเพียง 512 ไบต์ยังต้องรอหลายมิลลิวินาที?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 17–20 เปิดดูต้นฉบับในเครื่อง ↗

Magnetic disk (ดิสก์แม่เหล็ก) เก็บข้อมูลคงอยู่บน platter (แผ่นจานหมุน). ภาพซ้อนแผ่นจานแสดง track (วงทางบันทึกบนผิว), sector (ช่วงย่อยของ track), cylinder (track รัศมีเดียวกันบนหลายผิว); หัวอ่านต้องเลื่อนไปวงที่ถูกต้องแล้วรอ sector หมุนมาถึง. แต่ละ sector มี sector ID (หมายเลขระบุ), data (ข้อมูล 512 ไบต์ในตัวอย่าง; สไลด์ระบุ 4096 ว่า proposed), ECC หรือ error correcting code (รหัสแก้ข้อมูลผิด), synchronization fields (ส่วนช่วยจับจังหวะ) และช่องว่าง.

เวลาเข้าถึงรวม queuing delay (รอคิวคำขออื่น), seek time (เลื่อนหัว), rotational latency (รอการหมุน), transfer time (ส่งข้อมูล) และ controller overhead (เวลาของตัวควบคุม). ตัวอย่างดิสก์ว่างจึงไม่บวกเวลาคิว: 15000 rpm = 250 รอบ/วินาที หนึ่งรอบ 4 ms เฉลี่ยรอครึ่งรอบ 2 ms; seek 4 ms; ส่ง 512 ไบต์ที่ 100 MB/s ใช้ 0.00512 ms; ควบคุม 0.2 ms รวม 6.20512≈6.2 ms. ถ้า seek จริง 1 ms รวม 3.20512≈3.2 ms.

ค่า average seek ที่ผู้ผลิตอ้างเฉลี่ยการเลื่อนหลายระยะ ขณะที่ locality และ OS disk scheduling (จัดลำดับคำขอดิสก์) อาจทำให้ระยะจริงสั้นลง. Smart controller (ตัวควบคุมจัดการภายใน) แสดง logical sector (หมายเลขที่ host ใช้) แล้วจัดตำแหน่งจริงเองผ่านอินเทอร์เฟซ SCSI/ATA/SATA. Cache และ prefetch (อ่านเตรียมล่วงหน้า) ในไดรฟ์อาจเลี่ยงการเลื่อนหัวและรอหมุนซ้ำได้.

ภาพก่อนและหลังอ้าง Xₙ แสดงแคชมีข้อมูลที่เคยอ้าง X₁…Xₙ₋₁ เมื่อขอ Xₙ ถ้าไม่อยู่ต้องนำเข้ามา อาจทำให้ข้อมูลเดิมถูกแทน. รายการออกแบบเริ่มจาก cache address (ใช้ที่อยู่ logical/virtual หรือ physical), cache size (ความจุข้อมูล), mapping function (กติกาวางข้อมูล: direct, associative, set associative), replacement algorithm (เลือกสิ่งที่เอาออก), write policy (นโยบายเขียน), line size (ขนาดบล็อก), number of caches (จำนวนระดับและแยกคำสั่ง/ข้อมูลหรือรวม).

LRU หรือ least recently used (เอาตัวที่ไม่ได้ใช้นานที่สุดออก), FIFO หรือ first in first out (เอาตัวที่เข้าก่อนออก), LFU หรือ least frequently used (เอาตัวที่ใช้น้อยครั้งออก), random (สุ่ม) เป็นทางเลือกในภาพ ไม่ใช่ว่าแคชทุกแบบเลือกได้ทุกนโยบาย. Unified cache (แคชรวม) เก็บคำสั่งและข้อมูลด้วยกัน; split cache (แคชแยก) มี I-cache สำหรับคำสั่งและ D-cache สำหรับข้อมูล ช่วยรองรับการขอทั้งสองพร้อมกัน.

3.8 · Direct mapping, tag, valid (วางตายตัวและตรวจว่าใช่)

ถ้าหลายที่อยู่ใช้ช่องแคชเดียวกัน จะแยกข้อมูลของใครได้อย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 23–24 เปิดดูต้นฉบับในเครื่อง ↗

Direct-mapped cache (แคชที่แต่ละบล็อกมีช่องเดียวให้ลง) ใช้ index = block address mod จำนวนบล็อกในแคช. เมื่อจำนวนช่องเป็นกำลังสอง ใช้บิตต่ำของ block address เป็น index (เลขเลือกช่อง). ภาพมีแคช 8 ช่อง 000–111; ลูกศรจากหลายบล็อกหน่วยความจำมารวมที่ช่องเดียว เช่นบล็อกลงท้าย 001 ลงช่อง001 ทั้งหมด จึงอาจแย่งที่กัน.

Tag (ป้ายระบุส่วนที่อยู่ที่เหลือ) เก็บบิตสูงเพื่อบอกว่าช่องนั้นเป็นสำเนาบล็อกใด. Valid bit (บิตว่ารายการใช้ได้) เริ่ม 0 ทุกช่อง แล้วเป็น1เมื่อมีบล็อกถูกต้อง. Hit ต้องทั้ง valid=1 และ tagตรง; การมีข้อมูลบิตอะไรก็ได้อยู่ในช่องไม่พอ. [อธิบายเสริม] Index เหมือนเลขช่องจอด ส่วน tag เหมือนทะเบียนรถ จอดช่องถูกแต่ทะเบียนไม่ตรงก็ไม่ใช่รถที่หา.

3.10 · Address subdivision (แยกบิตที่อยู่)

บิตไหนเลือกไบต์ บิตไหนเลือกช่อง และบิตไหนยืนยันบล็อก?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 31–32 เปิดดูต้นฉบับในเครื่อง ↗

Byte offset (เลขเลือกไบต์ภายในเวิร์ด/บล็อก) ไม่ใช่ index. ภาพหน้า31ใช้ที่อยู่64บิต ช่องละ32บิต=4ไบต์ และ1024ช่อง: offset2บิตเพราะ4=2²; index10บิตเพราะ1024=2¹⁰; tag64−10−2=52บิต. Indexเลือกแถวตารางพร้อม valid/tag/data; tagเข้า comparator (วงจรเปรียบเทียบ) แล้ว AND กับvalidเพื่อสร้างhit; data32บิตส่งกลับ. ลูกศรจึงแยกงาน “เลือกแถว” ออกจาก “ตรวจว่าใช่”.

ตัวอย่างหน้า32ใช้ที่อยู่32บิต,64บล็อก,16ไบต์/บล็อก: offset4บิต, index6บิต, tag22บิต. ที่อยู่ไบต์1200ให้ block address=⌊1200/16⌋=75, index75mod64=11, offset1200mod16=0, tag⌊75/64⌋=1. คำว่า block number ในสูตรสไลด์หมายถึงช่องแคช ไม่ใช่หมายเลขบล็อกหน่วยความจำ75; เขียนชื่อแยกกันจะไม่สับสน.

3.11 · Block size and misses (ขนาดบล็อกกับการหยุดรอ)

ขยายบล็อกให้ใหญ่ที่สุดแล้วจะเร็วที่สุดเสมอหรือไม่?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 33–34 เปิดดูต้นฉบับในเครื่อง ↗

บล็อกใหญ่ช่วย spatial locality เพราะคำขอข้างเคียงถูกนำมาพร้อมกัน แต่เมื่อความจุแคชคงที่ จำนวนบล็อกลดลง เกิดการแข่งขันและ pollution (ข้อมูลที่ไม่ใช้กินพื้นที่แคช) มากขึ้น อีกทั้ง miss penalty สูงขึ้นเพราะส่งมากขึ้น. Early restart (เริ่ม CPU ต่อทันทีที่ได้เวิร์ดที่ขอ) และ critical-word-first (ส่งเวิร์ดที่ต้องใช้ก่อน) ลดเวลาที่ CPU ต้องรอได้ แม้บล็อกยังส่งไม่ครบ.

บน hit CPUทำต่อปกติ; บนmiss แคชพื้นฐานสั่ง stall pipeline (หยุดขั้นทำคำสั่งชั่วคราว), ดึงบล็อกจากระดับถัดไป ถ้าเป็น instruction miss (พลาดการอ่านคำสั่ง) ให้เริ่ม fetchใหม่ ถ้าเป็น data miss (พลาดข้อมูล) ให้ทำการอ่าน/เขียนข้อมูลนั้นให้เสร็จ. [อธิบายเสริม] Pipeline คือการแบ่งคำสั่งเป็นขั้นและซ้อนหลายคำสั่ง; เมื่อข้อมูลจำเป็นยังไม่มาขั้นที่ต้องใช้ย่อมทำต่อไม่ได้.

3.12 · Write policies (เขียนแล้วสำเนาตรงกันอย่างไร)

เมื่อแก้ข้อมูลในแคช ต้องแก้หน่วยความจำหลักเมื่อใด?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 35–37 เปิดดูต้นฉบับในเครื่อง ↗

Write-through (เขียนผ่าน) บน write hit อัปเดตทั้งแคชและระดับล่าง จึงไม่ปล่อยหน่วยความจำหลักเก่ากว่า แต่ CPUอาจรอนาน. ตัวอย่าง base CPI (รอบต่อคำสั่งเมื่อไม่มีเวลารอเพิ่ม)=1, store10%, เขียนmemory100รอบ: effective CPI=1+0.1×100=11. Write buffer (คิวพักการเขียน) รับข้อมูลแทนการรอทุกครั้ง; CPUทำต่อได้จนคิวเต็มจึงต้องstall.

Write-back (เขียนกลับภายหลัง) บนhitแก้เฉพาะแคช แล้วตั้ง dirty bit (บิตว่าแก้แล้วแต่ยังไม่เขียนคืน). เมื่อแทนบล็อกdirtyจึงเขียนคืนmemory; clean block (บล็อกไม่สกปรก) ทิ้งได้เลย. ใช้write bufferรับบล็อกเก่าเพื่อเปิดทางอ่านบล็อกใหม่ก่อนได้. [อธิบายเสริม] เหมือนจดแก้ในฉบับทำงานแล้วค่อยส่งคืนฉบับเก็บ แต่ต้องติดเครื่องหมายว่าฉบับไหนถูกแก้.

Write allocation (การนำบล็อกเข้ามาเมื่อเขียนพลาด) เป็นคนละคำถามกับเวลาเขียนคืน: write-allocateอ่านบล็อกเข้าก่อนแล้วเขียน, no-write-allocate หรือ write-around (เขียนข้ามแคช) เขียนระดับล่างโดยไม่ดึงเข้ามา. Write-throughเลือกได้ทั้งสอง เช่นการเขียนเริ่มต้นทั้งบล็อกอาจไม่คุ้มที่จะอ่านข้อมูลเก่ามาก่อน; write-backมักใช้write-allocateเพื่อใช้ประโยชน์การเขียนซ้ำ.

3.13 · Intrinsity FastMATH (แคชตัวอย่างจริง)

จะแยกคำสั่งกับข้อมูลเพื่อให้เข้าถึงทุก cycle ได้อย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 38–39 เปิดดูต้นฉบับในเครื่อง ↗

ตัวอย่าง embedded MIPS processor (ตัวประมวลผลMIPSสำหรับระบบฝังตัว) มีpipeline12ขั้น และเข้าถึงคำสั่งกับข้อมูลทุกcycle จึงแยก I-cache/D-cache อย่างละ16KB=256บล็อก×16เวิร์ด×4ไบต์. D-cacheเลือกwrite-throughหรือwrite-backได้. SPEC2000 (ชุดงานวัดประสิทธิภาพที่ใช้ในสไลด์) มีmiss rate I=0.4%, D=11.4%, weighted average=3.2%; ค่าเฉลี่ยนี้ถ่วงด้วยจำนวนการเข้าถึง จึงไม่ใช่(0.4+11.4)/2.

ภาพที่อยู่32บิตแยกtag18,index8, block offset4 และbyte offset2. Indexเลือกหนึ่งใน256แถว; แถวนั้นมีvalid,tagและข้อมูล512บิต=16×32. Comparatorตรวจtagและvalidเพื่อhit; muxใช้block offsetเลือกเวิร์ด32บิตจาก16เวิร์ด ขณะbyte offsetเลือกไบต์ภายในเวิร์ด. เส้นจากtagไม่ได้เลือกเวิร์ด และoffsetไม่ได้พิสูจน์ว่าบล็อกถูกต้อง.

3.14 · Main memory support (ราคาของการเติมแคช)

เหตุใด DRAM กว้างหนึ่งเวิร์ดจึงเติมบล็อกช้ากว่าแบบกว้างหรือหลาย bank?

Main memoryใช้DRAMต่อบัสที่มีความกว้างคงที่และมีclock ซึ่งมักช้ากว่าCPU clock. ตัวอย่างบล็อก4เวิร์ดและmemoryกว้าง1เวิร์ด ใช้1bus cycleส่งaddress, แต่ละเวิร์ดรอDRAM15cycleและส่ง1cycle รวม1+4×15+4×1=65bus cycles. ได้16ไบต์/65≈0.246≈0.25ไบต์/รอบ เทียบกับ17รอบของmemoryกว้าง4เวิร์ดและ20รอบของ4-bankหน้า14. ต้องไม่เอาbus cyclesไปบวกCPU cyclesโดยยังไม่แปลงหน่วยนาฬิกา.

3.15 · CPI and AMAT (วัดผลของแคช)

miss rate ต่ำเพียงอย่างเดียวพอจะบอกว่าเครื่องเร็วหรือไม่?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 41–44 เปิดดูต้นฉบับในเครื่อง ↗

CPU time (เวลาที่CPUใช้ทำโปรแกรม) มีprogram execution cycles (รอบทำคำสั่ง รวมcache hit timeอยู่แล้ว) และmemory stall cycles (รอบรอหน่วยความจำ). ภายใต้สมมติฐานไม่ซ่อนเวลารอ: stall cycles = memory accesses/program × miss rate × miss penalty = instructions/program × misses/instruction × miss penalty. ต้องใช้miss rateให้ตรงฐานนับ เช่นD-cache rateนับต่อdata access ไม่ใช่ต่อinstruction.

ตัวอย่างI miss2%,D miss4%,penalty100cycles,base CPI2,load/store36%: I stalls/instruction=0.02×100=2; D stalls/instruction=0.36×0.04×100=1.44; actual CPI=2+2+1.44=5.44; CPUที่cacheอุดมคติเร็วกว่า5.44/2=2.72เท่าเมื่อclockและจำนวนคำสั่งเท่ากัน.

Average memory access time หรือ AMAT (เวลาเข้าถึงหน่วยความจำเฉลี่ย) = hit time + miss rate×miss penalty โดยpenaltyเป็นเวลาที่เพิ่มจากhit. ตัวอย่างclock1ns,hit1cycle,miss20cycles,I miss5%: 1ns+0.05×20ns=2nsต่อการเข้าถึงคำสั่ง. สไลด์เรียก2cycles/instructionภายใต้กรณีคิดหนึ่งinstruction fetchต่อคำสั่ง ไม่ใช่CPIรวมทุกปัจจัยโดยอัตโนมัติ. ลดbaseCPIหรือเพิ่มclockแล้วmemoryอาจกินสัดส่วนเวลามากขึ้น เพราะmiss penaltyเป็นจำนวนCPUcyclesสูงขึ้น แม้เวลาหน่วยความจำจริงไม่เปลี่ยน.

จะลดการไล่ข้อมูลออกเพราะชนช่องเดิมได้อย่างไร?

3.18 · Multilevel caches (คำนวณแคชหลายระดับ)

Primary cache หรือL1 (แคชชั้นแรก) อยู่ใกล้CPU เน้นhit timeต่ำและมักเล็ก. L2 (แคชชั้นสอง) ใหญ่และช้ากว่าL1แต่เร็วกว่าmain memory จึงรับL1miss; บางระบบมีL3. L2เน้นลดmiss rateออกmemoryมากกว่าลดhit timeให้ต่ำสุด เพราะไม่ถูกใช้ทุกคำขอ. L1จึงมักมีบล็อกเล็กกว่าL2ด้วย.

ตัวอย่างbaseCPI1,clock4GHzจึงcycle time1/(4×10⁹)=0.25ns, primary misses/instruction2%,memory100ns: ไม่มีL2 penalty100/0.25=400cycles; CPI1+0.02×400=9. เพิ่มL2 hit5nsจึง20cycles และglobal miss rate (พลาดถึงmemoryต่อคำขอเริ่มต้น)0.5%: CPI=1+0.02×20+0.005×400=3.4; เร็วขึ้น9/3.4≈2.65เท่า สไลด์ปัดเป็น2.6.

ต้นฉบับหน้า55พิมพ์“Extra penalty=500cycles”ขัดกับข้อมูล100nsและสมการที่ใช้400 บทนี้ใช้400และเปิดเผยข้อผิดพลาดนี้. [อธิบายเสริม] Local L2 miss rate (พลาดต่อจำนวนครั้งที่เข้าL2) ในชุดนี้=0.005/0.02=0.25=25%; อย่าแทน0.5%เป็นlocal rateแล้วคูณ0.02ซ้ำ เพราะจะลดโทษmemoryผิดไปอีก40เท่า.

3.19 · CPU and software interaction (งานอื่นซ่อนเวลาพลาดได้)

พลาดแคชครั้งหนึ่งหมายถึงCPUหยุดทั้งหมดเสมอหรือไม่?

Out-of-order CPU (CPUที่เลือกทำคำสั่งพร้อมก่อน แม้ลำดับโค้ดอยู่ทีหลัง) อาจทำงานที่ไม่ขึ้นกับข้อมูลที่พลาดต่อได้. Pending store (คำสั่งเขียนที่ยังไม่เสร็จ) ค้างในload/store unit (หน่วยดูแลคำสั่งอ่านเขียน); dependent instructions (คำสั่งที่ต้องใช้ผลนั้น) รอในreservation stations (ช่องพักงานรอoperand); independent instructions (คำสั่งที่ไม่ต้องพึ่ง) เดินต่อ. ผลต่อเวลาจริงจึงขึ้นกับdata flow (ความสัมพันธ์การส่งค่าระหว่างคำสั่ง) ควรใช้system simulation (จำลองระบบ) แทนบวกทุกmissอย่างง่าย.

กราฟหน้า58เปรียบRadix Sort (เรียงตามหลักตัวเลข) กับQuicksort (เรียงด้วยการแบ่งช่วง) บนขนาด4ถึง4096K items. กราฟบนคือinstructions/item: Radixลดลงมากจนต่ำกว่าQuicksortเมื่อชุดใหญ่; กราฟกลางคือclock cycles/item: Radixยังใช้รอบมากกว่าและเพิ่มกลับเมื่อชุดใหญ่; กราฟล่างคือcache misses/item: Radixลดจนราว64Kแล้วเพิ่มสูงกว่าของQuicksortมาก ส่วนQuicksortค่อนข้างต่ำจนถึงชุดใหญ่. ภาพจึงเตือนว่าคำสั่งน้อยกว่าไม่ได้แปลว่าเร็วกว่า หากรูปแบบอ้างmemoryแย่ลง. Compiler optimization (การปรับโค้ดโดยตัวแปลภาษา) และalgorithm behavior (วิธีเข้าถึงข้อมูลของขั้นตอนวิธี) เปลี่ยนmissesได้.

3.20 · Cache blocking and DGEMM (ใช้ข้อมูลก้อนเดิมให้คุ้ม)

คูณเมทริกซ์แล้วนำข้อมูลเดิมออกก่อนใช้ซ้ำ จะแก้ลำดับงานอย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 59–62 เปิดดูต้นฉบับในเครื่อง ↗

DGEMM หรือ double-precision general matrix multiplication (คูณเมทริกซ์เลขจุดลอยความละเอียดสองเท่า) ในตัวอย่างคำนวณ C[i,j] += A[i,k]×B[k,j] สะสมทุกk. เมทริกซ์ (ตารางตัวเลขสองมิติ) ถูกเก็บเป็นอาร์เรย์หนึ่งมิติแบบcolumn-major (คอลัมน์ติดกัน): ตำแหน่งi+j×nหมายถึงแถวiคอลัมน์j. ลูปjด้านนอกกับkด้านในอ่านCหนึ่งค่าไว้ในตัวแปรcij แล้วสะสมA[i+k*n]×B[k+j*n]ก่อนเขียนCกลับ. Aเดินข้ามคอลัมน์ด้วยระยะn ส่วนBเดินติดกันตามk จึงมีlocalityต่างกัน.

ภาพหน้า60มีตารางC,A,Bขนาด6×6: ลูกศรnew accessesชี้ช่องที่กำลังเข้าถึง ส่วนolder accessesแสดงช่องที่เคยอ่าน; เพื่อคำนวณหนึ่งแถวของCต้องใช้แถวของAซ้ำและหลายคอลัมน์ของB ถ้าBใหญ่เกินแคช ข้อมูลที่ต้องใช้รอบใหม่อาจถูกไล่ออก. Cache blocking (แบ่งงานเป็นบล็อกย่อยให้ข้อมูลอยู่ใช้ซ้ำในแคช) เปลี่ยนขอบเขตงานให้คูณtile (ตารางย่อย) ก่อนข้ามไปส่วนไกล.

โค้ดหน้า61กำหนดBLOCKSIZE32; do_blockรับsi,sj,skเป็นตำแหน่งเริ่มบล็อก: i=si…si+31, j=sj…sj+31, อ่านcij=C[i+j*n], k=sk…sk+31สะสมA[i+k*n]×B[k+j*n], แล้วเขียนcijคืน. ฟังก์ชันdgemmวนsjแล้วsiแล้วskเพิ่มครั้งละ32 จนครอบทุกบล็อก; การวนskหลายรอบสะสมผลย่อยลงบล็อกCเดียวกัน. [อธิบายเสริม] โค้ดสาธิตสมมติnหาร32ลงตัว หากเขียนใช้ทั่วไปต้องจำกัดปลายลูปด้วยmin(n,start+32)เพื่อไม่อ่านเกินอาร์เรย์.

ภาพหน้า62แรเงาเฉพาะบล็อกย่อยที่ใช้ในC,A,B แทนแรเงาทั้งแถว/ตารางใหญ่. กราฟGFLOPS (พันล้านการคำนวณจุดลอยต่อวินาที) สำหรับ32×32,160×160,480×480,960×960: unoptimized=1.7,1.5,1.3,0.8; blocked=1.7,1.6,1.6,1.5. บล็อกช่วยชุดใหญ่ชัดเจนเพราะข้อมูลสามก้อนย่อยกลับมาใช้ซ้ำก่อนถูกแทน ไม่ได้ลดจำนวนผลคูณเชิงคณิตศาสตร์.

3.21 · Dependability (บริการที่ยังใช้ได้เมื่อมีส่วนผิด)

มีชิ้นส่วนผิดหนึ่งจุดจำเป็นต้องทำให้ทั้งระบบล่มหรือไม่?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 63–64 เปิดดูต้นฉบับในเครื่อง ↗

Fault (ความผิดของส่วนประกอบ) อาจนำไปสู่failure (บริการไม่เป็นไปตามข้อกำหนด) หรืออาจถูกทนทาน/แก้ไขจนผู้ใช้ไม่เห็นผล. ภาพสองสถานะมีService accomplishment (ส่งบริการตามที่กำหนด) กับService interruption (บริการขัดข้อง); ลูกศรFailureพาจากทำงานปกติไปขัดข้อง และRestoration (กู้บริการ) พากลับ. Dependability (ความเชื่อถือได้ของบริการ) จึงรวมทั้งลดโอกาสเสียและกู้กลับเร็ว.

MTTF หรือ mean time to failure (เวลาเฉลี่ยที่ทำงานก่อนเสีย) ใช้วัดreliability (ความสามารถทำงานโดยไม่เสีย); MTTR หรือ mean time to repair (เวลาเฉลี่ยซ่อม/กู้); MTBF หรือ mean time between failures (เวลาเฉลี่ยระหว่างการเสีย)=MTTF+MTTR. Availability (สัดส่วนเวลาที่บริการพร้อม)=MTTF/(MTTF+MTTR). เพิ่มMTTFด้วยfault avoidance (ป้องกันความผิด), fault tolerance (ยังให้บริการแม้มีส่วนผิด), fault forecasting (คาดการณ์ความเสี่ยง); ลดMTTRด้วยเครื่องมือวินิจฉัยและขั้นตอนซ่อมที่ดี. [อธิบายเสริม] ถ้าทำงาน990ชั่วโมงแล้วซ่อม10ชั่วโมง MTBF1000ชั่วโมงและavailability990/1000=99% ตัวอย่างเสริมนี้ไม่ใช่ค่าตัวอย่างในสไลด์.

3.23 · Virtual machines and VMM (จำลองทรัพยากรเป็นหลายเครื่อง)

จะให้หลายระบบปฏิบัติการใช้เครื่องเดียวโดยไม่รบกวนกันได้อย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 69–72 เปิดดูต้นฉบับในเครื่อง ↗

Virtual machine หรือVM (เครื่องเสมือน) ให้guest OS (ระบบปฏิบัติการผู้ใช้เครื่องจำลอง) เห็นทรัพยากรเสมือนบนhost (เครื่องจริงที่รองรับ). ช่วยisolation (แยกความผิด/การเข้าถึง), แชร์ทรัพยากรและลดปัญหาความปลอดภัย/ความเชื่อถือได้ แต่มีoverhead (งานเพิ่มที่เสียประสิทธิภาพ). ตัวอย่างตามสไลด์คือIBM VM/370ในทศวรรษ1970,VMWareและMicrosoft Virtual PC; เป็นตัวอย่างประวัติในเอกสาร.

Virtual machine monitor หรือVMM (ผู้ดูแลเครื่องเสมือน) จับคู่CPU,memory,I/Oเสมือนกับของจริง. โมเดลพื้นฐานในสไลด์ให้guest codeรันคำสั่งปกติบนเครื่องจริงในuser mode (โหมดสิทธิ์จำกัด); privileged instruction (คำสั่งสิทธิ์สูง) หรือการแตะทรัพยากรป้องกันทำให้trap (เปลี่ยนเข้าโค้ดผู้ดูแลเพื่อจัดการ). VMMดูแลอุปกรณ์จริงแล้วemulate (ทำพฤติกรรมเลียนแบบ) อุปกรณ์ทั่วไปให้guestซึ่งอาจเป็นOSคนละชนิดกับhost. [อธิบายเสริม] เปรียบVMMเหมือนผู้จัดสรรห้องทำงาน แต่ละguestเห็นอุปกรณ์ของตัวเองแม้ใช้ของจริงร่วมกัน.

Timer virtualization (จำลองตัวจับเวลา): เครื่องปกติเมื่อtimer interruptเกิด OSพักprocessปัจจุบัน จัดการเหตุแล้วเลือกprocessต่อไป; เมื่อมีVMM ผู้พักและเลือกVMคือVMM ส่วนguestที่ต้องการtimerจะได้รับvirtual timer interruptที่VMMจำลองให้ตามเหตุเวลาจริง. ต้องแยกphysical interruptที่VMMรับออกจากvirtual interruptที่guestเห็น.

ISA หรือinstruction set architecture (ข้อตกลงชุดคำสั่งที่ฮาร์ดแวร์รองรับ) ต้องมีuser/system modes (ระดับสิทธิ์ผู้ใช้/ระบบ), คำสั่งสิทธิ์สูงทำได้เฉพาะsystem mode และtrapเมื่อใช้จากuser mode. การแก้page tables (ตารางแปลหน้า), interrupt controls (ตัวควบคุมเหตุขัดจังหวะ), I/O registers (รีจิสเตอร์อุปกรณ์) ต้องผ่านสิทธิ์ที่เหมาะสมเพื่อให้VMMยึดการควบคุมได้. ข้อความ“guest user mode”เป็นโมเดลอธิบายพื้นฐานในสไลด์ ไม่ใช่คำรับรองโครงสร้างของทุกระบบvirtualization.

3.24 · Virtual memory and paging (พื้นที่ส่วนตัวที่แปลสู่ของจริง)

โปรแกรมหลายตัวจะใช้หน่วยความจำเดียวกันอย่างปลอดภัยและดูเหมือนมีพื้นที่ส่วนตัวได้อย่างไร?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 73–79 เปิดดูต้นฉบับในเครื่อง ↗

Virtual memory (หน่วยความจำเสมือน) ใช้main memoryเป็นcacheของsecondary storage (ที่เก็บข้อมูลรองเช่นดิสก์) โดยCPU hardwareและOSร่วมกันจัดการ. แต่ละโปรแกรมเห็นprivate virtual address space (พื้นที่ที่อยู่เสมือนส่วนตัว) เก็บcode/dataที่ใช้บ่อยในRAMและป้องกันโปรแกรมอื่น. Virtual address (ที่อยู่ที่โปรแกรมออก) ถูกแปลเป็นphysical address (ที่อยู่หน่วยความจำจริง). Page (หน้า) คือบล็อกขนาดคงที่ของระบบนี้; page fault (เหตุไม่มีหน้าอยู่ในRAMตามการเข้าถึง) ไม่ใช่แค่ข้อมูลไม่อยู่ในcacheCPU.

ภาพหน้า74มีเส้นจากvirtual pagesไปphysical pagesโดยไม่ต้องรักษาลำดับติดกัน บางเส้นลงdisk. อีกภาพแบ่งvirtual address48บิตเป็นvirtual page number36บิตกับpage offset12บิตสำหรับหน้า4KiB=2¹²ไบต์; physical address40บิตเป็นphysical page number28บิตกับoffset12บิตเดิม. Translation (การแปล) เปลี่ยนเฉพาะเลขหน้า ไม่เปลี่ยนตำแหน่งภายในหน้า. [อธิบายเสริม] เหมือนเปลี่ยนเลขตึกแต่เลขห้องในตึกเท่าเดิม.

Page table (ตารางหน้า) เป็นอาร์เรย์PTE หรือpage table entry (รายการข้อมูลของหน้าแต่ละหน้า) จัดตามvirtual page number. CPUมีpage-table registerชี้ฐานตารางในphysical memory. ถ้าpresent/valid=1 PTEให้physical page numberพร้อมreference bit (บอกเคยใช้) และdirty bit; ถ้าไม่มีหน้า อาจระบุตำแหน่งในswap space (พื้นที่ดิสก์พักหน้า). ภาพหน้า77: virtual page numberเลือกแถวของpage tableจากฐานregister, ตรวจvalid, นำphysical page numberต่อoffsetเป็นphysical address; valid0ไปเส้นpage fault. ภาพหน้า78วาดPTEที่valid1เชื่อมRAM และvalid0เชื่อมdisk เพื่อแสดงว่าที่อยู่เสมือนต่อเนื่องไม่ได้บังคับให้พื้นที่จริงติดกัน.

Page faultต้องอ่านdiskจึงใช้เวลาหลายล้านclock cycles ให้OSจัดการและพยายามลดfault rateด้วยfully associative placement (วางหน้าในframeจริงใดก็ได้) และนโยบายเปลี่ยนหน้าที่ฉลาด. LRUเหมาะต่อการลดfaultแต่ติดตามตรงทุกการใช้แพง จึงใช้reference/use bitในPTEตั้ง1เมื่อใช้ OSล้างเป็น0เป็นระยะ; ค่า0ช่วยหาหน้าไม่ใช้ช่วงล่าสุด. Diskเขียนทีละpageและช้ามาก จึงใช้write-back: dirty1เมื่อมีการเขียนและเขียนdiskตอนต้องแทนหน้า ไม่ใช้write-throughทุกคำสั่งเขียน.

3.25 · TLB and fault handlers (แปลที่อยู่ให้เร็ว)

ถ้าทุกการอ่านต้องอ่านตารางหน้าก่อน จะไม่ช้าสองต่อหรือ?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 80–84 เปิดดูต้นฉบับในเครื่อง ↗

Translation look-aside buffer หรือTLB (แคชของผลแปลที่อยู่) อยู่ในCPU เก็บPTEที่ใช้บ่อยเพื่อไม่ต้องอ่านpage tableในRAMทุกครั้ง. ตัวเลขทั่วไปตามเอกสารคือ16–512PTEs,hit0.5–1cycle,miss10–100cycles,miss rate0.01–1%. ภาพหน้า81มีvirtual page numberค้นTLBซึ่งมีvalid,dirty,reference,tagและphysical page address; TLBชี้ไปRAMโดยตรงเมื่อhit ส่วนpage tableเต็มยังมีเส้นไปทั้งRAMและdisk เป็นคนละข้อมูลกับdata cacheที่เก็บเนื้อหา.

TLB miss (ผลแปลไม่อยู่ในTLB) มีสองเหตุ: หน้าอยู่RAMแต่PTEยังไม่cacheไว้ หรือหน้าไม่อยู่RAMจริง. ถ้าหน้าอยู่ อ่านPTEจากmemoryเติมTLBแล้วretry (ลองคำสั่งใหม่) จะทำโดยhardwareหรือsoftwareก็ได้; page tableซับซ้อนทำให้hardwareซับซ้อนขึ้น. Software handler (ชุดคำสั่งรับเหตุ) รับexception (เหตุที่ต้องเปลี่ยนไปโค้ดพิเศษ) และคัดลอกPTEก่อนrestart. ต้องตรวจmissก่อนdestination register (รีจิสเตอร์รับผล) ถูกเขียนทับเพื่อให้ทำคำสั่งเดิมใหม่อย่างถูกต้อง.

Page fault handler (ชุดคำสั่งOSจัดการหน้าขาด) ทำตามลำดับ: ใช้faulting virtual addressหาตัวPTE; หาตำแหน่งหน้าบนdisk; เลือกvictim page; ถ้าdirtyเขียนคืนก่อน; อ่านหน้าที่ขอเข้าRAM; แก้page tableและข้อมูลแปลที่เกี่ยวข้อง; ทำprocessให้runnable (พร้อมรับCPU) แล้วrestartคำสั่งที่เกิดfault ไม่ข้ามคำสั่งนั้นไป. [อธิบายเสริม] ระหว่างรอdisk OSอาจให้processอื่นใช้CPUแทน การรอหน้านี้จึงเชื่อมกับการจัดตารางงานในบทOS.

3.26 · TLB/cache and protection (แปลก่อนค้นและตรวจสิทธิ์)

ทำไมสองชื่อที่อยู่ของข้อมูลเดียวกันทำให้แคชและสิทธิ์ยุ่งยาก?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 85–86 เปิดดูต้นฉบับในเครื่อง ↗

ภาพหน้า85ส่งvirtual page numberเข้าTLBพร้อมเก็บpage offsetไว้ เมื่อได้physical page numberจึงประกอบphysical address แล้วแบ่งเป็นphysical tag/cache index/block offset/byte offsetสำหรับแคช. Physical-tagged cache (แคชตรวจด้วยที่อยู่จริง) จึงต้องมีผลแปลก่อนตรวจtag. ทางเลือกvirtual-tagged cache (แคชตรวจด้วยที่อยู่เสมือน) มีปัญหาaliasing (หลายvirtual addressesอ้างphysical dataเดียวกัน) ทำให้มีสำเนาที่ชื่อไม่ตรงกัน ต้องมีกลไกดูแลเพิ่มเติม.

Memory protection (การป้องกันหน่วยความจำ) ไม่ได้ห้ามแชร์ทุกอย่าง: taskต่างกันอาจแชร์บางpagesได้ แต่ต้องกันerrant access (การเข้าถึงผิดพลาด/ไม่มีสิทธิ์). Hardwareให้supervisor/kernel mode (โหมดแกนระบบสิทธิ์สูง), privileged instructions และป้องกันpage tablesกับสถานะระบบจากuser code. System call (การเรียกบริการOS) เช่นecallในRISC-Vทำให้เกิดexceptionเข้าโค้ดOSที่ตรวจและทำงานให้โดยมีขอบเขตสิทธิ์. [อธิบายเสริม] การรู้physical addressไม่ได้แปลว่ามีสิทธิ์แก้ได้ และการแปลสำเร็จยังต้องผ่านข้อกำหนดการอ่าน/เขียน/รันของหน้า.

3.28 · Cache controller FSM (สถานะควบคุมแคช)

วงจรจะจำได้อย่างไรว่ากำลังรอเขียนบล็อกเก่าหรืออ่านบล็อกใหม่?

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 94–97 เปิดดูต้นฉบับในเครื่อง ↗

ตัวอย่างเป็นdirect-mapped,write-back,write-allocate,blocking cache (แคชให้CPUรอจนคำขอเสร็จ),ขนาด16KiB=1024blocks,block16bytes=4words,ที่อยู่32บิตและvalid/dirtyต่อblock. แบ่งoffset4,index10,tag18. ภาพinterface (สัญญาณเชื่อมต่อ) CPU↔cacheส่งaddress32/write data32/read data32 พร้อมRead/Write,Valid,Ready; cache↔memoryส่งaddress32แต่data128บิตหนึ่งบล็อก พร้อมValid/Readyเช่นกัน. Validหมายถึงมีrequestที่ใช้ได้ ส่วนReadyหมายถึงอีกฝั่งทำเสร็จ ไม่ใช่บิตvalidของentry.

Finite state machine หรือFSM (เครื่องสถานะจำนวนจำกัด) มีstate register (รีจิสเตอร์จำสถานะปัจจุบัน), combinational control logic (วงจรคำนวณสัญญาณจากอินพุต), transition (เปลี่ยนสถานะที่ขอบclock). Next state=fₙ(current state,current inputs); control outputs=fₒ(current state)ตามโมเดลอธิบายในสไลด์. ภาพแสดงstate registerวนกลับเข้าวงจรและnext-stateไหลกลับไปregister พร้อมinputsจากdatapath (ทางเดินข้อมูล) และoutputsกลับควบคุมdatapath.

3.29 · Cache coherence and consistency (สำเนาหลายแกนเห็นอะไร)

3.33 · Pitfalls (ข้อผิดพลาดในการคิดและออกแบบ)

Segment (ช่วงที่อยู่มีฐานและขอบเขต) เคยใช้ขยายaddress rangeเช่นIntel80286 แต่segmentอาจไม่ใหญ่พอและทำaddress arithmeticซับซ้อน. VMMบนISAที่ไม่ได้ออกแบบให้virtualizeมีปัญหาnon-privileged instructionเข้าถึงhardware resourceโดยไม่trap จึงควบคุมguestได้ไม่ครบ ต้องขยายISAหรือปรับguestOSให้ไม่ใช้คำสั่งปัญหา. [อธิบายเสริม] Virtual memoryจัดหน้าไม่ใช่ชื่ออื่นของVMทั้งเครื่อง และsegmentไม่ใช่pageขนาดคงที่โดยอัตโนมัติ.

[อธิบายเสริม] ประเด็นสำหรับตรวจความเข้าใจ ไม่ใช่การยืนยันข้อสอบจริง

Cache miss vs TLB miss vs page fault

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 34, 80, 82, 84 เปิดดูต้นฉบับในเครื่อง ↗

Cache missคือข้อมูลไม่อยู่cacheชั้นนั้น;TLB missคือผลแปลไม่อยู่TLB;page faultคือหน้าไม่presentในRAM. หน้าอาจอยู่RAMและเติมTLBได้โดยไม่แตะdisk ขณะที่data cacheอาจhitหรือmissแยกกัน จึงต้องถามว่า “ไม่พบอะไร ที่ชั้นใด”.

Write policy vs write allocation

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 35–37 เปิดดูต้นฉบับในเครื่อง ↗

Write-through/backตอบว่าเขียนระดับล่างเมื่อใดเมื่อแก้cache ส่วนallocate/no-allocateตอบว่าเขียนพลาดแล้วเอาบล็อกเข้ามาหรือไม่. Dirty bitจำเป็นกับwrite-back ไม่ใช่คำตอบว่าบล็อกvalidหรือไม่.

Virtual machine vs virtual memory

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 69–70, 73–74 เปิดดูต้นฉบับในเครื่อง ↗

Virtual machineจำลองทรัพยากรเป็นเครื่องให้guestOS;virtual memoryจำลองaddressspaceและแปลหน้าให้process. ระบบหนึ่งอาจมีทั้งสองร่วมกันได้ โดยVMMยังต้องควบคุมทรัพยากรจริง.

Coherence vs consistency

ต้นทาง: itds-211_comp_arch_Chapter04.pdf · หน้า PDF 99, 102 เปิดดูต้นฉบับในเครื่อง ↗

Coherenceรักษาประวัติของตำแหน่งเดียว เช่นX;consistencyกำหนดลำดับที่เห็นการเข้าถึงหลายตำแหน่งเช่นXแล้วY. การส่งค่าล่าสุดของXถูกต้องไม่ได้รับประกันว่าผู้ใช้Yเป็นสัญญาณจะเห็นXตามลำดับที่ตั้งใจเสมอโดยไม่ดูmemorymodel.

7 · ทบทวนก่อนสอบ

  • Localityทำให้คัดข้อมูลเพียงส่วนหนึ่งแล้วได้ประโยชน์สูง;ระดับเร็วต้องเล็กและอยู่ใกล้CPU
  • Directเลือกช่องเดียว;set-associativeเลือกsetแล้วค้นหลายways;fullyassociativeวางได้ทุกช่อง
  • Hitต้องvalidและtagตรง;offsetเลือกข้อมูลภายในบล็อก
  • เพิ่มขนาดcache,จำนวนwaysหรือblocksizeมีทั้งผลดีและต้นทุน ต้องคำนวณhit timeและpenaltyร่วม
  • Write-through/backกับwriteallocationเป็นคำถามคนละเรื่อง;write-backต้องรักษาdirty
  • AMATวัดต่อaccess ส่วนCPIวัดต่อinstruction และอัตราlocal/globalใช้ฐานนับต่างกัน
  • SECDEDเพิ่มoverall parityเพื่อแยกหนึ่งบิตแก้ได้กับสองบิตตรวจพบ

1. [อธิบายเสริม] เหตุใดcacheที่จุเท่ากันแต่associativityต่างกันให้ผลลำดับ0,8,0,6,8ต่างกัน?

Direct4ช่องให้0และ8ลงช่อง0จึงไล่กันออกทุกครั้ง มีmiss5. 2-wayมี2sets คำขอทั้งหมดเป็นเลขคู่ลงset0ซึ่งเก็บได้2ตัว;0ถูกใช้อีกครั้งจึงhit แต่ตอน6เข้าต้องเอา8ซึ่งเก่าสุดออก ทำให้8ท้ายmiss รวม4miss. Fullyassociative4ช่องเก็บ0,8,6ได้พร้อมกัน มีเพียง3compulsorymiss. ความต่างเกิดจากทางเลือกวาง ไม่ใช่ความจุรวม.

2. [อธิบายเสริม] อธิบายสูตรAMATและเหตุที่ใช้ตัดสินout-of-orderCPUตรงๆไม่ได้

AMAT=hit time+miss rate×misspenaltyคิดเวลาเฉลี่ยต่อการเข้าถึงภายใต้โมเดลที่กำหนด ไม่รู้ว่าคำขอนั้นอยู่ในเส้นทางงานวิกฤตหรือซ้อนกับงานอื่น. Out-of-orderทำindependent instructionsต่อได้และnon-blockingcacheรับhit/missอื่นระหว่างรอ จึงไม่ใช่ทุกmissเพิ่มCPUtimeเต็มpenalty. ต้องดูdataflowและจำลองระบบเพื่อประเมินเวลาทั้งโปรแกรม.

3. [อธิบายเสริม] ถ้าwrite-backcachemissและvictimdirty ตัวควบคุมเดินอย่างไร?

Idleรับvalidrequest→CompareTagพบmissและdirty→Write-Backส่งบล็อกเก่ารอmemoryReady→Allocateอ่านblockใหม่รอReady→CompareTagทำคำขอเดิมบนblockใหม่ ถ้าstoreให้ปรับdata/setdirtyแล้วmarkCacheReady→Idle. ห้ามทิ้งdirtyvictimก่อนเขียนคืน และห้ามตอบCPUทันทีที่เริ่มallocate.

4. [อธิบายเสริม] syndrome1010และoverall parityผิดหมายถึงอะไร และถ้าparityรวมไม่ผิดล่ะ?

ภายใต้evenparityและไม่เกินสองบิตผิด S=1010₂=10และP=1ชี้single-bit errorตำแหน่ง10ให้กลับบิต10. หากSไม่เป็นศูนย์แต่P=0เป็นdouble-bit errorตรวจได้แต่แก้ตำแหน่งไม่ได้ ห้ามกลับบิต10ตามsyndrome. เลข10เป็นคู่ไม่ได้แปลว่าต้องเป็นdoubleerror;ต้องใช้zero/nonzerosyndromeร่วมกับผลparityรวม.

5. [อธิบายเสริม] ทำไมTLBmissไม่จำเป็นต้องอ่านdisk?
