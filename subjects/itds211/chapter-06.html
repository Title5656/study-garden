3.1 · I/O Systems (ตำแหน่งของบท)

เหตุใดCPUกับmemoryเพียงสองส่วนยังไม่พอให้เครื่องใช้งานได้?

ปกกำหนดบทV:I/O Systems และCourse Outlineวางหลังmemory hierarchy/cache และก่อนstorage systems. บทนี้ศึกษาทางเชื่อมระหว่างเครื่องกับภายนอก ว่าใครออกคำสั่ง ใครย้ายข้อมูล ใครรอ และใครตรวจพบความผิด ไม่ได้จำกัดเฉพาะคีย์บอร์ดหรือจอภาพ.

3.2 · I/O module and device (ตัวกลางกับอุปกรณ์)

ทำไมไม่ต่ออุปกรณ์ทุกชนิดเข้าวงจรCPUโดยตรง?

I/O module (โมดูลรับส่งข้อมูล) เชื่อมsystem bus (บัสระบบ) กับperipheral/external device (อุปกรณ์ภายนอก). ภาพgeneric modelมีaddress lines (เส้นระบุเป้าหมาย), data lines (เส้นข้อมูล) และcontrol lines (เส้นคำสั่ง/จังหวะ) เข้าโมดูล แล้วหลายlinksออกสู่อุปกรณ์. อุปกรณ์มีความเร็ว รูปข้อมูลและวิธีควบคุมต่างจากCPUจึงต้องมีตัวกลาง. External devicesแบ่งhuman readable (สื่อสารกับคน),machine readable (สื่อสารกับอุปกรณ์/เครื่องจักร),communication (สื่อสารระยะไกลกับterminalหรือคอมพิวเตอร์อื่น). [อธิบายเสริม] คีย์บอร์ด/จอเป็นตัวอย่างกลุ่มคน เซนเซอร์กลุ่มเครื่องจักร และการ์ดเครือข่ายกลุ่มสื่อสาร.

ภาพexternal deviceหน้า5แยกcontrol logic (วงจรควบคุม) รับcontrolจากโมดูล ส่งstatus (สถานะ) กลับ และสั่งbuffer (ที่พักข้อมูล). Transducer (ตัวแปลงสัญญาณ) แปลงข้อมูลเฉพาะอุปกรณ์/สภาพแวดล้อมเป็นบิตหรือกลับกัน;data bitsวิ่งสองทิศผ่านbufferกับโมดูล. จึงมีทั้งเส้นควบคุม เส้นสถานะ และเส้นเนื้อข้อมูล ไม่ใช่ทุกลูกศรส่งข้อมูลผู้ใช้.

หน้าที่โมดูลสิ่งที่ทำ
Control and timingประสานลำดับและจังหวะรับส่งระหว่างภายในกับภายนอก
Processor communicationถอดคำสั่ง รับ/ส่งdata รายงานstatus และรู้ว่าaddressใดเรียกตน
Device communicationส่งcommand/dataและรับstatusจากอุปกรณ์
Data bufferingพักข้อมูลเพื่อปรับความเร็วอุปกรณ์กับmemory
Error detectionตรวจและรายงานข้อผิดพลาดการรับส่ง

ภาพหน้า7แสดงฝั่งsystem busต่อdata registers (รีจิสเตอร์พักเนื้อข้อมูล) และstatus/control registers (รีจิสเตอร์อ่านสถานะ/ตั้งคำสั่ง) ส่วนaddress/controlเข้าI/O logic (วงจรตัดสินและประสานงาน). I/O logicเชื่อมexternal device interface logicหลายชุด แต่ละชุดมีdataสองทิศ,statusจากdevice,controlไปdevice. [อธิบายเสริม] เหมือนจุดรับส่งสินค้าที่มีช่องวางของ ใบสถานะ และผู้จัดคิว ไม่จำเป็นต้องทำอัตราส่งของทั้งสองฝั่งให้เท่ากันทุกขณะ.

3.3 · Three I/O techniques (ใครรอ ใครย้าย)

เมื่ออุปกรณ์ช้ากว่าCPUจะเสียเวลารอและย้ายข้อมูลมากเพียงใด?

Programmed I/O (CPUควบคุมด้วยโปรแกรมและตรวจสถานะเอง) แลกข้อมูลผ่านCPUกับโมดูล;CPUออกคำสั่งแล้ววนรอ. Interrupt-driven I/O (รับส่งโดยให้อุปกรณ์แจ้งเหตุเมื่อพร้อม) ให้CPUทำคำสั่งอื่นระหว่างรอ แต่อ่าน/เขียนข้อมูลผ่านCPUอยู่. DMAหรือdirect memory access (ย้ายข้อมูลตรงระหว่างโมดูลกับmain memory) ให้หน่วยควบคุมย้ายบล็อกโดยไม่ให้CPUย้ายทุกword;CPUยังตั้งงานและรับผลได้ ไม่ได้หายจากระบบ.

เส้นทางข้อมูลในตารางหน้า9ไม่มีinterruptใช้interrupt
I/O↔memoryผ่านprocessorProgrammed I/OInterrupt-driven I/O
I/O↔memoryโดยตรงไม่ระบุในตารางDMA (ใช้แจ้งcompletion)

I/O command (คำสั่งที่ส่งให้โมดูล) มี4ชนิด: Control (สั่งเปิด/ตั้งงานอุปกรณ์), Test (ตรวจสถานะ), Read (ให้อุปกรณ์ส่งข้อมูลเข้าบัฟเฟอร์โมดูล), Write (เอาข้อมูลจากdata busไปส่งอุปกรณ์). อ่าน/เขียนในที่นี้ต้องระบุผู้มอง ไม่สับสนกับชื่อread/writeของDMAที่อ้างฝั่งmemoryในชิปบางชนิด.

ผังหน้า11ฝั่งprogrammed: issue read→read status→check;not readyวนกลับ, errorไปจัดการผิด,readyจึงread word I/O→CPUแล้วwrite word CPU→memory;ถ้ายังไม่ครบblockย้อนเริ่ม. ฝั่งinterrupt: issue readแล้วdo something else;เมื่อinterruptค่อยอ่าน/checkstatusและย้ายwordผ่านCPU→memoryเหมือนเดิม จากนั้นทำซ้ำจนครบ. ฝั่งDMA: issue read-block CPU→DMAแล้วทำงานอื่น;DMAย้ายblock;เมื่อinterrupt CPUอ่านDMAstatusแล้วไปnext instruction. เส้นประในภาพสื่อการทำงานอื่น/เหตุแจ้ง ไม่ใช่dataทุกword.

3.4 · Memory-mapped and isolated I/O (เรียกอุปกรณ์ด้วยที่อยู่)

คำสั่งloadจะรู้ได้อย่างไรว่าที่อยู่นั้นเป็นRAMหรือรีจิสเตอร์อุปกรณ์?

I/O instruction (คำสั่งCPUที่ใช้เริ่ม/ทำI/O) ต่างจากI/O command (สัญญาณงานที่โมดูลได้รับ) แต่สัมพันธ์กัน. แต่ละอุปกรณ์มีidentifier/address (รหัสหรือที่อยู่เฉพาะ) โมดูลถอดaddress linesเพื่อตรวจว่าคำขอส่งถึงตนหรือไม่. Memory-mapped I/OหรือMMIO (วางรีจิสเตอร์อุปกรณ์ในพื้นที่ที่อยู่ร่วมกับmemory) ใช้คำสั่งอ่านเขียนmemoryและเส้นread/writeร่วม;มีชุดคำสั่งจัดการmemoryให้ใช้มาก. Isolated/port-mapped I/O (แยกพื้นที่ที่อยู่อุปกรณ์) มีmemory/I/O selectและคำสั่งI/Oเฉพาะ จึงใช้ชุดคำสั่งจำกัดกว่า. พื้นที่ร่วมไม่ได้แปลว่าข้อมูลอุปกรณ์อยู่ในRAMธรรมดา.

ภาพMMIOมีkeyboard data registerที่516ขนาด8บิต;status/control registerที่517ขนาด8บิต โดยbit7=1ready/0busy และbit0เขียน1เพื่อstart read. ACหรือaccumulator (รีจิสเตอร์รับค่าสะสมในตัวอย่าง) ใช้รับส่งข้อมูล. คำสั่งจริงในภาพเป็นภาษาเครื่องสมมติเพื่อแสดงกลไก ไม่ใช่assemblyRISC-V.

3.5 · Interrupt-driven I/O (แจ้งพร้อมแล้วกลับมางานเดิม)

CPUจะพักงานชั่วครู่แล้วกลับมาโดยค่าตัวแปรไม่เสียได้อย่างไร?

Programmed I/Oเสียเวลารอreadyนาน;interrupt-drivenให้ออกcommandแล้วทำuseful workจนโมดูลพร้อมแลกข้อมูลและขอบริการ. ISRหรือinterrupt service routine (ชุดคำสั่งรับเหตุขัดจังหวะ) ทำdata transferเสร็จแล้วคืนงานเดิม. [อธิบายเสริม] เหมือนฝากให้แจ้งเมื่อของมาถึง แต่เมื่อแจ้งแล้วผู้ทำงานยังต้องย้ายของเอง ต่างจากDMAที่มีผู้ช่วยย้าย.

ผังหน้า16แยกhardwareและsoftware: controllerออกinterrupt→CPUทำคำสั่งปัจจุบันให้เสร็จ→acknowledge (ตอบรับเหตุ)→push PC/PSWลงcontrol stack→โหลดPCใหม่เข้าISR;softwaresaveสถานะที่เหลือ→process interrupt→restoreสถานะ→คืนPSW/PCเก่า. PCหรือprogram counter (เลขตำแหน่งคำสั่งถัดไป),PSWหรือprogram status word (บิตสถานะ/การควบคุม),stack (ที่เก็บแบบใส่ท้ายเอาออกก่อน) ต้องถูกเก็บก่อนISRทับค่าเดิม. แบ่งว่าอะไรทำโดยhardware/softwareตามโมเดลภาพนี้ ไม่ใช่ทุกISAทำเหมือนกัน.

ภาพหน้า17สมมติเกิดเหตุหลังคำสั่งที่N จึงPCเดิมเป็นN+1;ISRเริ่มYและมีreturnที่Y+L. ก่อนเข้ารับเหตุstack pointer (รีจิสเตอร์ชี้ยอดstack)=T;การsaveMหน่วยทำให้ชี้T−Mและเก็บN+1กับgeneral registers (รีจิสเตอร์ทั่วไป). PCเปลี่ยนไปY. ตอนถึงY+Lให้ดึงค่าที่saveไว้คืน PCกลับN+1และSPกลับT. ตัวเลขN,Y,Tเป็นตำแหน่ง ไม่ใช่ข้อมูลไหลเป็นผลคำนวณ;ลูกศรในภาพซ้ายคือการบันทึก/เปลี่ยนค่า ส่วนขวาคือการคืนค่า.

เมื่อมีหลายโมดูล ต้องตอบว่าใครขอinterruptและหากมาพร้อมกันใครมาก่อน. วิธีdevice identification (ระบุผู้ขอ)มี4แบบ:

3.6 · 82C59A interrupt controller (รวมและจัดเหตุ)

จะรับคำขอหลายสิบอุปกรณ์โดยCPUไม่ต้องมีหลายสิบขาได้อย่างไร?

ภาพใช้82C59Aเป็นinterrupt controller (วงจรรวมคำขอและจัดบริการเหตุ) แบบmaster/slave (ตัวหลัก/ตัวย่อย). Slaveแต่ละตัวมีIR0…IR7รับได้8device requests แล้วส่งINTออกหนึ่งเส้นเข้าหนึ่งIRของmaster. MasterมีIR0…IR7และส่งINTเข้าINTRของ80386processor. ตัวอย่างslaveแรกdevice00…07,ถัดไป08…15,ตัวท้าย56…63:8slaves×8inputs=64อุปกรณ์ที่ถูกจัดกลุ่มโดยmasterเดียว.

ลูกศรจากdeviceไปslaveแล้วmasterแล้วCPUแสดงเส้นทางคำขอ ส่วนการรู้ว่าเป็นเหตุใดต้องทำกระบวนการacknowledge/vectorตามระบบ ไม่ใช่CPUอ่านเพียงสายINTRแล้วทราบdeviceทันที. [อธิบายเสริม] เปรียบหัวหน้ากลุ่ม8คนรายงานหัวหน้าหลักช่วยลดจำนวนสายที่ไปCPU แต่ต้องระบุสมาชิกกลุ่มขณะให้บริการ.

3.8 · Direct memory access (ขนบล็อกโดยไม่ผ่านรีจิสเตอร์CPU)

ถ้าอุปกรณ์ส่งข้อมูลจำนวนมาก แม้ไม่วนรอแล้วCPUยังเหนื่อยกับอะไร?

Programmedและinterrupt-driven I/Oยังถูกจำกัดด้วยความเร็วCPUในการตรวจ/บริการdevice และต้องรันหลายคำสั่งต่อการย้ายหนึ่งหน่วย. DMA (ย้ายตรงถึงmemory) ให้CPUเริ่มต้นด้วยทิศทาง อุปกรณ์ ที่อยู่memoryและจำนวนข้อมูล แล้วcontrollerย้ายเองจนจบ. ไม่ต้องให้CPUอ่านwordเข้าregisterแล้วstoreทุกword แต่ยังแย่งbus/memory bandwidthได้.

ภาพDMAหน้า25มีdata count (ตัวนับจำนวนที่เหลือ),data register (ที่พักข้อมูลตามโมเดลทั่วไป),address register (ที่อยู่memoryปัจจุบัน),control logic (ควบคุมลำดับ) ต่อdata/addresslines. Request to DMAเป็นคำขอ,acknowledge from DMAยืนยันรับงาน,interruptแจ้งCPU,read/writeสั่งทิศทาง. หลังย้ายแต่ละหน่วยมีการปรับaddressและcountตามงานที่ตั้งไว้. [อธิบายเสริม] เหมือนให้ผู้ช่วยรู้จุดเริ่มกับจำนวนกล่อง แล้วรายงานเมื่อขนเสร็จ แต่ยังต้องใช้ประตูขนส่งร่วมกัน.

ภาพbreakpointsหน้า26แยกinstruction cycle (รอบทำคำสั่งหนึ่งคำสั่ง) เป็นfetch instruction,decode,fetch operand,execute,store result,process interrupt. ลูกศรDMA breakpointsอยู่ก่อนfetch instruction,ก่อนfetch operandและก่อนstore result เพื่อยืมbusระหว่างช่วงที่เหมาะสม;interrupt breakpointอยู่หลังstore resultก่อนprocess interrupt เพราะโมเดลนี้รับเหตุเมื่อคำสั่งเสร็จ. จึงไม่ใช่DMAต้องหยุด/เปลี่ยนprogram counterเข้าISRทุกหน่วย;หยุดให้สิทธิ์busกับการสลับโค้ดเป็นคนละเหตุ.

3.9 · 8237 bus control and fly-by (ให้สิทธิ์บัสแล้วข้อมูลผ่านตรง)

DMAcontrollerจำเป็นต้องรับข้อมูลเข้าไปเก็บเองทุกไบต์หรือไม่?

ภาพ8237 DMA Usage of System Busเชื่อมCPU,8237,DMA disk controllerและmain memory. DREQหรือDMA request (อุปกรณ์ขอย้าย) จากdiskcontrollerถึง8237;HRQหรือHOLD request (DMAขอถือbus) จาก8237ถึงCPU;HLDAหรือHOLD acknowledge (CPUยอมให้ถือbus) กลับ8237;DACKหรือDMA acknowledge (ยืนยันสิทธิ์ให้device) จาก8237กลับdiskcontroller. สวิตช์ในภาพแสดงช่วงที่CPUปล่อยdata/address/controlbusให้DMAควบคุม ไม่ใช่เชื่อมผู้ขับbusสองตัวตีกันพร้อมกัน.

ControlbusมีIOR (อ่านจากI/O),IOW (เขียนI/O),MEMR (อ่านmemory),MEMW (เขียนmemory). ขารับเข้าmemoryจากdeviceใช้IORร่วมMEMW;ขาออกใช้MEMRร่วมIOW. Fly-by DMA (ย้ายข้อมูลบินผ่านระหว่างปลายทาง)หมายถึงข้อมูลI/O↔memoryไม่ผ่านและไม่พักใน8237 ตัวชิปสร้างaddress/controlเท่านั้น. ต้องแยกจากdata registerในโมเดลgenericหน้า25 ซึ่งไม่บังคับimplementationทุกแบบ.

8237มี4channels (ชุดสถานะงานDMAแยกกัน)หมายเลข0,1,2,3 ตั้งโปรแกรมอิสระแต่มีเพียงหนึ่งchannelactiveณขณะหนึ่งตามตัวอย่าง. ข้อความ“not between two memory locations”ในหน้า29หมายถึงทางfly-byโดยตรง;8237ยังทำmemory-to-memoryได้โดยผ่านtemporary register (รีจิสเตอร์พักชั่วคราว)ดังกล่องกลางของสไลด์ จึงไม่ขัดกับcommand registerที่เปิดmemory-to-memory. [อธิบายเสริม] อ่านข้อมูลต้นทางเข้าtemporaryแล้วเขียนปลายทางเป็นสองช่วง จึงต่างจากสั่งdeviceกับmemoryให้ส่งต่อกันในช่วงเดียว.

3.11 · DCA and Xeon architecture (คอขวดย้ายจากCPUสู่memory)

เมื่อการ์ดเครือข่ายเร็วขึ้นมาก ทำไมDMAแบบเดิมยังไม่พอ?

Direct cache accessหรือDCA (ทำให้ข้อมูลI/Oเข้าใกล้แคชโดยตรง/ล่วงหน้า)ตอบปัญหาDMAต้องวิ่งผ่านmain memoryหลายครั้งและCPUยังmisscacheเมื่อเริ่มอ่านpacket. สไลด์ยกเครือข่าย10/100Gbps EthernetและWi-Fi3.2/6.76Gbpsเป็นบริบทความต้องการขณะเขียนเอกสาร ไม่ใช่เพดานเทคโนโลยีปัจจุบัน. เพิ่มlink speedอย่างเดียวไม่เพิ่มDRAM bandwidthหรือทำให้dataอยู่cacheเอง.

ภาพXeonE5-2600/4600เป็นชิป8coresเลข0…7 แต่ละcoreมีL1ระบุ64KBและL2ระบุ256KB;ตรงกลางมีL3 slices (ส่วนย่อยแคชระดับสาม)8ก้อน×2.5MB=20MBรวมตามภาพ. วงแหวนลูกศรสองทิศเชื่อมcores/L3กับMemory Controller Hub (ตัวควบคุมmemory)ด้านล่างไปDDR3,PCIeด้านบนไปI/OและQPIหรือQuickPath Interconnect (ทางเชื่อมกับprocessor chipอื่น). เส้นประchip boundary (ขอบชิป)บอกส่วนที่อยู่บนชิปเดียวกัน. รูปทำให้เห็นว่าทางI/Oสามารถเข้าถึงโครงสร้างcacheร่วมใกล้coreแทนลงDRAMทุกครั้ง;ไม่ใช่L3อยู่ในNIC.

3.12 · Packet traffic (ตามแพ็กเก็ตเข้าและออก)

ก่อนข้อมูลเครือข่ายถึงโปรแกรม มีใครคัดลอกและอ่านheaderบ้าง?

Packet / protocol data unitหรือPDU (ก้อนข้อมูลตามกติกาสื่อสาร)มีheader (ข้อมูลกำกับ)และpayload (เนื้อหาที่บรรทุก). ตัวอย่างวางEthernet (กติกาลิงก์)ข้างนอกIPหรือInternet Protocol (กติกาส่งข้ามเครือข่าย) และTCPหรือTransmission Control Protocol (กติกาส่งข้อมูลระหว่างปลายทาง)ภายใน. Ethernet payloadมีIPheader,TCPheaderและapplicationdata;IPอยู่เหนือEthernetและTCPอยู่เหนือIP ไม่ใช่headerสามชื่อที่แทนกันได้.

NICหรือnetwork interface controller (ตัวควบคุม/การ์ดเครือข่าย)ประกอบEthernetpacketขาออก;ขาเข้าถอดส่วนEthernetแล้วส่งTCP/IPpacketให้host CPUตามโมเดลสไลด์. Application buffer (พื้นที่พักของแอป)กับsystem buffer (พื้นที่พักของระบบ)เป็นคนละช่วงmemory. ในDMAขาออก แอปวางข้อมูลในbufferของตน→coreคัดไปsystembufferและสร้างTCP/IPheadersในmemory→NICอ่านผ่านDMAส่งออก. ขาเข้ามีการย้ายsystem→applicationbufferเช่นกัน ทำให้memoryและcacheเข้ามาเกี่ยวทั้งสองทิศ.

3.13 · DCA prefetch and DDIO (ให้แคชเป็นปลายทางI/O)

จะลดทั้งการพลาดแคชและการวิ่งไปDRAMซ้ำๆได้อย่างไร?

กลยุทธ์DCAแรกในprototypeXeonช่วง2006–2010ใช้กับincoming traffic:ข้อมูลเข้าsystemmemoryก่อน จากนั้นDCA functionในmemorycontrollerส่งprefetch hint (คำแนะให้อ่านเตรียม)ให้coreดึงpacketจากsystembufferขึ้นcacheก่อนถูกขอจริง. จึงซ่อนเวลาบางส่วนแต่ยังไม่ตัดsystembufferออก. สไลด์ชี้ว่าcoreมักอ่านpacket/descriptorจากsystembufferเพียงครั้งเดียวเพื่อส่งpayloadไปapplicationbuffer จึงได้ประโยชน์มากกว่าถ้าข้ามการพักDRAMนั้นได้.

Cache injection (ใส่ข้อมูลI/Oเข้าcache) ในตัวอย่างIntelเรียกDDIOหรือData Direct I/O (รับส่งข้อมูลโดยใช้แคชเป็นทางหลัก). ภาพหน้า37มี4กรณี ต้องอ่านทั้งขาเข้าและขาออก: (a)normalDMAto memoryรับที่I/Ocontroller(1),เกี่ยวข้องกับการตรวจ/ทำให้cacheเก่าใช้ไม่ได้(2),เขียนmainmemory(3),แล้วcoreอ่านขึ้นcache(4); (b)DDIOto cacheรับที่controller(1),ย้ายเข้าlast-levelcacheหรือLLC(แคชชั้นสุดท้าย)(2),coreใช้จากcache(3). เส้นหนาสีเทาคือทางเชื่อมที่มีอยู่ ส่วนเส้นเขียวแสดงทางงานในกรณีนั้น ไม่ใช่ว่าDDRmemoryถูกถอดออกจากเครื่อง.

(c)normalDMAto I/O:coreเตรียมpacketโดยเข้าถึงข้อมูลจากmemory/cache(1);NICรับข้อมูลจากcacheเมื่อcoherenceตรวจพบข้อมูลล่าสุด(2) แต่โมเดลเก่ามีmemorytrafficเพิ่มเติมและทำให้ข้อมูลออกจากcache(3). (d)DDIOto I/O:coreใช้/สร้างpacketในcache(1);NICอ่านข้อมูลจากcacheส่งออก(2)โดยเก็บสำเนาไว้ใช้ซ้ำได้. รูปลูกศรต้องอ่านร่วมกับการควบคุมcoherence ไม่ใช่ตีความว่าCPUเป็นผู้คัดทุกbyteผ่านตัวเองแทนDMA.

[อธิบายเสริม] ตรวจความหมายของภาพกับ Intel DDIO Primer:แบบเดิมขาเข้าinvalidateแล้วอ่านจากmemory;DDIOใช้write-update/allocateในLLC ขาออกNICอ่านcacheได้โดยไม่บังคับevict. ถ้าข้อมูลไม่อยู่cacheก็ยังต้องไปmemory จึงเป็นการลดtrafficเมื่อใช้cacheได้ ไม่ใช่ข้อรับรองว่าไม่มีDRAM accessทุกกรณี. DMAกับDDIOจึงไม่ใช่วิธีแทนกันเด็ดขาด;DDIOเปลี่ยนทางที่ธุรกรรมDMAของอุปกรณ์พบข้อมูล.

3.14 · I/O evolution and channels (ยกงานให้หน่วยเฉพาะ)

ถ้ายังมีอุปกรณ์อีกมาก CPUจะสั่งทุกรายการย่อยเองตลอดไปหรือไม่?

พัฒนาการ6ขั้นในหน้า38:1CPUควบคุมperipheralตรง;2เพิ่มcontroller/moduleใช้programmedI/O;3เพิ่มinterruptให้CPUไม่ต้องวนรอ;4ให้moduleเข้าถึงmemoryโดยDMAโดยCPUเกี่ยวตอนเริ่ม/จบ;5moduleเป็นprocessorที่มีspecialized instruction set (ชุดคำสั่งเฉพาะI/O);6มีlocal memory (หน่วยความจำของตัวเอง)จนเป็นคอมพิวเตอร์ย่อยดูแลdevicesจำนวนมากและลดงานCPU. แต่ละขั้นเพิ่มความรับผิดชอบของโมดูล ไม่ใช่แค่อัตราส่งสายเร็วขึ้น.

I/O channel (หน่วยประมวลผลงานI/OแทนCPU)ในภาพหน้า39มีdata/addresschannelต่อmain memoryและcontrol pathต่อCPU แล้วเชื่อมI/Ocontrollersกับdevices. Selector channel (ช่องเลือกบริการ)วาดบัสร่วมต่อหลายcontroller;Multiplexor channel (ช่องสลับบริการหลายทาง)แตกหลายสาขาไปcontrollersพร้อมdevicesหลายตัว. [อธิบายเสริม] Selectorมักเลือกdeviceความเร็วสูงหนึ่งตัวใช้ทางช่วงย้ายblock ส่วนmultiplexorสลับช่วงข้อมูลจากหลายdeviceเพื่อใช้ทางร่วมคุ้มขึ้น จึงเหมาะกับหลายงานที่ไม่ต้องครองทางต่อเนื่อง. Controllerยังดูแลdeviceเฉพาะ ขณะที่channelจัดลำดับงานระดับสูงกว่า.

3.15 · Interface assignment (งานกลุ่มในต้นฉบับ)

จะเปรียบเทียบเทคโนโลยีเชื่อมต่อโดยไม่ดูความเร็วเพียงเลขเดียวได้อย่างไร?

สไลด์มอบหมายกลุ่มละ6–7คน จัด9กลุ่มจับฉลาก9เรื่อง ทำรายงานสรุปใส่ชื่อและรหัสสมาชิกครบ และนำเสนอ10–15นาทีในคาบสัปดาห์ถัดไปที่ระบุ8,10กันยายน2569. นี่คือข้อกำหนดในเอกสารต้นทาง ไม่ใช่การประกาศกำหนดส่งใหม่ของหน้าเรียน. ทั้ง9เทคโนโลยีมีบทอธิบายต่อไป รวมPCI/PCIeกับSATAที่แชร์หน้าเดียวกัน.

[อธิบายเสริม] ในรายงานให้ถามว่าเชื่อมอะไร ใช้busร่วม/point-to-point/เครือข่ายสวิตช์ ใครควบคุม อัตราเป็นsignalingหรือusable data และหมายถึงgenerationใด. ตัวเลขในสไลด์อิงรุ่นที่กล่าวถึงขณะเขียน โดยคำว่าcurrent/mostrecentไม่ได้ยืนยันรุ่นล่าสุดในวันนี้.

3.16 · 1. USB (บัสอนุกรมสำหรับอุปกรณ์รอบข้าง)

จะต่ออุปกรณ์หลายชนิดในระบบที่มีผู้ควบคุมเดียวได้อย่างไร?

Universal Serial BusหรือUSB (บัสอนุกรมสากล)ใช้กับperipheralsทั้งช้าและเร็ว มีroot host controller (ตัวควบคุมต้นทางที่host)จัดการอุปกรณ์เป็นhierarchical tree topology (โครงต้นไม้หลายชั้น). Serial (อนุกรม)คือส่งบิตตามกันบนลิงก์ ต่างจากparallel (ขนาน)ที่ส่งหลายบิตพร้อมกันหลายเส้น. USB3เพิ่มSuperSpeed busคู่กับUSB2busในระบบ ไม่ได้เปลี่ยนให้เป็นparallelbitbus.

[อธิบายเสริม] รุ่นUSBกับรูปหัวต่อเป็นข้อมูลคนละอย่าง;ชื่อเท่ากันในตารางหมายถึงโหมดความเร็วที่สไลด์จับคู่ ไม่ใช่รับรองความสามารถทุกสายและทุกพอร์ตที่หน้าตาเหมือนกัน.

3.17 · 2. FireWire / IEEE1394 (อนุกรมต่ออุปกรณ์แบบลูกโซ่)

จะต่ออุปกรณ์อัตราสูงโดยไม่ใช้channelใหญ่ราคาแพงแบบmainframeได้อย่างไร?

FireWire (ชื่อเทคโนโลยีบัสอนุกรมIEEE1394)พัฒนาเป็นทางเลือกSCSIบนPC,workstationและserverขนาดเล็ก เพื่อให้I/Oเร็วโดยไม่ใช้I/Ochannelsขนาดใหญ่แพงของmainframe/supercomputer. สไลด์ใส่บริบท1999–2000 ไม่ได้บอกว่าปีนี้เป็นเทคโนโลยีใหม่.

Daisy-chain configuration (ต่ออุปกรณ์เป็นสายต่อกัน)ในสไลด์รองรับถึง63devicesจากportเดียว และเชื่อม1022busesผ่านbridges (วงจรเชื่อมbus). Hot plugging (เสียบ/ถอดขณะเครื่องเปิด)กับautomatic configuration (ระบบกำหนดการเชื่อมต่อ/ที่อยู่เอง)ช่วยให้ไม่ต้องปิดหรือจัดระบบใหม่ด้วยมือทุกครั้ง และสไลด์ระบุไม่ต้องใช้terminationsแบบSCSIในบริบทเปรียบเทียบนี้. [อธิบายเสริม] Daisychainที่นี่เป็นรูปต่ออุปกรณ์ ไม่ใช่ชื่อเดียวกันแล้วต้องทำหน้าที่เหมือนสายinterruptacknowledgeหน้า19ทุกประการ.

3.18 · 3. SCSI (กติกาเชื่อมอุปกรณ์เก็บข้อมูล)

จะให้อุปกรณ์เก็บข้อมูลหลายตัวใช้ทางสื่อสารที่มีคำสั่งระดับสูงได้อย่างไร?

Small Computer System InterfaceหรือSCSI (อินเทอร์เฟซระบบคอมพิวเตอร์ขนาดเล็ก)ในหน้านี้กล่าวถึงparallel shared bus (บัสขนานร่วมกัน)ของรุ่นเก่า ใช้ต่อperipheralsและmass storage (หน่วยเก็บข้อมูลจำนวนมาก) ระบบองค์กร. เอกสารกล่าวว่าUSB/FireWireแทนบทบาทในระบบเล็กบางส่วน และรุ่นเร็วใช้ในenterprise;ควรอ่านตามบริบทประวัติของสไลด์ ไม่เหมารวมว่าSCSIทุกแบบต้องเป็นparallelbusทางกายภาพ.

ข้อความต้นฉบับระบุ16/32devicesตามรุ่น,16บิตรุ่นแรก/32บิตรุ่นหลัง,และความเร็ว5Mbpsถึง160Mbps. มีปัญหาทั้งการเหมารวมรุ่นและหน่วย: SCSIแบบnarrowมีbus8บิต ส่วนwideที่พบทั่วไป16บิต ดังนั้นไม่ควรจำว่าSCSIรุ่นแรก16บิตทั้งหมด;ตัวเลข32ต้องดูspecรุ่นเฉพาะ. อัตรา5และ160ในตัวอย่างSCSI-1/Ultra160ควรอ่านเป็นMB/s (เมกะไบต์ต่อวินาที) ไม่ใช่Mbps ต่างกัน8เท่า.

[อธิบายเสริม] ตรวจหน่วยกับ IBM Ultra160 (160MBps) และ Seagate SCSI revision levels ที่แยกnarrow8bit/wide16bit. การระบุอุปกรณ์บนsharedbusต้องมีรหัสแยกและกติกาว่าใครเริ่มส่งได้ ไม่ใช่ส่งทุกตัวพร้อมกันเพราะมีหลายสายข้อมูล.

3.19 · 4. Thunderbolt (รวมข้อมูลภาพและไฟเลี้ยง)

จะส่งหลายชนิดสัญญาณไปอุปกรณ์ภายนอกผ่านการเชื่อมต่อเดียวได้อย่างไร?

Thunderbolt (เทคโนโลยีเชื่อมต่อความเร็วสูงที่Intelพัฒนาร่วมกับApple)รวมdata,video,audio,power (ข้อมูล ภาพ เสียง และไฟเลี้ยง)สำหรับhard drives,RAID arrays (ชุดดิสก์ทำงานร่วมกัน),video-capture boxes (กล่องรับภาพ)และnetwork interfaces. ตัวเลขในหน้านี้คือthroughput10Gbpsต่อทิศทางและจ่ายไฟได้10Wตามรุ่นยุคต้นที่สไลด์อธิบาย. “most recent and fastest”เป็นถ้อยคำตามยุคนั้น ไม่ใช่อันดับปัจจุบัน.

[อธิบายเสริม] Per directionหมายถึงแต่ละทิศส่งได้ตามค่าระบุ ส่วนWหรือwattเป็นกำลังไฟ ไม่ใช่อัตราส่งdata. การรองรับภาพกับข้อมูลบนทางเดียวต้องมีการจัดทรัพยากรลิงก์ร่วม จึงควรแยกคำถามเรื่องbandwidthจากคำถามเรื่องไฟเลี้ยง.

3.20 · 5. InfiniBand (ผืนเครือข่ายสวิตช์สำหรับระบบใหญ่)

serverและstorageจำนวนมากจะเชื่อมกันโดยไม่แย่งบัสเส้นเดียวอย่างไร?

InfiniBand (สถาปัตยกรรมเชื่อมต่อข้อมูลความเร็วสูงสำหรับระบบสมรรถนะสูง)มุ่งhigh-end server market (ตลาดserverระดับสูง),รุ่นแรกออกต้น2001และสไลด์ยกIBM zEnterprise. กำหนดdata flowระหว่างprocessorsกับintelligent I/O devices (อุปกรณ์I/Oที่มีวงจรจัดการงานเอง). ใช้ในstorage area networkingหรือSAN (เครือข่ายเฉพาะเชื่อมหน่วยเก็บข้อมูล)และระบบเก็บข้อมูลใหญ่.

Central fabric (ผืนโครงข่ายกลาง)ประกอบswitchesกับlinksเชื่อมserver,remote storageและอุปกรณ์เครือข่าย;สไลด์ระบุswitch-based architectureขยายถึง64000nodes/devices. ไม่ใช่ลากบัสกายภาพเส้นเดียวผ่าน64000กล่อง. [อธิบายเสริม] เปรียบเป็นเครือข่ายทางแยกที่เลือกเส้นทางหลายทางได้ ต่างจากถนนร่วมเพียงเส้นเดียว แต่ผลเร็วจริงยังขึ้นกับรูปเครือข่ายและความหนาแน่นของงาน.

3.21 · 6. PCI / PCI Express (เชื่อมอุปกรณ์ขยายภายใน)

การ์ดขยายหลายชนิดและหลายความเร็วจะสื่อสารกับระบบได้อย่างไร?

PCIหรือPeripheral Component Interconnect (ทางเชื่อมอุปกรณ์ต่อพ่วงภายใน)เป็นหัวข้อที่6 ขณะที่ป้ายในหน้า46เขียนPCI Express. สไลด์ให้แกนว่าเป็นhigh-speed bus systemที่เชื่อมperipheralsหลายชนิด/หลายความเร็ว. ต้องแยกชื่อสองแบบให้ถูกก่อนเทียบbandwidth.

[อธิบายเสริม] PCIแบบเดิมเป็นparallel sharedbus;PCI ExpressหรือPCIeเป็นserial point-to-point links (ลิงก์อนุกรมระหว่างปลายสองฝั่ง)ผ่านโครงสร้างสวิตช์. Lane (ช่องสัญญาณหนึ่งชุด)รวมได้เป็นx1,x4,x8,x16ตามการออกแบบ. ภาพXeonหน้า32และIBMหน้า51ใช้PCIeเป็นเส้นเชื่อมI/O;ชื่อPCIeไม่ได้บอกว่าเป็นการpoll,interruptหรือDMA เพราะสามอย่างนั้นเป็นวิธีจัดงานบนระบบที่ใช้ลิงก์นี้ได้. ไม่มีตารางgeneration/ความเร็วPCIeในสไลด์หน้านี้จึงไม่เพิ่มตัวเลขรุ่นล่าสุดแทนต้นฉบับ.

3.22 · 7. SATA (ลิงก์อนุกรมสำหรับดิสก์)

จะเชื่อมอุปกรณ์เก็บข้อมูลด้วยทางเฉพาะที่เรียบง่ายได้อย่างไร?

Serial Advanced Technology AttachmentหรือSATA (อินเทอร์เฟซอนุกรมสำหรับหน่วยเก็บข้อมูล)ใช้ในdesktopและงานindustrial/embeddedตามสไลด์. เอกสารระบุdata rateถึง6Gbps แต่บรรทัด“maximum per device300Mbps”ขัดกันและไม่ควรนำไปจำเป็นค่าสูงสุดของSATA6Gbps.

[อธิบายเสริม] ตรวจ SATA-IO Revision3.0 FAQ ระบุSATA6Gb/sอัตรา600MB/s. ดังนั้นบทนี้คงให้เห็นว่าต้นฉบับพิมพ์300Mbps แต่ไม่รับรองค่านั้น. Signaling6Gb/sหลัง8b/10bencoding (ส่ง10บิตเพื่อข้อมูล8บิต)เหลือ6×8/10=4.8Gb/sแล้วหาร8=0.6GB/s=600MB/sก่อนงานprotocolอื่น;300MB/sเป็นระดับอัตราที่ต่างกัน ไม่ใช่300Mbps.

3.23 · 8. Ethernet (เครือข่ายใช้สาย)

จะเชื่อมคอมพิวเตอร์และstorageหลายตัวในองค์กรผ่านเครือข่ายอย่างไร?

Ethernet (ตระกูลมาตรฐานเครือข่ายใช้สาย)เชื่อมPC,workstation,serverและmass storageในองค์กรเล็กใหญ่. สไลด์เล่าว่าเริ่มจากระบบทดลองbus-based3Mbpsแล้วเปลี่ยนเป็นswitch-based (แต่ละdeviceต่อตรงเข้าสวิตช์กลาง) และเพิ่มอัตราประมาณหนึ่งลำดับขนาดหลายครั้ง. แยกbusร่วมที่ทุกคนแชร์ทางกับswitchที่ส่งต่อframeระหว่างportที่เกี่ยวข้อง.

อัตราถึง100Gbpsและระยะตั้งแต่ไม่กี่เมตรถึงหลายสิบกิโลเมตรเป็นช่วงรุ่น/สื่อที่สไลด์กล่าวถึง ไม่ใช่ทุกสายและทุกEthernetportทำได้เท่ากัน. คำว่าcurrently available100Gbpsเป็นบริบทของเอกสาร ไม่ใช่ข้ออ้างว่าเป็นรุ่นเร็วสุดปัจจุบัน. [อธิบายเสริม] Ethernetคือวิธีลิงก์/ส่งframe ส่วนIP/TCPเป็นกติกาชั้นบนตามpacketที่เรียน จึงเปลี่ยนอัตราEthernetโดยยังรับส่งTCP/IPได้.

3.24 · 9. Wi-Fi (เครือข่ายไร้สาย)

จะเชื่อมอุปกรณ์เคลื่อนที่โดยไม่ลากสายเครือข่ายได้อย่างไร?

Wi-Fi (การเชื่อมเครือข่ายไร้สายตามตระกูลIEEE802.11)เชื่อมcomputer,tablet,smartphone,กล้อง,TVและthermostat (อุปกรณ์ควบคุมอุณหภูมิ). ในองค์กรช่วยเข้าถึงงานได้คล่องตัวและpublic hotspots (จุดบริการเครือข่ายสาธารณะ)ช่วยให้เชื่อมต่อได้ตามสถานที่ต่างๆ. เสาอากาศ เทคนิคส่งไร้สาย และprotocolพัฒนาแล้วIEEE802.11ออกมาตรฐานรุ่นใหม่ที่เร็วขึ้น.

สไลด์ใช้คำว่า“current version802.11ac(2014),maximum3.2Gbps” จึงคงเป็นตัวเลขตามข้อความในเอกสารพร้อมระบุว่าไม่ใช่คำกล่าวถึงรุ่นปัจจุบันหรือความเร็วที่ผู้ใช้ทุกคนได้รับ. [อธิบายเสริม] อัตราที่เครื่องเดียวได้ยังขึ้นกับจำนวนspatial streams (ชุดสัญญาณที่ส่งพร้อมกัน),ความกว้างchannel (ย่านความถี่ที่ใช้),สัญญาณรบกวนและการแชร์สื่อ จึงไม่ควรเอาเลขpeakไปแทนความเร็วInternetโดยไม่วัดเส้นทางจริง.

3.25 · IBM EC12 channel subsystem (หลายระบบเสมือนใช้หลายช่อง)

เครื่องmainframeแบ่งI/Oให้หลายpartitionอย่างไรโดยไม่ให้CPUสั่งทุกdevice?

ภาพchannel subsystem (ส่วนจัดการช่องI/O)มี4subsystems;แต่ละตัวรับpartition (ส่วนเครื่องที่แบ่งใช้งาน)ผ่านsubchannels (ข้อมูลควบคุมงานI/Oที่partitionใช้)แล้วต่อchannelsไปdevices. ตัวเลขบนภาพคือ≤15partitionsต่อsubsystem,≤60partitionsต่อsystem,≤256channelsต่อsubsystem. เส้นแตกหลายทางแสดงmany-to-many connectivity (หลายส่วนมีทางเชื่อมหลายส่วน)ระหว่างpartitionกับsubsystem/channel ไม่ใช่สายdataที่ทุกเส้นส่งพร้อมกันเสมอ.

วงเล็บล่างภาพพิมพ์“≤1024 partitions per system”แต่ขัดกับ≤60ด้านบน และอยู่ใต้กลุ่มchannels;4×256=1024จึงต้องอ่านว่า≤1024 channels per system ไม่ใช่1024partitions. บทนี้เปิดเผยการแก้จากตำแหน่งและเลขในภาพ. [อธิบายเสริม] Partitionเป็นผู้ใช้เส้นทางI/O,channelเป็นทางบริการ,subchannelเป็นสถานะควบคุมงาน ทั้งสามจึงนับคนละหน่วย.

3.26 · IBM zEC12 I/O frames (ดูส่วนกายภาพของระบบใหญ่)

ภาพตรรกะchannelในบทเรียนอยู่ตรงไหนของตู้เครื่องจริง?

ภาพfront viewของIBM zEC12มีลูกศรชี้internal batteries optional (แบตเตอรี่ภายในที่เลือกติดตั้ง),power supplies (ชุดจ่ายไฟ),support elements (ส่วนควบคุมสนับสนุน),I/O cage carried forward (โครงชุดI/Oที่คงใช้งานต่อ),PCIe I/O drawer (ลิ้นชักใส่การ์ดI/O). อีกฝั่งชี้FSPหรือFlexible Service Processor controller cards (การ์ดตัวประมวลผลบริการ),processor booksพร้อมmemory/HCA/PCIe-fanout cards,InfiniBandและPCIe I/O interconnects (ชุดทางเชื่อม),N+1 water cooling units (ชุดระบายความร้อนด้วยน้ำมีส่วนเพิ่มสำรองตามป้าย).

ภาพนี้ใช้สอนว่าระบบI/Oจริงมีทั้งการ์ด ทางเชื่อม ไฟเลี้ยง การระบายความร้อนและวงจรบริการ ไม่ได้มีเพียงprocessorกับสายbusบนกระดาษ. ลูกศรสีแดงเป็นเส้นชี้ส่วนประกอบ ไม่ใช่ลูกศรdataflow;อย่านำลำดับตำแหน่งบนภาพไปอ่านเป็นลำดับย้ายpacket. [อธิบายเสริม] N+1หมายถึงมีหน่วยเพิ่มเติมจากจำนวนที่ต้องใช้ตามการออกแบบเพื่อรองรับการเสียหนึ่งหน่วย ไม่ได้บอกจำนวนตู้ทั้งหมด.

3.27 · IBM EC12 I/O system structure (ติดตามจากbookถึงcontroller)

ข้อมูลจากprocessorbookไปอุปกรณ์ต่างชนิดผ่านทางใดบ้าง?

ภาพหน้า51วางBook1…4ด้านบน แต่ละbookมีmemory,PU (processing unit/หน่วยประมวลผล),ส่วนกลางป้ายSC1,SC0;สไลด์ไม่ได้ขยายอักษรSCจึงคงป้ายโดยไม่เดารายละเอียด. Book1/2ต่อPCIe(8X)ลงPCIe switchesหลายตัวในPCIe I/O Drawer แล้วต่อFibre Channel controller (ตัวควบคุมเครือข่ายstorage)และ10-Gbps Ethernet controller. เส้นไขว้แสดงการมีทางเชื่อมจากหลายbookไปหลายswitch ไม่ใช่ว่าข้อมูลต้องข้ามbookตามลำดับ1→2→3→4.

Book3/4ต่อHCA2(8X)ซึ่งในบริบทนี้เป็นhost channel adapter (ตัวต่อhostกับchannel) ลงInfiniBand multiplexorsในI/O Cage & I/O Drawer แล้วแตกเป็นESCON channels (ช่องI/OแบบESCONในภาพ)และportsของ1-Gbps Ethernet controller. จุดหมายทั้งสองกลุ่มแสดงว่าระบบเดียวรองรับI/Oหลายรุ่นผ่านทางPCIeและInfiniBand. [อธิบายเสริม] ป้าย8Xบอกความกว้างทางตามรูป ควรอ่านคู่กับชนิดลิงก์ ไม่ใช่ใช้แปลงเป็น8Gbpsทันที. หน้า52เป็นQ&A ไม่มีรายละเอียดทางเทคนิคเพิ่ม.

6 · จุดที่มักสับสนและประเด็นฝึกสอบ

[อธิบายเสริม] ประเด็นสำหรับตรวจความเข้าใจ ไม่ใช่การยืนยันข้อสอบจริง

Interrupt-driven I/O vs DMA

Interruptเปลี่ยนวิธีรอ แต่ในแบบinterrupt-drivenCPUยังreadwordจากI/Oแล้วwriteไปmemory. DMAเปลี่ยนผู้ย้ายให้controllerทำblockและอาจใช้interruptแจ้งจบ. จึงไม่ควรสรุปว่าใช้interruptแล้วคือDMA หรือDMAไม่ใช้interrupt.

MMIO vs programmed I/O

MMIOบอกว่ารีจิสเตอร์deviceอยู่ในaddressspaceใดและใช้คำสั่งชนิดใด;programmed/pollingบอกCPUเฝ้าสถานะและย้ายอย่างไร. โปรแกรมอาจใช้MMIOตั้งDMAหรือจัดinterruptได้โดยไม่ต้องpollทุกbyte.

Data vs status vs control

Dataคือเนื้อข้อมูล,Statusคือสภาพอุปกรณ์เช่นready,Controlคือคำสั่งตั้งงาน. ภาพregister517มีทั้งstatus/controlโดยแยกบิต ขณะที่516เป็นdata. การเขียนstartbitไม่ได้กำหนดreadybitโดยCPUเอง.

DCA hint vs DDIO injection

DCAแบบprefetchhintให้packetลงsystemmemoryก่อนแล้วเตือนcoreอ่านล่วงหน้า ส่วนDDIOมุ่งให้cacheเป็นปลายทาง/ต้นทางI/Oเพื่อลดการผ่านDRAM. ชื่อDCAกว้างกว่าวิธีhintprototypeหนึ่งรุ่น จึงไม่เหมารวมว่าDCAทุกแบบขาเข้าอย่างเดียวหรือDDIOใช้ได้แค่prefetch.

Mbps vs MB/s; generation vs current maximum

bคือbit,Bคือbyteและ1B=8b. ต้องบอกว่าตัวเลขเป็นsignaling/usableและรุ่นใด. 10GbpsของThunderboltและ100GbpsของEthernetเป็นตัวอย่างในเอกสาร ไม่ใช่อันดับล่าสุด;SCSIและSATAมีunittypoที่บทเรียนเปิดเผยแล้ว.

1. [อธิบายเสริม] อธิบายความแตกต่างสามวิธีI/Oโดยแยกผู้รอกับผู้ย้ายข้อมูล

ProgrammedCPUออกคำสั่งและpollจนพร้อมแล้วreadwordเข้าCPU/storememoryทุกword. Interrupt-drivenออกงานแล้วทำอื่น อุปกรณ์แจ้งพร้อมให้ISRกลับมาย้ายwordผ่านCPU จึงลดbusywaitแต่ไม่เอางานย้ายออกจากCPU. DMAให้CPUตั้งblock/address/countแล้วcontrollerย้ายdevice↔memoryเองและอาจinterruptเมื่อเสร็จ ลดงานCPUต่อwordแต่ยังใช้bus/memoryร่วม.

2. [อธิบายเสริม] ในMMIOภาพเดิมเหตุใดอ่าน517ก่อน516 และbranchตรวจSign?

517เป็นstatus/control:bit0ใช้startread,bit7บอกready. เริ่มLoadAC1แล้วStore517 จากนั้นLoad517วนที่202จนbit7เป็น1. ในค่า8บิตbit7เป็นsignbitจึงBranchifSign0หมายถึงยังbusy. พร้อมแล้วจึงLoad516รับdataไม่ใช่อ่าน517เป็นตัวอักษร. ต้องแยกตำแหน่งregisterออกจากค่าในregister.

3. [อธิบายเสริม] ถ้าinterruptเกิดหลังคำสั่งN จะกลับตรงไหนและต้องรักษาอะไร?

PCเดิมชี้N+1 ต้องบันทึกPCกับPSWก่อนเปลี่ยนไปISR และsavegeneralregistersที่handlerใช้ตามกติกา. ภาพเริ่มSPT ลดเป็นT−Mระหว่างเก็บสถานะแล้วเข้าISRที่Y. เมื่อถึงreturnY+Lให้คืนregisters,PSW,PCจากstackและSPกลับT จึงกลับN+1 ไม่กลับNจนทำผลเดิมซ้ำและไม่ไปY+LของISRต่อเป็นงานผู้ใช้.

4. [อธิบายเสริม] เปรียบ4วิธีระบุอุปกรณ์ที่ขอinterrupt

Multiplelinesใช้สายแยกแต่มีขาจำกัดและอาจแชร์;softwarepollอ่านstatusหลายmoduleใช้เวลา;daisychainhardwareให้ackผ่านmoduleแล้วตัวได้รับสิทธิ์วางvectorเลือกISR;busarbitrationให้ผู้ได้busขอinterruptและตอบvectorบนdataเมื่อCPUack. PIC82C59Aแบบcascadeจัดกลุ่ม8slave×8inputsได้64requestsไปmasterเส้นเดียวสู่CPU แต่ยังต้องมีกติกาpriorityและระบุvector.

5. [อธิบายเสริม] Mode-setกับBSRของ8255ต่างกันอย่างไร?

D7=1ตีความทั้งwordเป็นmode/directionsของA/B/C:GroupAใช้D6D5,D4,D3;GroupBใช้D2,D1,D0. D7=0เป็นBSRให้D3D2D1เลือกbitC0–7และD0set/reset โดยD6…D4ไม่สน. ภาพkeyboard/displayใช้Aรับ,Bส่ง,Cประสานready/ack/control จึงต้องตั้งตามหน้าที่และmode ไม่สมมติว่าบิตCทุกเส้นเป็นpayloadได้พร้อมhandshake.

6. [อธิบายเสริม] ตามเส้นDREQ→HRQ→HLDA→DACKแล้วอธิบายfly-by

Deviceส่งDREQถึง8237;8237ส่งHRQขอCPUปล่อยbus;CPUตอบHLDAเมื่อยอมให้;8237ส่งDACKยืนยันdeviceแล้วสร้างaddress/control เช่นIOR+MEMWสำหรับinput. ข้อมูลผ่านbusตรงdevice→memoryไม่พัก8237ในfly-by. ชิปยังเก็บaddress/countและทำmemory-to-memoryแบบtemporaryregisterได้ จึงไม่เอาคำอธิบายfly-byไปห้ามทุกโหมดของชิป.

7. [อธิบายเสริม] ทำไมpacketรับเข้าโดยDMAอาจทำcorecachemiss และDDIOช่วยอย่างไร?

DMAแบบเดิมรับpacket/descriptorลงsystembufferในDRAMและอาจinvalidateสำเนาเก่า. เมื่อcoreอ่านheaderต้องfetchจากmemoryขึ้นcacheอีกครั้งก่อนย้ายpayloadไปแอป. DCAhintเตือนให้prefetchหลังข้อมูลเข้าmemoryจึงซ่อนรอได้บางส่วน;DDIOwrite-update/allocateLLCโดยตรงทำให้coreอ่านจากcacheและลดDRAMtrips. ขาออกNICอ่านจากcacheได้ด้วยแต่cachemissยังต้องmemory จึงไม่รับรองไม่มีDRAMaccessทุกกรณี.

8. [อธิบายเสริม] ถ้าเห็นSATA6Gbps,300Mbpsในหน้าเดียวกันและIBM1024partitionsควรทำอย่างไร?

ตรวจหน่วยและบริบทก่อนจำ. 6Gb/sไม่เท่ากับ300Mb/s;SATA-IOระบุ600MB/sสำหรับ6Gb/sภายหลังencodingจึงเปิดเผยว่าบรรทัด300Mbpsต้นฉบับไม่สอดคล้อง. SCSIUltra160ใช้160MB/sไม่ใช่160Mbps. IBMภาพให้4subsystems×256channels=1024channels ขณะที่partitionsมี4×15=60 ดังนั้นป้ายล่าง1024partitionsต้องแก้หน่วยเป็นchannelsโดยแจ้งsourceissue ไม่ลบความขัดแย้งเงียบๆ.
