ภาพรวม

1 · ภาพรวมบทนี้

บทปฐมนิเทศนี้บอกว่าเรากำลังจะเรียนอะไร เรียนไปเพื่ออธิบายปัญหาใด และต้องแสดงความเข้าใจอย่างไร ไม่ใช่บทลงรายละเอียดวงจรหรือสูตรประสิทธิภาพ

Computer Architecture (สถาปัตยกรรมคอมพิวเตอร์) เชื่อมการออกแบบเครื่องเข้ากับวิธีที่โปรแกรมทำงาน ส่วน Operating System: OS (ระบบปฏิบัติการ) จัดการทรัพยากรให้โปรแกรมหลายงานใช้เครื่องร่วมกันได้

ลำดับใหญ่ของวิชาคือ พื้นฐานเครื่อง → ประสิทธิภาพและทรัพยากรฮาร์ดแวร์ → การจัดการงานของ OS → การจัดการหน่วยความจำและแฟ้มข้อมูล

ข้อมูลคะแนน ห้องเรียน วันเวลา และรายการหนังสือในบทนี้เป็นข้อมูลตามสไลด์ต้นฉบับปี 2026 ใช้ตรวจบริบทของเอกสาร และตรวจประกาศใน MyCourse อีกครั้งเมื่อต้องใช้จริง

2 · พื้นฐานที่ต้องรู้ก่อน

[อธิบายเสริม] บทที่ช่วยปูพื้นฐาน: เริ่มจากศูนย์ได้

[อธิบายเสริม] เริ่มได้โดยไม่ต้องเคยเรียนฮาร์ดแวร์: Computer (คอมพิวเตอร์) คือเครื่องที่ทำตามคำสั่งเพื่อรับข้อมูล คำนวณ เก็บข้อมูล และส่งผลออกมา Hardware (ฮาร์ดแวร์) คือชิ้นส่วนที่จับต้องได้ เช่น หน่วยประมวลผลและหน่วยความจำ Software (ซอฟต์แวร์) คือคำสั่งที่บอกให้ชิ้นส่วนเหล่านั้นทำงาน Program (โปรแกรม) คือลำดับคำสั่งสำหรับทำงานหนึ่ง ๆ

[อธิบายเสริม] CPU: Central Processing Unit (หน่วยประมวลผลกลาง) คือส่วนที่ทำคำสั่ง Memory (หน่วยความจำ) คือพื้นที่เก็บคำสั่งและข้อมูลที่กำลังใช้ Storage (อุปกรณ์เก็บข้อมูล) คือที่เก็บข้อมูลระยะยาว เช่น SSD และ I/O: Input/Output (การรับเข้า/ส่งออก) คือการแลกเปลี่ยนข้อมูลระหว่างเครื่องกับอุปกรณ์หรือโลกภายนอก คำเหล่านี้จะมีบทเรียนเฉพาะในภายหลัง

3.2 · Computer Architecture Topics (แผนที่ฝั่งฮาร์ดแวร์และคำสั่ง)

โปรแกรมหนึ่งทำงานได้อย่างไรตั้งแต่เป็นข้อมูล ไปจนถึงเครื่องประมวลผลและส่งผลลัพธ์?

คำอธิบายรายวิชาหน้า 3 ครอบคลุมทั้งสถาปัตยกรรมและระบบปฏิบัติการ ส่วนหน้า 4 ยกหัวข้อฝั่งสถาปัตยกรรมสำหรับครึ่งภาคแรกตามลำดับดังตาราง คำอธิบายสั้นในคอลัมน์ขวาเป็นพื้นฐาน [อธิบายเสริม] เพื่อให้ผู้เริ่มต้นอ่านชื่อเรื่องรู้เรื่อง ไม่ใช่เนื้อหาที่ต้นฉบับปฐมนิเทศลงรายละเอียดไว้แล้ว

หัวข้อตามลำดับต้นฉบับ[อธิบายเสริม] ปัญหาที่หัวข้อนั้นช่วยตอบ
Structure and Architecture (โครงสร้างและสถาปัตยกรรม)เครื่องมีส่วนใด เชื่อมกันอย่างไร และโปรแกรมมองเห็นความสามารถอะไร
Basic Components (องค์ประกอบพื้นฐาน)CPU หน่วยความจำ และอุปกรณ์รับเข้า/ส่งออกแบ่งหน้าที่กันอย่างไร
Data Representations (การแทนข้อมูล)จำนวน ตัวอักษร และข้อมูลต่าง ๆ เขียนเป็นบิต 0 และ 1 ได้อย่างไร
Assembly Language (ภาษาแอสเซมบลี)ชื่อคำสั่งที่คนอ่านได้เชื่อมกับคำสั่งระดับเครื่องอย่างไร
Memory System Organization (การจัดระบบหน่วยความจำ)คำสั่งและข้อมูลถูกจัดเก็บและเข้าถึงที่ตำแหน่งใด
Memory Hierarchy and Cache (ลำดับชั้นหน่วยความจำและแคช)ทำอย่างไรให้ CPU หาข้อมูลได้เร็ว แม้พื้นที่เก็บขนาดใหญ่จะช้ากว่า
Input and Output Systems (ระบบรับเข้าและส่งออก)CPU สื่อสารกับอุปกรณ์ที่มีความเร็วต่างกันอย่างไร
Storage Systems (ระบบเก็บข้อมูล)เก็บข้อมูลให้คงอยู่และเรียกกลับมาใช้อย่างไร
Computing Units (หน่วยคำนวณ)หน่วยประมวลผลดำเนินงานคำนวณและตรรกะอย่างไร
Multiprocessor Architecture (สถาปัตยกรรมหลายหน่วยประมวลผล)หลายหน่วยประมวลผลแบ่งงานและใช้ข้อมูลร่วมกันอย่างไร

[อธิบายเสริม] ให้มองโปรแกรมเปิดภาพหนึ่งภาพ: คำสั่งต้องถูกอ่าน ข้อมูลภาพต้องอยู่ในรูปที่เครื่องเข้าใจ ข้อมูลเดินทางจากที่เก็บผ่านหน่วยความจำไปถึงหน่วยประมวลผล แล้วออกสู่จอภาพ เรื่องเดียวจึงพาดผ่านหลายหัวข้อในตาราง การเรียนชื่อส่วนประกอบเพียงอย่างเดียวจึงยังไม่พอ ต้องตามการทำงานระหว่างส่วนด้วย

3.3 · Operating System Topics (แผนที่ฝั่งการจัดการทรัพยากร)

เมื่อมีหลายโปรแกรมอยากใช้เครื่องพร้อมกัน ใครจัดคิว ป้องกันข้อมูล และเก็บแฟ้มให้เรา?

หน้า 3 ระบุ Operating System: OS (ระบบปฏิบัติการ) ซึ่ง [อธิบายเสริม] หมายถึงซอฟต์แวร์ที่ประสานการใช้ทรัพยากรของเครื่องให้โปรแกรมทำงานได้อย่างเป็นระบบ หัวข้อต่อไปนี้เป็นขอบเขตของวิชาทั้งรายวิชา ไม่ได้หมายความว่าหน้าปฐมนิเทศสอนกลไกเหล่านี้ครบแล้ว

หัวข้อที่ต้นฉบับระบุ[อธิบายเสริม] ความหมายเริ่มต้น
Resource Management (การจัดการทรัพยากร)ตัดสินใจว่าโปรแกรมใดได้ CPU พื้นที่หน่วยความจำ หรืออุปกรณ์ในเวลาใด
Process Management and Scheduling (การจัดการและจัดตารางงานของโปรเซส)Process คือโปรแกรมที่กำลังทำงาน; scheduling คือการเลือกว่างานใดได้ใช้ CPU ต่อไป
Synchronization (การประสานจังหวะ)กำหนดลำดับการใช้ข้อมูลร่วมกัน เพื่อให้งานหลายงานไม่แก้ข้อมูลชนกัน
Deadlock (การติดตาย)งานหลายงานรอกันเป็นวงจนไม่มีงานใดไปต่อได้
Memory Management (การจัดการหน่วยความจำ)แบ่งพื้นที่ จดจำว่าใครใช้ส่วนใด และแปลงตำแหน่งที่โปรแกรมใช้
Segmentation and Paging (การแบ่งเป็นเซกเมนต์และการแบ่งเป็นหน้า)สองวิธีจัดส่วนของพื้นที่หน่วยความจำ: ตามส่วนเชิงตรรกะ หรือเป็นชิ้นขนาดคงที่
Virtual Memory (หน่วยความจำเสมือน)ทำให้โปรแกรมใช้พื้นที่ที่อยู่ของตนเอง โดยระบบเป็นผู้จัดการความสัมพันธ์กับหน่วยความจำจริง
Protection, Sharing, Access Control (การป้องกัน การใช้ร่วมกัน และการควบคุมสิทธิ์)แยกว่าใครเข้าถึงข้อมูลใดได้ และจะใช้ทรัพยากรร่วมกันอย่างไรโดยไม่รบกวนกัน
File and I/O Systems (ระบบแฟ้มข้อมูลและระบบรับเข้า/ส่งออก)ให้ชื่อและวิธีเข้าถึงข้อมูลที่เก็บอยู่ พร้อมประสานงานกับอุปกรณ์

[อธิบายเสริม] อุปมา: เครื่องเป็นพื้นที่ทำงานที่มีโต๊ะและเครื่องมือจำกัด OS คล้ายผู้จัดการที่จัดคิวและสิทธิ์ใช้เครื่องมือ อุปมานี้ช่วยเห็นเหตุผลที่ต้องจัดการทรัพยากร แต่ในเครื่องจริงสิ่งที่จัดคือเวลาของ CPU ที่อยู่หน่วยความจำ และคำขอ I/O

3.4 · Textbooks and Objectives (หนังสือและขอบเขตการศึกษา)

เราจะใช้วิชานี้วิเคราะห์การทำงานของโปรแกรมอย่างไร และต้องเรียนลึกถึงการสร้างทรานซิสเตอร์หรือไม่?

หน้า 5 ระบุหนังสือสามรายการ: (1) Hennessy and Patterson, Computer Architecture: A Quantitative Approach, 7th edition, 2026; (2) William Stallings, Computer Organisation and Architecture, 11th edition, 2022; (3) David A. Patterson และ John L. Hennessy, Computer Organisation and Design RISC-V edition: The Hardware Software Interface, 2020 รายละเอียดปีและฉบับนี้ถอดตามสไลด์ ไม่ใช่การตรวจบรรณานุกรมจากสำนักพิมพ์

หน้า 6 วางเป้าหมายหลักว่าให้ศึกษา บทบาทของสถาปัตยกรรมต่อ System/Program Performance (ประสิทธิภาพของระบบและโปรแกรม) หมายถึงดูว่าการออกแบบส่วนใดของเครื่องทำให้งานที่ต้องการเสร็จเร็วหรือใช้ทรัพยากรดีขึ้น คำถามนำของต้นฉบับคือ องค์ประกอบหลักของสถาปัตยกรรมมีอะไร การออกแบบใดกระทบแอปพลิเคชัน หน่วยประมวลผลประสิทธิภาพสูงมีโครงสร้างอย่างไร แนวโน้มใหม่คืออะไร และจะใช้ Quantitative Approach (แนวทางเชิงปริมาณ) คืออาศัยตัวเลขเพื่อเปรียบเทียบอย่างมีเหตุผลได้อย่างไร

ขอบเขตที่สไลด์ระบุว่าไม่ใช่เป้าหมายคือ Hardware Design (การออกแบบฮาร์ดแวร์ระดับลงมือสร้างวงจร) และ Semiconductor Technology Details (รายละเอียดเทคโนโลยีสารกึ่งตัวนำ) จึงต้องรู้ว่าส่วนประกอบทำหน้าที่อะไรและมีผลต่อโปรแกรมอย่างไร แต่ไม่ต้องตีความว่าบทนี้จะสอนกระบวนการผลิตวงจรทุกขั้น

[อธิบายเสริม] ตัวอย่างของแนวคิดเชิงปริมาณคือ เมื่อพูดว่าเครื่องหนึ่งเร็วกว่า ต้องระบุว่างานอะไร ใช้เวลาหรือปริมาณงานเป็นตัววัด และเทียบภายใต้เงื่อนไขใด การจำเพียงความถี่ CPU จึงยังไม่ใช่การประเมินโปรแกรมครบถ้วน บทถัดไปจะค่อย ๆ ให้สูตรและตัวอย่างจริง

3.5 · Objectives and CLOs (จากเป้าหมายสิบข้อสู่ผลลัพธ์สี่กลุ่ม)

จะตรวจได้อย่างไรว่าเราเข้าใจวิชานี้จริง แทนที่จะเพียงคุ้นกับชื่อหัวข้อ?

Course Objective (วัตถุประสงค์การเรียน) บอกความสามารถที่วิชาตั้งใจพัฒนา ส่วน CLO: Course Learning Outcome (ผลลัพธ์การเรียนรู้รายวิชา) รวบความสามารถที่ต้องแสดงได้เมื่อเรียนจบ หน้า 7 มีสิบข้อ และหน้า 8 จัดรวมเป็นสี่ CLO ดังตาราง

Objective ตามเลขในต้นฉบับความสามารถที่ต้องได้CLO
1เข้าใจการจัดระบบคอมพิวเตอร์ดิจิทัล Pipelining (การเหลื่อมขั้นการทำงาน) และ Parallelism (การทำงานหลายส่วนพร้อมกัน)1
2อธิบายการทำคำสั่ง ISA Format (รูปแบบชุดคำสั่งที่เครื่องรองรับ) และ Addressing Mode (วิธีระบุที่อยู่หรือแหล่งของข้อมูล)1
3ประเมิน Performance Metrics (ตัววัดประสิทธิภาพ)2
4อธิบาย Memory Hierarchy (การจัดหน่วยความจำหลายระดับ)2
5อธิบาย I/O Organisation (การจัดระบบรับเข้าและส่งออก)2
6อธิบาย Process Management (การจัดการโปรแกรมที่กำลังทำงาน)3
7เข้าใจ Concurrency (การดำเนินงานหลายงานในช่วงเวลาทับซ้อนกัน) และ Synchronisation (การประสานงานให้ใช้ข้อมูลร่วมกันถูกต้อง)3

ภาพรวมหน้า 8 เรียง Architecture basics → Performance/hardware → OS process handling → OS storage handling ลูกศรหมายถึงการต่อยอดความรู้: รู้จักเครื่องก่อนจึงประเมินการใช้ทรัพยากรได้ แล้วจึงอธิบายว่า OS จัดงานและพื้นที่เก็บข้อมูลอย่างไร ไม่ได้หมายความว่าแต่ละส่วนแยกขาดจากกัน

[อธิบายเสริม] เปลี่ยนคำว่า “เข้าใจ” ให้เป็นสิ่งที่ตรวจได้ เช่น วาดเส้นทางคำสั่งแล้วเล่าเหตุผลของลูกศร คำนวณเวลาพร้อมหน่วย อธิบายเหตุการณ์ที่งานรอกัน หรือบอกว่าความจำกับแฟ้มข้อมูลมีหน้าที่ต่างกันอย่างไร ความสามารถเหล่านี้ตรวจตนเองได้ดีกว่าการจำชื่อคำภาษาอังกฤษอย่างเดียว

4 · ตัวอย่างและวิธีทำทีละขั้น

[อธิบายเสริม] อ่านน้ำหนักคะแนน 30–15–5 โดยไม่สับสนกับคะแนนทั้งวิชา

โจทย์ฝึกจากตัวเลขหน้า 2: ถ้าได้สอบกลางภาค 24/30 การบ้าน 12/15 และ quiz 4/5 จะได้เท่าใดในส่วนนี้?

  1. หาคะแนนเต็มของส่วนที่สไลด์แสดง: 30 + 15 + 5 = 50 คะแนน
  2. รวมคะแนนที่ทำได้: 24 + 12 + 4 = 40 คะแนน
  3. หาสัดส่วนภายในส่วนนี้: 40 ÷ 50 = 0.8
  4. แปลงเป็นร้อยละของส่วนนี้: 0.8 × 100 = 80%
  5. สรุปว่าได้ 40 จาก 50 หรือ 80% ของส่วนนี้ ยังสรุปเกรดสุดท้ายไม่ได้เพราะยังต้องมีข้อมูลคะแนนส่วนอื่น

[อธิบายเสริม] จับความสามารถเข้ากับ CLO อย่างมีเหตุผล

โจทย์: “อธิบายว่าทำไมหลายงานจึงรอกันไปต่อไม่ได้” ควรทบทวนกลุ่มใด?

  1. ระบุคำสำคัญ: หลายงานรอกันจนไปต่อไม่ได้ ตรงกับ Deadlock (การติดตาย)
  2. เทียบหน้า 7 พบ Objective 8: Analyse deadlocks (วิเคราะห์การติดตาย)
  3. อ่านตารางหน้า 8 พบ CLO 3 รวม Objectives 6, 7, 8
  4. จึงเลือก CLO 3 ซึ่งเกี่ยวกับ process, concurrency, synchronisation และ deadlock ไม่ใช่ CLO 2 ที่เน้นประสิทธิภาพและทรัพยากรฮาร์ดแวร์

[อธิบายเสริม] แปลงตารางเรียนเป็นแผนอ่านแปดช่วง

  1. นับแถวหัวข้อในตารางได้ 8 ครั้ง
  2. แต่ละแถวระบุ 2 ชั่วโมง จึงเป็น 8 × 2 = 16 ชั่วโมงบรรยายในตาราง
  3. อ่านแถวที่ 2 ก่อนแถวที่ 4: ต้องรู้ก่อนว่า CPU ทำคำสั่งและอ่านข้อมูลอย่างไร จึงอธิบายได้ว่าลำดับชั้นหน่วยความจำช่วยช่วงใด
  4. เตรียมคำถามก่อนแถวที่ 8: ถ้ามีหลายหน่วยประมวลผล จะส่งงานและข้อมูลระหว่างกันอย่างไร คำถามนี้ต่อยอดจากองค์ประกอบ หน่วยความจำ และ I/O ที่เรียนมาก่อน
  5. ตัวเลข 16 ชั่วโมงเป็นผลรวมเฉพาะตารางหน้านี้ ไม่ใช่จำนวนชั่วโมงทั้งหมดของรายวิชา

7 · ทบทวนก่อนสอบ

  • ครึ่งแรกเริ่มจากองค์ประกอบและคำสั่ง ต่อด้วยข้อมูล หน่วยความจำ I/O ที่เก็บข้อมูล หน่วยคำนวณ และหลายหน่วยประมวลผล

  • คะแนนและตารางเป็นข้อมูลจากต้นฉบับ ต้องแยกความเข้าใจเนื้อหาออกจากการยืนยันประกาศปัจจุบัน

1. [อธิบายเสริม] วิชานี้เชื่อมฮาร์ดแวร์กับซอฟต์แวร์อย่างไร?

ฝั่งสถาปัตยกรรมอธิบายว่าคำสั่ง ข้อมูล หน่วยประมวลผล หน่วยความจำ และ I/O ทำงานร่วมกันอย่างไร และการออกแบบมีผลต่อโปรแกรมอย่างไร ฝั่ง OS อธิบายการจัดสรรเครื่องนี้ให้หลายงานใช้ได้ถูกต้องและมีประสิทธิภาพ การเรียนจึงต้องตามทั้งการทำงานของเครื่องและกฎที่ซอฟต์แวร์ระบบใช้จัดการทรัพยากร

2. [อธิบายเสริม] จะแสดงว่าเรียนแบบ quantitative ได้อย่างไร?

ต้องระบุตัววัดและเงื่อนไขเปรียบเทียบให้ชัด เช่น งานใด ใช้เวลาเท่าใด และมีข้อจำกัดอะไร แล้วใช้ตัวเลขให้ตรวจวิธีคิดได้ การกล่าวลอย ๆ ว่าเครื่องหนึ่งแรงกว่าไม่พอ เพราะความเร็วของส่วนเดียวไม่รับประกันเวลารวมของโปรแกรม บทนี้ตั้งทิศทางดังกล่าว ส่วนสมการจะปรากฏในบทประสิทธิภาพ

3. [อธิบายเสริม] CLO 2 รวมความสามารถใด และเกี่ยวข้องกันอย่างไร?

CLO 2 รวม Objective 3 การประเมินตัววัดประสิทธิภาพ Objective 4 การอธิบายลำดับชั้นหน่วยความจำ และ Objective 5 การอธิบายการจัดระบบ I/O ทั้งสามอยู่ในกลุ่มประสิทธิภาพและทรัพยากรฮาร์ดแวร์ เพราะโปรแกรมต้องใช้ทั้งการคำนวณ การอ่านข้อมูล และการติดต่ออุปกรณ์ จึงต้องมองการใช้ทรัพยากรรวมกัน

4. [อธิบายเสริม] ถ้าต้องวิเคราะห์การติดตาย ควรเชื่อมกับหัวข้อใด?

เชื่อมกับ process management, concurrency และ synchronisation ใน CLO 3 ก่อน เพราะการติดตายเกิดในบริบทหลายงานและการใช้ทรัพยากรร่วมกัน ต้นฉบับจับ Objective 6–8 ไว้ด้วยกัน การจำว่า deadlock แปลว่าติดตายยังไม่พอ ผลลัพธ์ที่ต้องได้คือวิเคราะห์ว่าใครรออะไรและเหตุใดจึงไปต่อไม่ได้

5. [อธิบายเสริม] การจัดการหน่วยความจำกับระบบแฟ้มอยู่ตรงไหนในผลลัพธ์วิชา?

Objective 9 คือเข้าใจ memory management และ Objective 10 คืออธิบาย file systems ทั้งสองรวมเป็น CLO 4 หรือกลุ่มการจัดพื้นที่และข้อมูลของ OS คำอธิบายรายวิชายังระบุ segmentation, paging, virtual memory, protection, sharing และ access control เป็นขอบเขตที่เกี่ยวข้อง จึงไม่ควรลดความหมายของกลุ่มนี้เหลือเพียงจำชื่อ RAM หรือ SSD

6. [อธิบายเสริม] ข้อมูลหน้า 2 และหน้า 9 ใช้ตัดสินอะไรได้ และมีขอบเขตอย่างไร?

หน้า 2 บอกแหล่งเอกสาร เวลาปรึกษา และองค์ประกอบคะแนนที่รวม 50 ส่วนหน้า 9 แสดงแปดหัวข้อ ครั้งละสองชั่วโมง พร้อมวัน เวลา และห้องของสอง section ใช้เข้าใจโครงสร้างการเรียนในฉบับนี้ได้ แต่ไม่ใช้ยืนยันว่าประกาศปัจจุบันไม่เคยเปลี่ยน และไม่ใช้คะแนนเต็ม 50 ในหน้าเดียวสรุปคะแนนทั้งวิชา
