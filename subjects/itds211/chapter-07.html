1 · ภาพรวมบทนี้

บทนี้ตอบว่าข้อมูลอยู่รอดหลังเลิกทำงานได้อย่างไร และทำไมการอ่านข้อมูลจึงช้าหรือเร็วต่างกันตามสื่อ

ต่อจากCA04เรื่องลำดับชั้นหน่วยความจำและCA05เรื่องรับส่งข้อมูล เราจะลงไปดูจานแม่เหล็ก การกระจายข้อมูลหลายดิสก์ และวงจรflash

จากนั้นเปรียบเทียบแผ่นอ่านด้วยแสงกับเทป พร้อมอ่านตารางจริงและอธิบายข้อแลกเปลี่ยนเรื่องความจุ เวลา ความทนเสีย และต้นทุน

ตัวเลขผลิตภัณฑ์และราคาในตารางเป็นข้อมูลของสไลด์ต้นฉบับ ใช้ฝึกหลักคิดและอ่านหน่วย ไม่ใช้เป็นข้อแนะนำซื้ออุปกรณ์ปัจจุบัน

3.1 · Storage Systems (ระบบเก็บข้อมูลระยะยาว)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

Storage (ที่เก็บข้อมูลระยะยาว) คือส่วนที่เก็บโปรแกรมและข้อมูลไว้ให้กลับมาใช้ภายหลัง ส่วน External Memory (หน่วยความจำภายนอก) ในชื่อบทหมายถึงระดับเก็บข้อมูลถัดจากหน่วยความจำหลัก ไม่ได้หมายความว่าต้องเสียบไว้นอกตัวเครื่องเสมอ บทนี้ต่อจาก CA04 เรื่องลำดับชั้นหน่วยความจำและ CA05 เรื่องการส่งข้อมูลกับอุปกรณ์

หน้า 2 วาง storage ไว้ระหว่างระบบรับส่งข้อมูลกับหน่วยประมวลผลในแผนวิชา หน้า 3 ให้หัวข้อ Magnetic Disk, RAID, SSD, Practical Issues และ Optical Memory; เนื้อหาจริงยังมี Magnetic Tape ช่วงท้ายด้วย จึงต้องเรียนส่วนเทปด้วยแม้สารบัญย่อไม่แสดงชื่อ

[อธิบายเสริม] ถ้า RAM เปรียบเหมือนพื้นที่เปิดเอกสารที่กำลังทำงาน Storage เหมือนชั้นเก็บแฟ้มที่ปิดร้านแล้วข้อมูลยังอยู่ ความจุ ความเร็ว ความทนทาน และต้นทุนจึงเป็นข้อแลกเปลี่ยน ไม่ใช่เลือกดูตัวเลขความจุอย่างเดียว

3.2 · Magnetic Disk (จานเก็บข้อมูลด้วยแม่เหล็ก)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

Magnetic Disk (ดิสก์แม่เหล็ก) เป็นจานกลมที่ทำจากฐานไม่เป็นแม่เหล็ก แล้วเคลือบวัสดุที่ทำให้เกิดสภาพแม่เหล็กเพื่อบันทึกข้อมูลได้ Substrate (วัสดุฐาน) คือเนื้อจานที่รองรับชั้นแม่เหล็ก เดิมใช้ aluminium หรือ aluminium alloy; สไลด์กล่าวถึงการใช้ glass substrate ด้วย

ประโยชน์ของฐานแก้วตามสไลด์ครบ 5 ด้าน: ผิวฟิล์มแม่เหล็กสม่ำเสมอขึ้นเพื่อเพิ่มความเชื่อถือได้; ลดตำหนิผิวและข้อผิดพลาดอ่านเขียน; รองรับหัวอ่านที่ลอยต่ำลง; แข็งขึ้นเพื่อลดการสั่น/การเปลี่ยนรูปของจาน; ทนแรงกระแทกและความเสียหายได้ดีขึ้น รูปโรงงานเล็กด้านล่างเป็นบริบทการผลิตจาน ไม่ใช่ผังเส้นทางข้อมูล

[อธิบายเสริม] เปรียบเหมือนการเขียนตัวอักษรเล็กบนกระดาษเรียบกับกระดาษเป็นคลื่น พื้นผิวเรียบช่วยให้วางข้อมูลถี่และอ่านได้แม่น แต่ในดิสก์จริงเราใช้สภาพแม่เหล็กแทนหมึก

3.3 · Read/Write Process (การอ่านและเขียนจานแม่เหล็ก)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

หน้า 5 แสดงสองทาง: Write (เขียน) รับกระแสไฟเข้าหัว → ทำให้เกิดสนามแม่เหล็ก → จัดสภาพแม่เหล็กบนผิวจาน; Read (อ่าน) ตรวจสภาพแม่เหล็กบนจาน → ได้สัญญาณไฟฟ้า → แปลกลับเป็นข้อมูล 0 และ 1 จึงเป็นการแปลงระหว่างข้อมูลไฟฟ้ากับสภาพแม่เหล็ก ไม่ใช่การเจาะรูลงจาน

ภาพ Figure 6.1 หน้า 6 แยก Inductive write element (ส่วนเขียนโดยสร้างสนามแม่เหล็ก) กับ Magnetoresistive: MR sensor (เซนเซอร์อ่านสภาพแม่เหล็ก) ลูกศร write current เข้าส่วนเขียน ส่วน read current อยู่ตรงส่วนอ่าน; Shield (ส่วนบังสนาม) ช่วยแยกบริเวณตรวจอ่าน; Track width (ความกว้างทางบันทึก) บอกแนวข้อมูลที่หัวอ่านครอบคลุม กล่อง N/S ใต้หัวคือรูปแทนบริเวณแม่เหล็กบน Recording medium (ผิวบันทึก)

  1. หัวถูกจัดให้อยู่เหนือแนวข้อมูลที่ต้องการ
  2. เมื่อเขียน วงจรสั่งกระแสให้ส่วนเขียนสร้างรูปแบบแม่เหล็กบนผิวที่เคลื่อนผ่าน
  3. เมื่ออ่าน ส่วนอ่านตรวจรูปแบบที่ผ่านใต้หัวและส่งสัญญาณให้วงจรถอดเป็นบิต

[อธิบายเสริม] เปรียบเป็นตราประทับที่สร้างร่องรอยกับคนอ่านร่องรอยนั้น: สองหน้าที่ใช้คนละกลไก จึงไม่ควรเอาลูกศรของส่วนเขียนไปอธิบายว่าเป็นส่วนอ่านทั้งหมด

3.4 · Disk Data Layout (ตำแหน่งข้อมูลบนผิวและหลายชั้นจาน)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

Platter (จาน) คือแผ่นที่หมุน; Track (แทร็ก) คือแนววงกลมร่วมศูนย์บนผิว; Sector (เซกเตอร์) คือส่วนย่อยตามแนวแทร็ก; Cylinder (กระบอกแทร็ก) คือกลุ่มแทร็กที่รัศมีเดียวกันบนหลายผิวจาน ตัวเลข S1…SN ในภาพบนแสดงส่วนของวงที่หัวอ่านจะพบเมื่อจานหมุน ไม่ใช่รีจิสเตอร์ของ CPU

Figure 6.2 ด้านล่างแสดง Spindle (แกนหมุน) ผ่านกลางจานหลายชั้น มี Read-write head หนึ่งหัวต่อผิว และแขน Boom ที่เลื่อนเข้าออก ลูกศร rotation คือจานหมุน ส่วนลูกศร arm motion คือแขนเปลี่ยนรัศมี เส้นแนวตั้งที่ผ่านหลายจานแสดง cylinder: เลื่อนแขนมารัศมีเดียวแล้วเลือกผิวด้วยหัวที่เหมาะสมได้

Inter-track gap (ช่องว่างระหว่างแทร็ก) และ Inter-sector gap (ช่องว่างระหว่างเซกเตอร์) เป็นพื้นที่แยกหน่วยข้อมูล ไม่ใช่ข้อมูลผู้ใช้ทั้งหมด การหาข้อมูลต้องระบุทั้งผิว/แทร็กและตำแหน่งตามการหมุน

[อธิบายเสริม] นึกถึงอาคารที่แต่ละชั้นมีทางเดินวงกลม: ชั้นคือผิวจาน วงคือ track ห้องบนวงคือ sector และห้องตำแหน่งเดียวกันทุกชั้นช่วยให้นึกถึง cylinder

3.5 · CAV and Multiple-zone Recording (การแบ่งพื้นที่จาน)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

Constant Angular Velocity: CAV (ความเร็วเชิงมุมคงที่) ในภาพซ้ายใช้จำนวนเซกเตอร์เท่ากันทุกแทร็ก ทำให้วงนอกที่ยาวกว่าใช้พื้นที่ไม่คุ้ม ส่วน Multiple-zone Recording (แบ่งแทร็กเป็นหลายโซน) ในภาพขวาเพิ่มจำนวนเซกเตอร์ในโซนด้านนอก รูปสีเขียว/เทาแยกกลุ่มโซน แต่ภายในโซนเดียวใช้รูปแบบเดียวกัน

ประเด็นในตารางแทรกหน้า 8CAV แบบในภาพMulti-zone แบบในภาพ
เซกเตอร์ต่อแทร็กเท่ากันทุกแทร็กมากขึ้นเมื่อออกด้านนอก
ความหนาแน่นข้อมูลไม่สม่ำเสมอ วงในแน่นกว่าใกล้เคียงกันทุกโซน
ความจุรวมต่ำกว่าสูงกว่า ใช้พื้นที่คุ้มกว่า
ความซับซ้อนง่ายกว่าต้องจัดการหลาย data rate
การใช้งานตามหมายเหตุในสไลด์พบน้อยใช้ในฮาร์ดดิสก์ส่วนใหญ่

[อธิบายเสริม] เหมือนวางที่นั่งรอบวง: วงนอกมีเส้นรอบวงยาวกว่า ถ้าบังคับจำนวนที่นั่งเท่าวงในก็เหลือที่ว่าง การเพิ่มที่นั่งตามโซนใช้พื้นที่คุ้มขึ้น คำว่า CAV เพียงอย่างเดียวบอกการหมุน ไม่ควรสรุปว่าดิสก์ที่ใช้หลายโซนต้องหมุนแบบความเร็วไม่คงที่เสมอ ตารางกำลังเทียบวิธีจัดเซกเตอร์สองรูป

RAID: Redundant Array of Independent Disks (ชุดดิสก์หลายลูกที่จัดทำงานร่วมกัน) ทำให้ OS เห็นดิสก์จริงหลายตัวเป็น Logical drive (ไดรฟ์ตรรกะหนึ่งชุด) สไลด์ระบุระดับ 0–6: ตัวเลขคือรูปแบบการออกแบบ ไม่ใช่ลำดับชั้นว่าทุกระดับสูงกว่าต้องเร็วกว่าและดีกว่าเสมอ

Striping (แบ่งข้อมูลเป็นชิ้นกระจายหลายดิสก์) ช่วยแบ่งงาน; Mirroring (เขียนสำเนาเหมือนกัน) เก็บข้อมูลซ้ำ; Parity (ค่าตรวจที่คำนวณจากข้อมูลหลายส่วน) ใช้ร่วมกับข้อมูลที่เหลือเพื่อสร้างส่วนที่หายเมื่อดิสก์เสีย สไลด์เขียนลักษณะร่วมเรื่อง parity แต่ RAID0 ไม่มี redundancy และ RAID1 ใช้สำเนา จึงต้องอ่านเป็นภาพรวมแล้วแยกตามระดับในตาราง

3.12 · RAID0 vs RAID1 (เลือกความเร็วและสำเนา)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

RAID0 ต้องมีทั้งเส้นทางจาก host memory ถึงดิสก์ที่ส่งข้อมูลได้เร็วพอ และโปรแกรมต้องออกคำขอที่ใช้ array ได้คุ้ม จึงจะเห็น high transfer capacity ถ้าคำขอเล็ก เวลาหลักอาจเป็น seek/rotation ไม่ใช่เวลาถ่ายข้อมูล การกระจายคำขอข้ามหลายลูกช่วยบาลานซ์งานและลดเวลาคิว โดยเฉพาะ strip ใหญ่ที่ทำให้คำขออิสระอยู่คนละลูก ข้อเสียหลักคือไม่มี redundancy ลูกเดียวเสียทำให้ข้อมูลชุดใช้งานไม่ได้ครบ

RAID1 ทำสำเนาข้อมูลทั้งหมด ทุก logical strip จับคู่กับดิสก์จริงสองตัว จึงอ่านจากลูกใดในคู่ก็ได้ มีได้ทั้งแบบร่วม striping และไม่มี striping เมื่อเสียอ่านสำเนาได้ต่อ และตอนเปลี่ยนลูกคัดลอกจากคู่ที่ยังดี ไม่ต้องสร้างทุกบล็อกจากสมการ parity เหมาะกับงานอ่านจำนวนมาก แต่เสียความจุ/ต้นทุนไปกับสำเนา

สไลด์บอก RAID1 “no write penalty” หมายถึงไม่มีภาระ read-modify-write ของ parity แบบ RAID4/5 ไม่ได้หมายความว่าเขียนเพียงสำเนาเดียวหรือไม่มีงานเพิ่ม: ต้องเขียนข้อมูลทั้งสองลูกเพื่อให้เหมือนกัน

[อธิบายเสริม] RAID0 เหมือนแบ่งอ่านหนังสือคนละบทเพื่อเร็วขึ้น แต่ถ้าคนหนึ่งหาย บทนั้นหาย ส่วน RAID1 เหมือนมีหนังสืออีกเล่มสำรอง อ่านจากใครก็ได้แต่ต้องซื้อสองเล่ม

[อธิบายเสริม] ระวังขอบเขตชื่อ: หน้า22เรียกการ striping ที่แต่ละแถบมีคู่สำเนาว่า RAID1 ด้วย แต่ภาพแทรกหน้า19เรียก mirror เป็นคู่แล้ว stripe ข้ามคู่ว่า RAID10 จึงคงคำอธิบายเดิมของสไลด์ไว้และระบุ layout ให้ชัดในโจทย์เสริม ห้องทดลองใช้ RAID1 อีกแบบหนึ่ง คือข้อมูลชุดเดียวทำสำเนาเหมือนกันทั้ง4ลูก

3.13 · RAID2 and RAID3 (ทำงานพร้อมกันในระดับข้อมูลเล็ก)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

Parallel access array (ชุดที่ทุกลูกเข้าร่วมคำขอเดียวกัน) ใน RAID2 ให้จานหมุนประสานตำแหน่งกัน แบ่ง strip เล็กมากระดับ byte/word แล้วคำนวณ Error-Correcting Code: ECC (รหัสตรวจและแก้ความผิดพลาด) ของบิตตำแหน่งเดียวกันข้ามลูก เก็บบิตรหัสบนดิสก์ตรวจหลายลูก โดยทั่วไปใช้ Hamming code จำนวนดิสก์รหัสเติบโตตาม log ของจำนวนดิสก์ข้อมูล สไลด์ให้บริบทว่าซับซ้อนและเหมาะเฉพาะเมื่อเกิดข้อผิดพลาดมาก ไม่ใช่ตัวเลือกทั่วไป

RAID3 ใช้ parity หนึ่งลูก ไม่ว่าจะมีดิสก์ข้อมูลกี่ลูก แบ่งข้อมูลชิ้นเล็กและให้ลูกต่าง ๆ ทำคำขอเดียวร่วมกัน เมื่อหนึ่งลูกเสีย คำนวณส่วนที่หายจาก parity กับส่วนอื่นแล้วให้บริการต่อใน Reduced mode (โหมดทำงานลดสมรรถนะขณะมีลูกเสีย) จากนั้นต้องเปลี่ยนลูกและสร้างข้อมูลทั้งหมดของลูกนั้นคืนก่อนกลับสภาพเต็ม

ถ่ายข้อมูลยาวต่อเนื่องได้เร็ว แต่ Transaction-oriented workload (งานคำขอสั้นหลายรายการ) เสียประโยชน์ เพราะทุกลูกผูกอยู่กับคำขอเดียว สไลด์ภาษาอังกฤษ Figure/Table เรียก bit-interleaved ส่วนหมายเหตุไทยหน้า24เรียก byte-level: ประเด็นร่วมคือกระจายหน่วยเล็กและใช้ parity เฉพาะลูก ไม่ใช่ block ใหญ่แบบ RAID4

[อธิบายเสริม] เหมือนหลายคนช่วยกันยกตู้เดียว: ยกตู้ใหญ่ได้ดี แต่รับลูกค้าคนละชิ้นพร้อมกันไม่ได้เท่าระบบที่แต่ละคนทำงานแยกกัน

3.14 · RAID4/5/6 (บล็อกใหญ่และตำแหน่ง parity)

สิ่งนี้มีไว้แก้ปัญหาอะไร / ทำไมต้องมี

Independent access (การเข้าถึงแยกลูกอย่างอิสระ) ของ RAID4 แบ่ง block ใหญ่พอให้แต่ละลูกบริการคำขอคนละงานได้ แต่ parity อยู่ดิสก์เดียว จึงเกิดคอขวดเมื่อคำขอเขียนหลายงานต้องมาปรับ parity ลูกนั้น

การเขียนข้อมูลเล็กแบบ Read-modify-write (อ่านเก่าเพื่อคำนวณแล้วเขียนใหม่) ตามหน้า25 มี 4 งานดิสก์: อ่านข้อมูลเดิม → อ่าน parity เดิม → เขียนข้อมูลใหม่ → เขียน parity ใหม่ สไลด์จึงเรียก two reads + two writes หรือ Write penalty (ภาระงานเพิ่มของการเขียน)

RAID5 คล้าย4แต่กระจาย parity strips ข้ามทุกลูก โดยมักหมุนเวียนแบบ round-robin จึงลดคอขวด parity ลูกเดียว แต่ยังมีงานคำนวณ/เขียน parity ส่วน RAID6 ใช้ parity อิสระสองชุดไว้คนละลูกในแต่ละแถว รองรับเสียพร้อมกันได้สองลูกและมี write penalty มากกว่า5 ข้อความว่าต้องเสียสามลูกภายในช่วงซ่อมจึงสูญข้อมูลเป็นการอธิบายกรณีล้มเหลวของดิสก์ภายใต้สมมติฐานแบบจำลอง ไม่ใช่รับประกันความปลอดภัยจากทุกสาเหตุ

[อธิบายเสริม] RAID4 เหมือนทุกโต๊ะต้องผ่านคนตรวจคนเดียว RAID5 ผลัดคนตรวจตามแถวงาน ส่วน RAID6 มีหลักฐานตรวจสองแบบ: ปลอดภัยขึ้นจากลูกเสีย แต่ต้องทำงานตรวจเพิ่ม

3.17 · SSD Architecture (จากคำขอไฟล์ถึงเซลล์ flash)

Figure6.8 แสดง Host system ด้านบน: Operating system software → File system software → I/O driver software → Interface เชื่อมลง SSD ด้านล่าง ใน SSD มี Interface → Controller → Addressing; แตกแขนง Data buffer/cache และ Error correction ก่อนเข้าชุด Flash memory components หลายก้อน

Controller (ตัวควบคุม) รับคำขอและจัดการการทำงาน; Addressing (การระบุตำแหน่ง) เลือกว่าข้อมูลอยู่ส่วนใด; Data buffer/cache (ที่พักข้อมูลชั่วคราว) พักข้อมูลระหว่างการจัดการ; Error correction (การตรวจแก้ข้อมูลผิด) ดูแลความถูกต้อง; ส่วน Flash memory components คือสื่อที่เก็บข้อมูลจริง ลูกศรสองทิศตรง interface หมายถึงรับคำสั่ง/ข้อมูลและคืนข้อมูล/สถานะได้

  1. โปรแกรมทำงานผ่าน OS และระบบไฟล์
  2. ไดรเวอร์ส่งคำขอผ่าน interface ของ host
  3. SSD controller ระบุตำแหน่ง ใช้ buffer และวงจรตรวจแก้ตามที่ต้องใช้
  4. อ่าน/เขียนกับ flash หลายส่วนแล้วคืนผลขึ้นทางเดิม

[อธิบายเสริม] เปรียบร้านส่งของ: ระบบไฟล์คือสารบัญพัสดุ driver/interfaceคือช่องสั่งงาน controllerคือผู้จัดการ bufferคือโต๊ะพัก และ flashคือชั้นเก็บจริง บางส่วนจัดการการเดินทาง ไม่ใช่เก็บข้อมูลถาวรทั้งหมด

3.18 · Practical Issues (ทำไม flash ต้องลบก่อนเขียนและสึกได้)

หน้า32ระบุปัญหาเฉพาะ SSD สองกลุ่ม: ประสิทธิภาพอาจลดเมื่อใช้งานไป และ flash ใช้ไม่ได้หลังผ่านการเขียนจำนวนหนึ่ง Flash block (กลุ่มเซลล์ที่ลบเป็นหน่วย) จึงเกี่ยวกับทั้งเวลาและอายุใช้งาน

  1. ตามคำอธิบายสไลด์ เมื่อต้องเปลี่ยนข้อมูลใน block ให้อ่านข้อมูล block ไปพักใน RAM buffer
  2. ลบ block เดิมของ flash ก่อนเขียนกลับ
  3. นำข้อมูลทั้ง block จาก buffer กลับไปเขียน

Wear leveling (กระจายการสึกจากการเขียน) คือจัดให้รอบเขียนกระจายข้ามเซลล์ แทนย้ำกลุ่มเดิม ส่วน Bad-block management (จัดการบล็อกที่ใช้งานไม่ได้) คือหลีกเลี่ยง/แทนที่พื้นที่เสีย เทคนิคตามสไลด์ยังมี cache หน้าระบบเพื่อชะลอและรวมการเขียน และประเมินอายุคงเหลือเพื่อเตรียมรับการเสีย

[อธิบายเสริม] เปรียบยางลบที่ลบได้ทีละบริเวณใหญ่ แม้เปลี่ยนตัวหนังสือเล็กนิดเดียวก็มีงานย้าย/เก็บส่วนอื่นก่อน และถ้าลบจุดเดิมซ้ำจะสึกก่อนส่วนอื่น การกระจายตำแหน่งช่วยใช้พื้นที่ให้สมดุล คำอธิบายอ่าน–ลบ–เขียนในสไลด์เป็นภาพระดับแนวคิด ไม่ได้บอกว่าทุกคำสั่ง host เขียนต้องลบ physical block เดิมตรงนั้นทันที

4. [อธิบายเสริม] ดิสก์4ลูก ลูกละ2TB ใช้ RAID0/1/5/6/10 จุเท่าไร โดย RAID1 ให้แยกแบบคู่ใน Table6.3 กับแบบข้อมูลชุดเดียวทำสำเนาทั้ง4ลูก
