1 · ภาพรวมบทนี้

เริ่มจากแยกสิ่งที่โปรแกรมมองเห็นออกจากวิธีที่ฮาร์ดแวร์ทำให้เกิดขึ้นจริง แล้วเชื่อมโปรแกรม ภาษา คอมไพเลอร์ ระบบปฏิบัติการ และชิ้นส่วนเครื่องเข้าด้วยกัน

อ่านภาพ CPU แคช คอร์ เธรด เมนบอร์ด ได และไมโครคอนโทรลเลอร์เป็นความสัมพันธ์ของหน้าที่ ไม่ใช่รายการชื่อที่ต้องท่อง

สำรวจคลาวด์ ระบบฝังตัว RISC/CISC รูปแบบความขนาน และรูปแบบระบบระดับสูงตามลำดับในต้นฉบับ

วัดความเร็วด้วยเวลา: Performance = 1 / Execution Time และ CPU Time = Instruction Count × CPI / Clock Rate พร้อมคำนวณโจทย์ต้นฉบับทุกขั้น

แยกข้อสมมติและจุดคลาดเคลื่อนของสไลด์ให้ชัด โดยเฉพาะตาราง IaaS ตัวอย่าง C กับ RISC-V คำอธิบาย SMT และความหมายของ 16/32 บิตใน Cortex-M3

2 · พื้นฐานที่ต้องรู้ก่อน

[อธิบายเสริม] บทที่ช่วยปูพื้นฐาน: CA00

[อธิบายเสริม] Bit (บิต) คือค่าหนึ่งตำแหน่งที่เป็น 0 หรือ 1; Byte (ไบต์) เท่ากับ 8 บิต Instruction (คำสั่งเครื่อง) บอกการกระทำหนึ่งอย่างที่ CPU รองรับ Data (ข้อมูล) คือค่าที่คำสั่งนำไปใช้ เช่น จำนวนที่จะบวก Address (ที่อยู่) คือเลขตำแหน่งสำหรับหาเนื้อหาในหน่วยความจำ จึงไม่ใช่ตัวเนื้อหานั้นเอง

[อธิบายเสริม] Register (รีจิสเตอร์) คือที่เก็บค่าขนาดเล็กภายใน CPU; RAM (หน่วยความจำหลักที่ใช้งาน) เก็บข้อมูลและคำสั่งของงานที่กำลังรัน; Storage (ที่เก็บข้อมูลระยะยาว) เช่น SSD เก็บข้อมูลแม้ปิดงานแล้ว GHz แปลว่าพันล้านรอบต่อวินาที: 1 GHz = 109 Hz ส่วน 1 ns = 10−9 วินาที และ 1 ps = 10−12 วินาที เครื่องหมาย × คือคูณ และ ÷ คือหาร

3.1 · Lecture Route (บทนี้อยู่ตรงไหนของวิชา)

ก่อนคำนวณว่าเครื่องเร็วเพียงใด เราต้องรู้จักส่วนใดและระดับการอธิบายใดก่อน?

หน้าปกระบุบท I: Basic Computer Components & Introduction to Computer Architecture ส่วน outline หน้า 2 เน้นสองหัวข้อแรกคือโครงสร้าง/สถาปัตยกรรมและองค์ประกอบพื้นฐาน หัวข้อที่เหลือ ได้แก่ การแทนข้อมูล ภาษาแอสเซมบลี การจัดหน่วยความจำ ลำดับชั้น/แคช I/O ที่เก็บข้อมูล หน่วยคำนวณ และหลายหน่วยประมวลผล เป็นเส้นทางที่จะต่อยอดจากบทนี้

[อธิบายเสริม] ใช้คำถามสามชั้นตลอดบท: โปรแกรมสั่งอะไรได้ → ส่วนใดของเครื่องรับผิดชอบ → จะพิสูจน์ด้วยตัวเลขได้อย่างไรว่าการออกแบบนั้นช่วยงาน การแยกชั้นนี้ทำให้อ่านทั้งภาพอุปกรณ์และสมการท้ายบทได้ต่อเนื่องกัน

3.2 · Architecture and Organization (ข้อกำหนดกับวิธีทำให้เกิดขึ้นจริง)

เครื่องสองเครื่องทำคำสั่งเดียวกันได้ แต่ทำไมภายในต่างกันและเร็วไม่เท่ากัน?

Architecture (สถาปัตยกรรมคอมพิวเตอร์) ตามหน้า 3 คือคุณสมบัติที่โปรแกรมเมอร์มองเห็นและมีผลโดยตรงต่อความหมายของการทำงาน เช่น Instruction Set (ชุดคำสั่ง), Addressing Modes (วิธีระบุแหล่งข้อมูล) และ Data Types (ชนิดข้อมูล) เป็นคำถามว่าเครื่องทำ อะไรได้ ส่วน Organization (การจัดระบบคอมพิวเตอร์) คือหน่วยปฏิบัติการและการเชื่อมต่อที่ทำให้ข้อกำหนดนั้นเกิดขึ้นจริง เช่น cache, pipeline, ความกว้างบัส และความถี่ เป็นคำถามว่าเครื่องทำสิ่งนั้น อย่างไร

การตัดสินใจด้าน ISA ในหน้า 4ความหมายสำหรับผู้เริ่มต้น
Registersโปรแกรมมีที่เก็บค่าภายใน CPU ให้ใช้อะไรบ้าง
Memory addressing / Addressing modesอ้างตำแหน่งหน่วยความจำและหา operand อย่างไร
Instruction operandsคำสั่งใช้ข้อมูลกี่ค่าและอยู่ในรูปใด
Available operationsมีการกระทำพื้นฐานใด เช่น คำนวณหรือย้ายข้อมูล
Control flow instructionsเปลี่ยนลำดับไปทำคำสั่งใดต่อได้อย่างไร
Instruction encodingเข้ารหัสคำสั่งเป็นบิตแบบใด

ISA: Instruction Set Architecture (สถาปัตยกรรมชุดคำสั่ง) จึงเป็นข้อตกลงระหว่างโปรแกรมกับเครื่อง แต่หน้า 4 ขยายว่า computer architecture ในงานออกแบบจริงกว้างกว่า ISA: ต้องเริ่มจากความต้องการเครื่องเป้าหมาย แล้วเลือก Microarchitecture (โครงสร้างภายในที่ใช้ทำคำสั่ง) และฮาร์ดแวร์เพื่อเพิ่มประสิทธิภาพภายใต้ Cost (ต้นทุน), Power (พลังงาน/กำลังไฟ) และ Availability (ความพร้อมใช้งาน)

[อธิบายเสริม] อุปมา: เมนูบอกว่าร้านทำอาหารอะไรได้คล้าย ISA ส่วนจำนวนเตาและวิธีจัดครัวคล้าย organization ร้านสองร้านทำเมนูเดียวกันได้แต่ใช้เวลาต่างกัน เช่นเดียวกับ CPU ที่เข้ากันได้ด้านคำสั่งแต่มีแคชหรือ pipeline ต่างกัน อุปมาไม่ได้บอกว่าระดับการออกแบบทุกระดับแยกขาดกัน

3.3 · Computer Classes and Cloud (เครื่องต่างเป้าหมายและทรัพยากรผ่านเครือข่าย)

เหตุใดเครื่องคำนวณวิทยาศาสตร์กับชิปในอุปกรณ์จึงควรออกแบบต่างกัน และคลาวด์ให้เราใช้เครื่องอย่างไร?

Supercomputer (ซูเปอร์คอมพิวเตอร์) เน้นงานคำนวณวิทยาศาสตร์และวิศวกรรมขนาดใหญ่ มีความสามารถสูงแต่เป็นสัดส่วนเล็กของตลาดเครื่องทั้งหมด ส่วน Embedded Computer (คอมพิวเตอร์ฝังตัว) ซ่อนเป็นส่วนหนึ่งของระบบอื่น และมีข้อจำกัดเข้มงวดเรื่องพลังงาน ประสิทธิภาพ และต้นทุน จึงไม่มีแบบเดียวที่เหมาะกับทุกงาน

Cloud Computing (การประมวลผลแบบคลาวด์) ตามหน้า 6 คือรูปแบบให้เข้าถึงทรัพยากรคำนวณที่ปรับตั้งได้และใช้เป็นแหล่งร่วม ผ่านเครือข่ายอย่างสะดวกและตามต้องการ On demand (ตามต้องการ) หมายถึงร้องขอใช้เมื่อจำเป็น; Shared pool (แหล่งทรัพยากรร่วม) หมายถึงผู้ให้บริการจัดสรรทรัพยากรจากแหล่งเดียวให้ผู้ใช้หลายราย

Cloud Networking (เครือข่ายสำหรับคลาวด์) คือเครือข่ายและการจัดการที่ทำให้เข้าถึงทรัพยากรนั้นได้ ส่วน Cloud Storage (ที่เก็บข้อมูลบนคลาวด์) คือพื้นที่เก็บข้อมูลระยะไกลบนระบบคลาวด์ หน้า 6 ยกฐานข้อมูลและแอปพลิเคชันฐานข้อมูลเป็นคำอธิบายของ storage แต่ [อธิบายเสริม] ไม่ควรจำว่าคลาวด์เก็บได้เฉพาะฐานข้อมูลเท่านั้น

[อธิบายเสริม] หากรันโปรแกรมบนเครื่องที่ให้บริการระยะไกล CPU และหน่วยความจำยังเป็นฮาร์ดแวร์จริง เพียงมีเครือข่ายและซอฟต์แวร์จัดสรรอยู่ระหว่างผู้ใช้กับฮาร์ดแวร์ คลาวด์จึงไม่ใช่การคำนวณที่ไม่มีเครื่องอยู่เบื้องหลัง

3.4 · SaaS, PaaS, IaaS (ผู้ใช้กับผู้ให้บริการรับผิดชอบชั้นใด)

หากต้องการใช้งานซอฟต์แวร์กับต้องการควบคุมเครื่องเอง เราควรเข้าใจความต่างของบริการคลาวด์อย่างไร?

SaaS: Software as a Service (ซอฟต์แวร์เป็นบริการ) ให้ผู้ใช้ใช้งานแอปพลิเคชันที่รันบนคลาวด์ PaaS: Platform as a Service (แพลตฟอร์มเป็นบริการ) ให้สภาพแวดล้อมที่นำแอปพลิเคชันของเราไปทำงานได้ และ IaaS: Infrastructure as a Service (โครงสร้างพื้นฐานเป็นบริการ) ให้ทรัพยากรเช่นเครื่องเสมือนและฮาร์ดแวร์ที่ซอฟต์แวร์ซ่อนรายละเอียดไว้ หน้า 7 กล่าวถึงการควบคุมผ่าน API: Application Programming Interface (ช่องทางคำสั่งที่โปรแกรมใช้เรียกบริการ)

ภาพหน้า 8 เป็นกองชั้นจากเครือข่ายด้านล่างถึงแอปพลิเคชันด้านบน สีเทาแสดงส่วนลูกค้าดูแล สีเขียวแสดงส่วน CSP: Cloud Service Provider (ผู้ให้บริการคลาวด์) ดูแล ตารางต่อไปนี้เก็บการแบ่ง ตามภาพในสไลด์ เพื่อให้อ่านภาพเดิมได้ครบ

ลูกศรสองหัวใต้ภาพสื่อ trade-off (การได้อย่างหนึ่งแลกอีกอย่าง): ฝั่งทำเองซับซ้อนกว่า ลงทุนแรกมากกว่า ขยายยากกว่า แต่ปรับแต่งได้มากกว่า; เคลื่อนไปบริการที่จัดให้มากขึ้น ลดภาระและลงทุนแรก เพิ่มความสะดวกในการขยาย แต่ลดอิสระบางส่วน [อธิบายเสริม] ผลจริงขึ้นกับบริการและสัญญาที่เลือก ไม่ใช่คำรับประกันว่าคลาวด์ทุกแบบมีค่าใช้จ่ายรวมต่ำกว่าเสมอ

3.5 · Understanding Performance (เหตุใดความเร็วขึ้นกับทั้งเส้นทางโปรแกรม)

ถ้า CPU รุ่นเดิม โปรแกรมจะเร็วขึ้นได้อีกจากส่วนใดบ้าง?

Algorithm (ขั้นตอนวิธี) กำหนดจำนวนการกระทำเชิงงานที่ต้องทำ Programming Language, Compiler, Architecture (ภาษาโปรแกรม ตัวแปลภาษา และสถาปัตยกรรม) กำหนดว่าการกระทำหนึ่งต้องแปลงเป็นคำสั่งเครื่องกี่คำสั่ง Processor and Memory System (หน่วยประมวลผลและระบบหน่วยความจำ) กำหนดว่าทำคำสั่งเหล่านั้นเร็วเพียงใด และ I/O System including OS (ระบบรับเข้า/ส่งออกรวมระบบปฏิบัติการ) กำหนดความเร็วของงานติดต่ออุปกรณ์

[อธิบายเสริม] สมมติงานค้นหาข้อมูล: เปลี่ยนวิธีค้นหาอาจลดจำนวนครั้งที่ต้องตรวจข้อมูล คอมไพเลอร์อาจเลือกคำสั่งได้ต่างกัน แคชอาจลดเวลารอข้อมูล และการอ่านจากอุปกรณ์อาจเป็นเวลาส่วนใหญ่ จึงต้องถามก่อนว่างานเสียเวลาอยู่ที่ชั้นใด การเพิ่มความถี่ CPU อย่างเดียวไม่รับประกันว่าจะช่วยงานที่กำลังรอ I/O ได้มาก

หน้า 10 มีแนวคิดแปดข้อพร้อมรูปสัญลักษณ์เล็ก ๆ รูปเป็นตัวช่วยจำ ไม่ใช่วงจรจริง อ่านแต่ละข้อพร้อมปัญหาที่มันแก้ดังนี้

Design for Moore’s Law (ออกแบบเผื่อแนวโน้มจำนวนทรานซิสเตอร์)เผื่อความก้าวหน้าทางการรวมวงจรเมื่อออกแบบเครื่อง; รูปกราฟขึ้นสื่อแนวโน้มในอดีต ไม่ใช่รับประกันความเร็วเพิ่มคงที่ตลอดไป
Abstraction (การซ่อนรายละเอียด)แบ่งชั้นให้ใช้สิ่งซับซ้อนได้ผ่านข้อตกลงที่เข้าใจง่าย โดยไม่ต้องเห็นรายละเอียดทุกชิ้น
Make the common case fast (ทำกรณีที่เกิดบ่อยให้เร็ว)ทุ่มการปรับปรุงกับส่วนที่ถูกใช้บ่อย เพื่อให้ส่งผลต่อเวลารวมมาก
Parallelism (การทำหลายส่วนพร้อมกัน)ใช้ทรัพยากรหลายส่วนทำงานที่แบ่งกันได้ในเวลาเดียวกัน
Pipelining (การเหลื่อมขั้น)ให้หลายงานอยู่คนละขั้นพร้อมกัน รูปท่อสื่อการเคลื่อนงานเป็นช่วง ๆ
Prediction (การคาดการณ์)คาดสิ่งที่จะต้องใช้หรือทางที่จะไปแล้วเตรียมล่วงหน้า; รูปลูกแก้วสื่อการเดา ไม่ได้แปลว่าผลเดาถูกเสมอ
Hierarchy of memories (ลำดับชั้นหน่วยความจำ)ใช้ระดับเล็กเร็วใกล้ CPU ร่วมกับระดับใหญ่ช้ากว่า รูปพีระมิดสื่อหลายชั้น
Dependability via redundancy (ความเชื่อถือได้ด้วยส่วนซ้ำสำรอง)เพิ่มข้อมูลหรือส่วนประกอบซ้ำเพื่อช่วยตรวจหรือรับมือความผิดพลาด

[อธิบายเสริม] อุปมา pipeline: ระหว่างคนหนึ่งล้างจาน อีกคนเช็ด และอีกคนเก็บ ทำให้หลายจานอยู่คนละขั้นพร้อมกัน จำนวนจานที่เสร็จต่อช่วงเวลาเพิ่มได้ แต่จานหนึ่งยังต้องผ่านครบทุกขั้น จึงไม่ควรตีความว่าการทำ pipeline ทำให้ขั้นตอนของงานเดี่ยวหายไป

3.7 · Below Your Program (จากภาษาคนสู่คำสั่งที่ฮาร์ดแวร์ทำได้)

CPU อ่านโปรแกรมภาษาระดับสูงได้โดยตรงหรือมีใครแปลและให้บริการระหว่างทาง?

ภาพวงซ้อนหน้า 11 มี Hardware (ฮาร์ดแวร์) อยู่แกนกลาง ได้แก่ processor, memory และ I/O controllers; ชั้นถัดมาเป็น System Software (ซอฟต์แวร์ระบบ) และวงนอกเป็น Application Software (โปรแกรมประยุกต์) ที่มักเขียนด้วยภาษาระดับสูง วงซ้อนสื่อการพึ่งบริการของชั้นด้านใน ไม่ใช่ตำแหน่งทางกายภาพในเครื่อง

ซอฟต์แวร์ระบบที่ต้นฉบับยกคือ Compiler (คอมไพเลอร์/ตัวแปลภาษาระดับสูง) แปล HLL: High-Level Language ให้เป็นคำสั่งเครื่อง และ Operating System (ระบบปฏิบัติการ) ให้บริการ I/O จัดการหน่วยความจำและ storage จัดตารางงานและแบ่งทรัพยากร ทั้งสองเป็นคนละหน้าที่: แปลโค้ดกับดูแลงานที่ใช้เครื่อง

ภาพลูกศรหน้า 12 อ่านจากบนลงล่าง: High-level language (ภาษาระดับสูง ใกล้ปัญหาที่มนุษย์ต้องการแก้) → Compiler → Assembly language (ภาษาแอสเซมบลี ใช้ชื่อคำสั่ง) → Assembler (ตัวแปลแอสเซมบลีเป็นรหัส) → Binary machine language (ภาษาเครื่องเป็นบิต) ภาษาระดับสูงช่วย Productivity (เขียนงานได้สะดวก) และ Portability (ย้ายซอร์สไปแปลสำหรับเครื่องอื่นได้ง่ายขึ้น) แต่ฮาร์ดแวร์ทำตาม encoding ของคำสั่งและข้อมูลเป็น 0/1

ตัวอย่าง C ในภาพสลับ v[k] กับ v[k+1] โดยใช้ temp เก็บค่าตัวแรกก่อนเขียนทับ ส่วนแอสเซมบลี RISC-V ในภาพคือ:

swap:
  slli x6, x11, 3
  add  x6, x10, x6
  ld   x5, 0(x6)
  ld   x7, 8(x6)
  sd   x7, 0(x6)
  sd   x5, 8(x6)
  jalr x0, 0(x1)

[อธิบายเสริม] slli เลื่อนบิตซ้ายเพื่อคูณดัชนีด้วย 8; add รวม offset กับที่อยู่ฐาน; ld อ่านข้อมูล 8 ไบต์เข้า register; sd เขียนกลับ; jalr บรรทัดสุดท้ายกลับไปผู้เรียก ชุดบิตด้านล่างเป็นการเข้ารหัสคำสั่งชุดเดียวกัน ไม่ใช่ภาษาที่ CPU แปลเป็นภาษา C อีกที

[อธิบายเสริม: จุดที่ต้องระวังในต้นฉบับ] C ในภาพเขียน int แต่ assembly ใช้สมาชิกละ 8 ไบต์ ถ้า int ของระบบมี 4 ไบต์ สองส่วนนี้ไม่ใช่คู่แปลที่ตรงกัน ต้องใช้ชนิดข้อมูล 8 ไบต์ให้สอดคล้องกับ assembly หรือเปลี่ยนการเลื่อนเป็น 2 และคำสั่งอ่าน/เขียนเป็นขนาด 4 ไบต์ ไม่ควรเรียนว่าชนิด int มี 8 ไบต์เสมอ

3.8 · Computer Components and CPU (แบ่งหน้าที่ให้เครื่องทั้งระบบ)

รับข้อมูล คำนวณ เก็บข้อมูล และแสดงผล ใช้ชิ้นส่วนใดทำงานร่วมกัน?

ส่วนประกอบหน้า 13หน้าที่ที่ต้องเข้าใจ
Input Devices (อุปกรณ์รับเข้า)นำข้อมูลหรือคำสั่งเข้าระบบ
CPU: Central Processing Unit (หน่วยประมวลผลกลาง)ควบคุมและทำคำสั่งของโปรแกรม
Memory / RAM (หน่วยความจำหลัก)เก็บคำสั่งและข้อมูลระหว่างใช้งาน
Storage Devices (อุปกรณ์เก็บข้อมูล)เก็บข้อมูลระยะยาว
Motherboard (แผงวงจรหลัก)รองรับและเชื่อมองค์ประกอบต่าง ๆ
Output Devices (อุปกรณ์ส่งออก)ส่งผลจากระบบออกสู่ผู้ใช้หรือภายนอก
Power Supply Unit: PSU (ชุดจ่ายไฟ)จ่ายพลังงานไฟฟ้าให้ชิ้นส่วน
Graphics Processing Unit: GPU (หน่วยประมวลผลกราฟิก)ประมวลผลงานกราฟิกและงานที่เหมาะกับโครงสร้างขนานของมัน

ภาพหน้า 13 วาง processor และ memory ไว้ใน computer มี input วิ่งเข้าและ output วิ่งออก ภายใน processor แยก Control (การควบคุม) กับ Datapath (เส้นทางข้อมูลและการคำนวณ) ด้านบนมี compiler/interface และด้านข้างมีการประเมิน performance จึงเชื่อมระดับโปรแกรมกับองค์ประกอบเครื่อง

หน้า 14 ขยาย CPU เป็น Control Unit: CU (หน่วยควบคุม) กำหนดว่าตอนไหนส่วนใดต้องทำอะไร, Arithmetic and Logic Unit: ALU (หน่วยคำนวณและตรรกะ) ทำการคำนวณ/เปรียบเทียบ, Registers (รีจิสเตอร์) เก็บค่าภายใน CPU และ CPU Interconnection (การเชื่อมต่อภายใน CPU) ส่งข้อมูลและสัญญาณระหว่างสามส่วน ถ้าแยกเพียง ALU แต่ไม่มี register และการควบคุม ก็ยังทำลำดับโปรแกรมไม่ได้

[อธิบายเสริม] อุปมา: ALU คล้ายจุดลงมือคำนวณ register คล้ายกระดาษทดใกล้มือ CU คล้ายคนบอกขั้นถัดไป และเส้นทางเชื่อมต่อคล้ายทางส่งกระดาษ อุปมานี้ช่วยจำบทบาท ไม่ได้หมายความว่า CPU มีผู้สั่งเป็นคนอยู่ภายใน

3.9 · Machine Cycle and Registers (รู้ว่าจะทำอะไรต่อและเก็บสถานะไว้ที่ใด)

CPU จะทำโปรแกรมหลายคำสั่งต่อเนื่องได้อย่างไรโดยไม่ลืมตำแหน่งและผลก่อนหน้า?

Machine Cycle (วงรอบการทำคำสั่ง) ในภาพหน้า 15 แยกเป็น Fetch–Decode–Execute–Store อ่านลูกศรเป็นลำดับ: (1) Fetch (ดึงคำสั่ง) จาก memory (2) Decode (ถอดรหัส) ที่ control unit เพื่อรู้ว่าจะทำอะไร (3) Execute (ลงมือทำ) โดยใช้ ALU หรือส่วนที่เกี่ยวข้อง (4) Store (เก็บผล) กลับที่ที่กำหนด แล้ววนไปคำสั่งถัดไป ภาพเก็บผลลง memory เป็นภาพย่อ [อธิบายเสริม] ในเครื่องจริงบางคำสั่งเก็บใน register หรือเปลี่ยน control flow และไม่เขียน memory ทุกคำสั่ง

Program Counter: PC (ตัวนับตำแหน่งคำสั่ง) ถือที่อยู่คำสั่งที่จะดึงต่อไป Instruction Register: IR (รีจิสเตอร์คำสั่ง) ถือคำสั่งที่ดึงมาเพื่อถอดรหัส/ทำงาน ส่วน Status Register / Flags (รีจิสเตอร์สถานะ/ธง) เก็บเงื่อนไขจากการทำงาน เช่น ผลเป็นศูนย์หรือมีเหตุการณ์บางอย่าง เพื่อให้ระบบตัดสินใจต่อได้ [อธิบายเสริม] ธงที่มีจริงและความหมายขึ้นกับ ISA ไม่ควรถือว่าทุกเครื่องเหมือนกัน

ภาพหน้า 16 วาง accumulator ใน ALU, PC/IR ใน control unit, หน่วยความจำกลาง ROM/RAM, backing storage และ input/output unit เส้นทึบคือ Data Bus (ทางส่งข้อมูล) ส่วนเส้นประคือ Control Bus (ทางสัญญาณควบคุม) จึงต้องแยก “ค่าไหลไปที่ไหน” จาก “ใครสั่งให้ไหลเมื่อใด” ROM (หน่วยความจำที่เน้นอ่านข้อมูลคงอยู่) และ RAM ในภาพเป็นตัวอย่างชนิดหน่วยความจำ ไม่ใช่ register ภายใน CPU

[อธิบายเสริม] ถ้า PC ชี้คำสั่งบวกอยู่ CPU ดึงคำสั่งนั้นเข้า IR แล้ว CU สั่งให้ ALU บวกค่าจากที่กำหนด เก็บผลและสถานะ จากนั้นจึงดำเนินคำสั่งต่อ PC จึงเป็น “ตำแหน่ง” ส่วน IR เป็น “คำสั่ง” อย่าสลับกัน

3.10 · Cache Memory (ลดระยะรอข้อมูลด้วยชั้นเล็กที่อยู่ใกล้)

ถ้า CPU ต้องอ่านข้อมูลบ่อย ทำไมไม่ใช้หน่วยความจำหลักเพียงระดับเดียว?

Cache (แคช) คือหน่วยความจำขนาดเล็กและเร็วกว่า main memory วางระหว่าง core กับหน่วยความจำหลักเพื่อเก็บข้อมูลที่คาดว่าจะใช้อีกในอนาคตอันใกล้ CPU จึงมีโอกาสหาค่าได้ใกล้ตัวก่อนต้องรอระดับที่ไกลกว่า L1 (แคชระดับหนึ่ง) ใกล้ core ที่สุดและตามภาพรวมในสไลด์เล็ก/เร็วที่สุด ถัดไปคือ L2 และอาจมี L3 ซึ่งไกลออกไปและมักใหญ่ขึ้น

ภาพซ้ายหน้า 17 วาด CPU มี L1 อยู่ข้างใน L2 อยู่ใกล้ใน processor package แล้วเชื่อม memory ผ่านลูกศรสองทิศ ลูกศรสื่อการแลกเปลี่ยนข้อมูล ไม่ใช่ย้ายหน่วยความจำหลักทั้งก้อนเข้า CPU ภาพขวาแสดงสอง core แต่ละ core มี L1 data cache และใช้ Smart-Shared L2 Cache ตรงกลางร่วมกัน ผ่าน system bus ด้านบน จึงเห็นทั้งแคชส่วนตัวและแคชร่วม

หน้า 18 ย้ำว่าจัดได้หลายชั้น L1 ใกล้ core และ L2/L3 อยู่ห่างออกไปเพื่อประนีประนอมความเร็วกับความจุ [อธิบายเสริม] คำว่าเล็ก/เร็วเป็นแนวโน้มตามลำดับชั้น ไม่ใช่ค่าขนาดหรือจำนวนชั้นที่เหมือนกันทุกผลิตภัณฑ์ แคชไม่ใช่พื้นที่เก็บแฟ้มถาวร และไม่ได้ทำให้การอ่านข้อมูลทุกครั้งมีเวลาศูนย์

[อธิบายเสริม] อุปมา: เก็บเอกสารที่ใช้บ่อยบนโต๊ะ เก็บชุดใหญ่ในตู้ และชุดใหญ่มากในคลัง การมีเอกสารถูกชุดอยู่บนโต๊ะช่วยเวลา แต่พื้นที่โต๊ะมีจำกัด ต้องเลือกสิ่งที่น่าจะใช้ กลไกเลือกและแทนที่ข้อมูลจะเป็นบทหน่วยความจำโดยเฉพาะ

3.11 · Multicore and Multithreading (จำนวนหน่วยทำงานกับจำนวนสายงาน)

เห็นจำนวน thread มากกว่า core แปลว่ามี CPU จริงเพิ่มขึ้นเท่ากันหรือไม่?

Core (แกนประมวลผล) คือหน่วยประมวลผลทางกายภาพภายในชิป Multicore (หลายแกน) มีหลาย core จึงแบ่งงานที่ทำแยกกันได้ไปทำพร้อมกัน ส่วน Thread (เธรด/สายการทำงาน) คือสายลำดับคำสั่งหนึ่งสาย Multithreading (การรองรับหลายเธรด) เกี่ยวกับการจัดการมากกว่าหนึ่งสายงาน ไม่ได้เท่ากับเพิ่ม ALU และทรัพยากรทั้งหมดเป็น core ใหม่ทุกสาย

ภาพซ้ายหน้า 19 มี core 1–4 แต่ละ core ต่อ local memory แล้วใช้ shared memory และ bus interface ร่วมกัน ลูกศรไป off-chip components แสดงส่วนที่อยู่นอกชิป ภาพขวาแสดง scheduler ด้านบนแจกสายงานให้หลาย core ภายใน core มีบริบท thread มากกว่าหนึ่ง แต่ยังมี ALU/control และ cache ที่ใช้ร่วมกัน และมี L3 ระดับล่างร่วมกันอีกชั้น

หน้า 20 ใช้อุปมา core เป็นจำนวนเชฟ ส่วน thread เป็นจำนวนแขนที่เชฟใช้จัดการงาน อุปมาชี้ว่ามีหน่วยทำงานจริงเพิ่มกับใช้หน่วยเดิมให้คุ้มเป็นคนละเรื่อง [อธิบายเสริม] อุปมานี้ไม่แปลว่าเพิ่มสองเธรดแล้วเวลาทุกงานลดครึ่งหนึ่ง เพราะเธรดแข่งขันทรัพยากรและบางงานแบ่งไม่ได้

[อธิบายเสริม: ขยายข้อความต้นฉบับ] สไลด์เขียน multi-thread ว่า virtual และยก Intel Hyper-Threading กับ AMD SMT แต่ SMT: Simultaneous Multithreading (ให้หลายเธรดใช้ทรัพยากร core พร้อมกัน) ต้องมีฮาร์ดแวร์รองรับบริบทและการเลือกคำสั่ง จึงไม่ใช่เทคนิคซอฟต์แวร์ล้วนหรือ core ปลอมที่ไม่มีส่วนรองรับจริง และคำว่า thread ในระดับโปรแกรมกว้างกว่า hardware thread ที่แผนภาพนี้เน้น

3.12 · Motherboard, Chip, Core and Die (อ่านขนาดของระบบให้ถูกชั้น)

คำว่าเครื่องหนึ่ง ชิปหนึ่ง และคอร์หนึ่งต่างกันอย่างไรเมื่อเปิดดูของจริง?

ภาพขยายหน้า 21 เริ่มจาก Motherboard (เมนบอร์ด) ที่มี main-memory chips, I/O chip และ processor chip เส้นประขยายเข้า processor chip ซึ่งมีหลาย core กับ L3 cache แล้วขยาย core อีกครั้งให้เห็น instruction logic (ส่วนจัดการคำสั่ง), arithmetic/logic unit, load/store logic (ส่วนอ่าน/เขียนข้อมูล) และ L1/L2 instruction/data cache ภาพตัวอย่างแสดง core หลายตัวในชิปเดียว จึงไม่ควรนับ motherboard = CPU = core เป็นสิ่งเดียว

ภาพถ่ายหน้า 22 เป็นเมนบอร์ดที่มี Intel Xeon สองตัว ตัวละสี่ core พร้อม integrated memory controller (ตัวควบคุมหน่วยความจำใน processor) รวมตามชื่อรูปเป็น 2 × 4 = 8 core ป้ายในภาพระบุหน่วยความจำ Six-channel DDR3-1333 สูงสุด 48 GB, Intel 3420 chipset, Serial ATA/300, USB 2.0 ภายใน 2 พอร์ตและภายนอก 2 พอร์ต, VGA video output, BIOS, Ethernet 10/100/1000Base-T สองพอร์ตกับ Ethernet controller, clock และขั้ว Power/Backplane I/O กับ PCI Express A/B

[อธิบายเสริม] ป้ายเหล่านี้แบ่งหน้าที่ได้เป็นกลุ่ม: CPU ทำคำสั่ง, DDR3 เก็บข้อมูลใช้งาน, chipset และช่อง PCIe เชื่อมส่วนขยาย, SATA เชื่อมอุปกรณ์เก็บข้อมูล, USB/VGA/Ethernet เชื่อมภายนอก, BIOS เป็นเฟิร์มแวร์เริ่มระบบ และ power/clock สนับสนุนไฟกับจังหวะ ตัวเลขเป็นสเปกของตัวอย่างในรูป ไม่ใช่ข้อจำกัดของเมนบอร์ดทั้งหมด

ภาพหน้า 23 ระบุ Apple A5 และแสดง Die (เนื้อชิปซิลิคอนที่มีวงจรจริง) เป็นพื้นที่ย่อย มี Arm Core สองบริเวณ พร้อม processor data paths, digital logic blocks, DDR SDRAM interfaces, USB, GPIO, I/O, video DAC และ audio ป้ายแสดงว่าในชิปเดียวมีทั้งการคำนวณและการเชื่อมอุปกรณ์ GPIO: General-Purpose Input/Output (ขารับส่งสัญญาณทั่วไป) เชื่อมสัญญาณภายนอก และ DAC: Digital-to-Analog Converter (ตัวแปลงดิจิทัลเป็นแอนะล็อก) ใช้สร้างสัญญาณแอนะล็อก [อธิบายเสริม] อย่านับพื้นที่ที่มีชื่อ data path ทุกช่องเป็น CPU core เพิ่ม เพราะพื้นที่แต่ละแบบมีหน้าที่ต่างกัน

3.13 · Manufacturing ICs (จากแผ่นซิลิคอนสู่ชิปที่ใช้งานได้)

เหตุใดชิปที่สร้างบนแผ่นเดียวกันต้องผ่านการทดสอบและไม่จำเป็นต้องใช้งานได้ทุกชิ้น?

IC: Integrated Circuit (วงจรรวม) รวมวงจรจำนวนมากบนชิ้นสารกึ่งตัวนำ ภาพกระบวนการหน้า 24 อ่านตามลูกศร: Silicon ingot (แท่งซิลิคอน) → slicer ตัด → blank wafers (แผ่นเวเฟอร์เริ่มต้น) → ขั้นประมวลผล 20–40 ขั้นตามภาพ → patterned wafers (แผ่นที่สร้างลวดลายวงจรแล้ว) → wafer tester ทดสอบ → dicer ตัดเป็น dies → bond die to package บรรจุ/ต่อเข้าขา → part tester ทดสอบชิปที่บรรจุแล้ว → ส่งลูกค้า

กากบาทในรูปที่ทดสอบสื่อชิ้นที่ไม่ผ่าน Yield (สัดส่วนชิ้นดี) จึงหมายถึงสัดส่วน die ที่ทำงานได้ต่อ wafer ไม่ใช่จำนวน transistor และไม่ใช่ความถี่ clock [อธิบายเสริม] ถ้าต้องเขียนเป็นสัดส่วนพื้นฐาน ใช้จำนวน die ที่ผ่าน ÷ จำนวน die ที่พิจารณา โดยต้องระบุว่ากำลังพูดถึงขั้นทดสอบใด

หน้า 25 เป็นภาพ Intel Core i7 wafer ขนาด 300 mm ระบุ 280 chips และ 32 nm technology ชิปแต่ละชิ้น 20.7 × 10.5 mm ตารางลายสี่เหลี่ยมบนแผ่นกลมคือ die หลายชิ้น ไม่ใช่ชิปหนึ่งชิ้นใหญ่ทั้งแผ่น [อธิบายเสริม] 300 mm เป็นขนาดแผ่นเวเฟอร์; 20.7 × 10.5 mm เป็นขนาด die; 32 nm เป็นชื่อเทคโนโลยีกระบวนการในตัวอย่าง อย่านำหน่วยสามชนิดไปเทียบเป็นความยาวชนิดเดียวกันหรือคำนวณว่า 280 ชิ้นผ่านทดสอบทั้งหมดโดยไม่มีข้อมูล yield

3.14 · Single-Processor Performance (อ่านกราฟความก้าวหน้าอย่างระวัง)

ทำไมจึงหันมาสนใจการใช้หลายหน่วยทำงาน แทนการรอให้หน่วยเดี่ยวเร็วขึ้นเรื่อย ๆ?

กราฟหน้า 26 ใช้แกนนอนเป็นปี 1978–2018 และแกนตั้งเป็น performance สัมพัทธ์ที่เริ่มฐานประมาณ 1 ในปี 1978 แกนตั้งเป็น Logarithmic Scale (มาตราส่วนลอการิทึม): 1, 10, 100, 1,000, 10,000, 100,000 ห่างเท่า ๆ กัน แต่แต่ละช่วงคือคูณสิบ จึงอ่านความชันเป็นอัตราเติบโต ไม่ใช่เพิ่มคะแนนเท่ากันทุกปี

ช่วงที่กราฟแบ่งโดยประมาณอัตราที่เขียนในต้นฉบับใจความ
1978–198625%/yearเติบโตช่วงแรก
1986–200352%/yearช่วงที่หน่วยเดี่ยวก้าวหน้าเร็วมาก
2003–201123%/yearอัตราเริ่มช้าลง
2011–201512%/yearความก้าวหน้าต่อปีลดลงอีก

จุดพร้อมชื่อเครื่อง เช่น VAX, MIPS, Alpha, Xeon และ Core i7 เป็นตัวอย่างที่ใช้ประกอบแนวโน้ม จุดปลายใกล้ค่าประมาณ 49,935 แสดงผลเทียบฐานในกราฟ ไม่ใช่ 49,935 GHz ข้อสังเกตสำคัญคืออัตราเติบโตลดลงในช่วงหลัง ทำให้แนวคิด parallelism และการออกแบบทั้งระบบมีความสำคัญ [อธิบายเสริม] นี่เป็นกราฟประวัติศาสตร์จากเอกสารปี 2019 ที่จบปี 2018 ไม่ใช่ค่าทำนายหรือรายงานประสิทธิภาพปีปัจจุบัน

3.15 · RISC and CISC (รูปแบบคำสั่งและวิธีสร้างสัญญาณควบคุม)

คำสั่งหนึ่งคำสั่งทำให้ datapath เคลื่อนข้อมูลได้อย่างไร และชื่อ RISC/CISC สื่อแนวคิดใด?

RISC: Reduced Instruction Set Computing (แนวออกแบบชุดคำสั่งที่เน้นความเรียบง่าย) และ CISC: Complex Instruction Set Computing (แนวออกแบบชุดคำสั่งที่มีคำสั่งซับซ้อน) เป็นชื่อแนวทางที่ต้นฉบับใช้เปรียบเทียบ ภาพซ้ายให้ PC ชี้ program memory แล้วคำสั่งเข้า IR ต่อไป decoder สร้าง CW: Control Word (ชุดบิตสัญญาณควบคุม) ไปสั่ง datapath ซึ่งแลกข้อมูลกับ data memory

ภาพขวาเพิ่มเส้นทาง microprogram counter (ตัวนับตำแหน่งคำสั่งย่อย) กับหน่วยเก็บ microprogram ก่อนสร้าง CW สื่อการแยกคำสั่งหนึ่งเป็นชุดควบคุมย่อย การอ่านภาพจึงควรจับว่าโปรแกรมมาจากไหน สัญญาณควบคุมเกิดจากไหน และ datapath รับข้อมูลจากไหน

[อธิบายเสริม: จุดแก้ต้นฉบับ] เชิงอรรถเขียน mPM = Microprocessor Mode แต่บล็อกในเส้นทางควบคุมมีบทบาทเป็น microprogram memory (หน่วยความจำคำสั่งย่อย) จึงไม่ควรจำคำขยาย Microprocessor Mode เป็นความหมายของบล็อกนี้ ภาพเป็นแบบจำลองการควบคุมสองแนวทาง ไม่ใช่กฎว่า RISC ทุกตัวต้องไม่มี microcode หรือ CISC ทุกตัวทำงานช้ากว่าเสมอ ความเร็วต้องตัดสินจากเวลาจริงและปัจจัย IC/CPI/clock ในท้ายบท

3.16 · Embedded Systems and ARM (คอมพิวเตอร์ที่ทำงานอยู่ในผลิตภัณฑ์)

ถ้าคอมพิวเตอร์ต้องควบคุมอุปกรณ์และตอบทันเวลา การออกแบบต้องใส่ใจอะไรนอกจากคำนวณเร็ว?

Embedded System (ระบบฝังตัว) ใช้อิเล็กทรอนิกส์และซอฟต์แวร์อยู่ภายในผลิตภัณฑ์ เครื่องจำนวนมากไม่ได้เป็นคอมพิวเตอร์ตั้งโต๊ะ แต่ซ่อนในอุปกรณ์ที่ใช้ไฟฟ้าและผูกกับสิ่งแวดล้อมของมัน หน้า 28 เน้น Real-time Constraint (ข้อจำกัดที่ต้องตอบสนองทันกำหนดเวลา) และการดูแลหลายกิจกรรมพร้อมกัน จึงต้องวิเคราะห์ทั้งความถูกต้องของคำตอบและเวลาที่คำตอบออกมา

[อธิบายเสริม] ตัวอย่างระบบอ่านเซนเซอร์แล้วควบคุมมอเตอร์: อ่านค่าถูกแต่สั่งช้าเกินกำหนดอาจยังถือว่าทำงานไม่สำเร็จ นี่ต่างจากการหมายความว่า real-time ต้องเป็นเครื่องที่มี GHz สูงที่สุดเสมอ

หน้า 29 ยก ARM เป็นตระกูลสถาปัตยกรรมที่วิวัฒน์จากแนว RISC ใช้ใน microprocessor และ microcontroller ชี้จุดเด่นในบริบทสไลด์ว่า die เล็ก ใช้พลังงานต่ำ และใช้กว้างขวาง คำขยายในภาพมีทั้ง Acorn RISC Machine / Advanced RISC Machine ซึ่งเป็นบริบทประวัติชื่อ ไม่ใช่ประเภทวงจรสองประเภท

ภาพบันไดหน้า 30 แบ่งผลิตภัณฑ์ที่ยกมาเป็น Cortex-A / Cortex-A50, Cortex-R และ Cortex-M พร้อม M0, M0+, M3, M4 [อธิบายเสริม] จดจำกลุ่มการใช้งานเบื้องต้นว่า A เน้นแอปพลิเคชัน, R เน้น real-time, M เน้นไมโครคอนโทรลเลอร์ รูปบันไดแยกตระกูล ไม่ควรอ่านว่าขั้นขวาสูงกว่าจึงเร็วกว่าและแทนทุกงานของขั้นซ้ายได้ หรือถือว่ารายชื่อเก่านี้เป็นแคตตาล็อกครบในปัจจุบัน

3.17 · Cortex-M3 Microcontroller (แกนประมวลผลพร้อมส่วนต่อโลกภายนอก)

ทำไมชิปควบคุมอุปกรณ์หนึ่งตัวจึงต้องมีมากกว่า ALU และหน่วยความจำ?

Microcontroller (ไมโครคอนโทรลเลอร์) คือชิปที่รวมแกนประมวลผล หน่วยความจำ และส่วนติดต่ออุปกรณ์ไว้ใช้ควบคุมงาน ภาพใหญ่หน้า 31 วาง Cortex-M3 processor กับ flash/SRAM, protection, debug และ DMA ไว้ส่วน core and memory แล้วเชื่อมผ่าน 32-bit bus และ peripheral bus ไปยังกลุ่มอุปกรณ์ ตารางนี้อธิบายทุกกลุ่มสำคัญในภาพ

กลุ่มในภาพส่วนที่เห็นและหน้าที่
SecurityHardware AES: วงจรช่วยงานเข้ารหัส
Analog InterfacesA/D อ่านสัญญาณแอนะล็อกเป็นตัวเลข; D/A เปลี่ยนตัวเลขเป็นสัญญาณแอนะล็อก
Timers and TriggersTimer/counter, low-energy timer, real-time counter, pulse counter และ watchdog: จับเวลา นับเหตุการณ์ และเฝ้าการทำงาน
Parallel I/OPin reset, general-purpose I/O และ external interrupts: รับส่งสัญญาณและแจ้งเหตุจากขาภายนอก

ภาพขยายล่างซ้ายมี 32-bit ALU, hardware divider, 32-bit multiplier, control logic, Thumb decode และช่อง instruction/data แยกกัน ส่วนภาพล่างขวาขยาย bus matrix, ICode interface, SRAM/peripheral interface, debug logic, DAP, MPU, ARM core, NVIC และ ETM NVIC (ตัวควบคุม interrupt แบบเวกเตอร์และซ้อนลำดับ) ช่วยเลือกและจัดการเหตุขัดจังหวะ; ETM (ส่วนติดตามการทำคำสั่ง) กับ debug ช่วยดูพฤติกรรมโปรแกรม; DMA (การย้ายข้อมูลโดยไม่ให้ CPU ย้ายทีละค่า) และ MPU (หน่วยป้องกันการเข้าถึงหน่วยความจำ) ลดภาระหรือควบคุมสิทธิ์ตามบทบาท

ข้อความต้นฉบับเน้นการตอบ interrupt ที่คาดเวลาได้ พลังงานต่ำ และ debug/trace ช่วยพัฒนาโปรแกรม [อธิบายเสริม: แก้คำว่า 16, 32-bit applications] Cortex-M3 เป็น processor แบบ 32 บิต ส่วน Thumb/Thumb-2 มี encoding คำสั่ง 16 และ 32 บิต ความยาวคำสั่งกับความกว้างแกนประมวลผลเป็นคนละเรื่อง ดู คำอธิบาย core จาก Arm และ Cortex-M3 Technical Reference Manual

[อธิบายเสริม] ค่าความจำ 64 kB และอุปกรณ์ AES/DAC/USB ในภาพเป็นการรวมของชิปตัวอย่างที่ใช้ core นี้ ไม่ใช่คำรับประกันว่าไมโครคอนโทรลเลอร์ทุกตัวที่ใช้ Cortex-M3 ต้องมีอุปกรณ์ทุกอย่างเหมือนภาพ

3.18 · Parallelism and Flynn’s Taxonomy (ขนานที่ข้อมูล งาน และคำสั่ง)

หลายสิ่งทำพร้อมกันเหมือนกันทั้งหมดหรือควรแยกตามชนิดของงานและโครงสร้าง?

หน้า 32 แยกความขนานที่แอปพลิเคชันมีออกจากกลไกเครื่องที่นำไปใช้ DLP: Data-Level Parallelism (ความขนานระดับข้อมูล) คือการทำแบบเดียวกันกับข้อมูลหลายค่า ส่วน TLP: Task-Level Parallelism (ความขนานระดับงาน) คือแยกงานที่ทำร่วมช่วงเวลาได้ ด้านสถาปัตยกรรมมี ILP: Instruction-Level Parallelism (ให้หลายคำสั่งมีการทำงานทับซ้อน), vector/GPU, Thread-Level Parallelism (ความขนานหลายเธรด) และ Request-Level Parallelism (รับคำขอหลายรายการพร้อมกัน) คำย่อ TLP จึงอาจหมายถึง task หรือ thread ต้องอ่านบริบท

[อธิบายเสริม] การเพิ่มความสว่างให้ทุกพิกเซลเหมาะกับ DLP; ให้หลายเธรดประมวลผลคนละส่วนเป็น thread-level; ให้หลายเครื่องตอบคนละคำขอเว็บเป็น request-level การมีงานแบ่งได้กับการมีฮาร์ดแวร์รองรับต้องสอดคล้องกันจึงจะใช้ความขนานได้ผล

Flynn’s Taxonomy (การจำแนกแบบฟลินน์) หน้า 33 นับ Instruction Stream (สายคำสั่ง) และ Data Stream (สายข้อมูล) ไม่ได้นับจำนวนโปรแกรมในโฟลเดอร์

ประเภทสายคำสั่งสายข้อมูลความหมาย/ตัวอย่างตามต้นฉบับ
SISDSingle: หนึ่งSingle: หนึ่งหนึ่งสายคำสั่งทำกับหนึ่งสายข้อมูล
SIMDSingle: หนึ่งMultiple: หลายคำสั่งแบบเดียวกับหลายข้อมูล; vector, multimedia extensions และ GPU ในมุมที่สไลด์กล่าว
MISDMultiple: หลายSingle: หนึ่งหลายสายคำสั่งกับสายข้อมูลเดียว; สไลด์ระบุว่าไม่มี commercial implementation ในบริบทตัวอย่างของเอกสาร
MIMDMultiple: หลายMultiple: หลายหลายสายคำสั่งกับหลายสายข้อมูล แยก tightly-coupled และ loosely-coupled

Tightly-coupled (เชื่อมใกล้ชิด) หมายถึงหน่วยทำงานประสานและใช้ทรัพยากรใกล้กัน ส่วน Loosely-coupled (เชื่อมหลวมกว่า) กระจายและสื่อสารผ่านการเชื่อมต่อที่แยกมากกว่า [อธิบายเสริม] คำว่าไม่มีเชิงพาณิชย์ของ MISD ไม่ควรขยายเป็นข้อพิสูจน์ว่าไม่มีระบบใดในโลกเข้าข่ายในทุกนิยาม และ GPU จริงมีหลายระดับการจัดงาน ต้องระบุระดับที่กำลังจำแนก

3.19 · System-Level Architecture Patterns (แบ่งระบบใหญ่เป็นส่วนบริการอย่างไร)

เมื่อขยายจาก CPU ไปมองทั้งระบบ เราแบ่งหน้าที่ระหว่างโปรแกรมและเครื่องได้แบบใดบ้าง?

รูปแบบแนวแบ่งงานตามสไลด์[อธิบายเสริม] ภาพใช้งานให้เข้าใจ
Monolithic (ระบบรวมเป็นก้อนเดียว)Single unified systemส่วนงานหลายอย่างอยู่ในหน่วยระบบเดียว จัดและเปลี่ยนไปด้วยกันมาก
Client–Server (ผู้ขอกับผู้ให้บริการ)แยกเครื่องหรือส่วนที่ร้องขอออกจากผู้ตอบบริการโปรแกรมผู้ใช้ส่งคำขอไปยังบริการที่รอรับ
Distributed Systems (ระบบกระจาย)การคำนวณกระจายหลายเครื่องที่เชื่อมเครือข่ายต้องคำนึงถึงการส่งข้อมูลและประสานเครื่องหลายตัว
Microservices (บริการย่อย)บริการเป็นโมดูลและนำขึ้นใช้งานแยกกันได้แบ่งความรับผิดชอบเป็นบริการเล็กที่สื่อสารกัน

หน้า 34 ระบุด้วยว่า microservices เป็นรูปแบบสถาปัตยกรรมซอฟต์แวร์มากกว่า ISA หรือโครงสร้าง CPU [อธิบายเสริม] รูปแบบเหล่านี้ไม่ใช่สี่ช่องที่ตัดกันเด็ดขาด: ระบบกระจายอาจมี client–server และ microservices อยู่ด้วย ต้องบอกระดับการมองก่อนเปรียบเทียบ

3.20 · Relative Performance (เร็วกว่าเป็นกี่เท่า ต้องกลับอัตราส่วนเวลา)

ถ้า A ใช้เวลา 10 วินาทีและ B ใช้ 15 วินาที จะพูดว่า A เร็วกว่าเท่าใดให้ถูก?

หน้า 35 เปิดช่วง Performance (ประสิทธิภาพ) และหน้า 36 นิยามสำหรับงานที่พิจารณาว่า Performance = 1 / Execution Time โดย Execution Time (เวลาทำงาน) ยิ่งน้อย ประสิทธิภาพตามนิยามนี้ยิ่งมาก ต้องเทียบงานเดียวกันและเงื่อนไขที่เหมาะสม

“X เร็วกว่า Y เป็น n เท่า” หมายถึง PerformanceX / PerformanceY = Execution TimeY / Execution TimeX = n เหตุที่เวลาอยู่กลับด้านเพราะ performance เป็นส่วนกลับของเวลา ตัวอย่างในสไลด์ A ใช้ 10 s, B ใช้ 15 s จึงได้ 15 ÷ 10 = 1.5 และสรุปว่า A มี performance เป็น 1.5 เท่าของ B

[อธิบายเสริม] อย่าสับสน 1.5 เท่ากับลดเวลา 50%: เวลาลดจาก 15 เป็น 10 ลด 5/15 = 33.33% ขณะที่ performance เพิ่ม 50% จากฐานของ B เป็นอัตราส่วนที่ใช้ฐานต่างกัน รายละเอียดคำนวณอยู่ในตัวอย่างทำทีละขั้น

3.21 · Elapsed Time and CPU Time (เวลาที่ผู้ใช้รอกับเวลาที่ CPU ใช้กับงาน)

โปรแกรมใช้ CPU ไม่นาน แต่ผู้ใช้ยังรอนานได้อย่างไร?

Elapsed Time (เวลาตั้งแต่เริ่มจนจบ/เวลาที่ผู้ใช้รอจริง) รวม processing, I/O, OS overhead และ idle time จึงสะท้อนผลระดับระบบ ส่วน CPU Time (เวลาที่ CPU ใช้ประมวลผลงานนั้น) ไม่นับเวลารอ I/O และเวลาที่ CPU ไปทำงานอื่น ประกอบด้วย User CPU Time (เวลา CPU ทำโค้ดผู้ใช้) และ System CPU Time (เวลา CPU ทำโค้ดระบบแทนงานนั้น)

Overhead (ค่าใช้จ่ายการจัดการ) คือเวลาที่ระบบใช้สนับสนุนการทำงาน เช่น การจัดการทรัพยากร ไม่ใช่ผลคำนวณหลักที่ผู้ใช้ขอ โปรแกรมต่างชนิดจึงได้รับผลจาก CPU และระบบต่างกัน บางโปรแกรมต้องคำนวณมาก บางโปรแกรมใช้เวลารออุปกรณ์มาก

[อธิบายเสริม] ถ้าเริ่มงาน 10:00:00 จบ 10:00:10 elapsed = 10 s แต่ในช่วงนั้น CPU ทำโค้ดงาน 2 s และโค้ดระบบให้มัน 1 s จะมี CPU time = 3 s เวลาที่เหลืออาจเป็นการรอหรือเครื่องทำงานอื่น ต้องวัดแยกจึงจะรู้ว่าควรปรับ CPU หรือ I/O

3.22 · Clock and CPU Time (เปลี่ยนรอบนาฬิกาเป็นวินาที)

จำนวนรอบ ความถี่ และคาบเวลารวมกันเป็นเวลารันโปรแกรมได้อย่างไร?

Clock (สัญญาณนาฬิกา) ให้จังหวะกับวงจรดิจิทัล ภาพหน้า 38 วาดคลื่นสี่เหลี่ยมด้านบน ช่วง data transfer/computation ตรงกลาง และจุด update state ที่ขอบสัญญาณด้านล่าง ความหมายคือวงจรมีช่วงคำนวณและรับสถานะตามจังหวะ ไม่ใช่หนึ่งลูกคลื่นเท่ากับหนึ่งคำสั่งเสมอ

Clock Period / Cycle Time (คาบ/เวลาต่อหนึ่งรอบ) มีหน่วยวินาทีต่อรอบ ส่วน Clock Frequency / Rate (ความถี่/จำนวนรอบต่อวินาที) มีหน่วย Hz ทั้งสองเป็นส่วนกลับกัน: Cycle Time = 1 / Clock Rate ตัวอย่างในภาพ 250 ps = 0.25 ns = 250 × 10−12 s และ 4.0 GHz = 4,000 MHz = 4.0 × 109 Hz เป็นคาบและความถี่ที่สอดคล้องกัน

หน้า 39 ให้สมการ CPU Time = CPU Clock Cycles × Clock Cycle Time = CPU Clock Cycles / Clock Rate กล่าวคือ งานใช้กี่รอบ คูณแต่ละรอบนานเท่าไร หรือหารด้วยรอบต่อวินาทีเพื่อตอบเป็นวินาที เพิ่ม performance ได้โดยลดจำนวนรอบหรือเพิ่ม clock rate แต่การออกแบบอาจแลกสองปัจจัยกัน: เพิ่มความถี่แล้วใช้รอบมากขึ้น ต้องคำนวณผลรวมใหม่

[อธิบายเสริม] ตรวจหน่วย: (รอบ) ÷ (รอบ/วินาที) = วินาที จึงไม่ควรเอาตัวเลข GHz ไปแทนเป็น 4 โดยไม่แปลง 109 หรือคิดว่า GHz สูงกว่ารับประกันเสร็จเร็วกว่าเมื่อจำนวนรอบต่างกัน

[อธิบายเสริม] ลองเปรียบเทียบเวลา CPU ของเครื่อง A และ B: ตั้ง IC = 500 ล้านคำสั่ง, A: CPI=2 และ 2 GHz, B: CPI=2.6 และ 3 GHz ก่อนเปลี่ยนค่าให้ทายว่าเครื่องใดเร็วกว่า แล้วอธิบายด้วย CPU time แทนการดู GHz อย่างเดียว ไปทดลองในวิดเจ็ตประจำบท →

[อธิบายเสริม] แนวตรวจผล: A ใช้ 0.5 วินาที ส่วน B ใช้ประมาณ 0.4333 วินาที จึงเร็วกว่า A ประมาณ 1.1538 เท่า ลองเพิ่ม CPI ของ B เป็น 3.2 โดยคง 3 GHz จะใช้ประมาณ 0.5333 วินาที ซึ่งช้ากว่า A แม้ความถี่สูงกว่า

3.23 · CPU Time Example (เพิ่มความถี่แต่รอบเพิ่ม ต้องชดเชยเท่าใด)

A ใช้ 10 s ที่ 2 GHz ถ้า B ใช้รอบเพิ่ม 20% และต้องจบใน 6 s ต้องมี clock เท่าไร?

โจทย์หน้า 40 ระบุ Computer A: clock 2 GHz และ CPU time 10 s ต้องออกแบบ B ให้ CPU time 6 s แต่การทำ clock เร็วขึ้นทำให้ B ต้องใช้ 1.2 เท่าของ clock cycles ของ A ดังนั้นห้ามคิดเพียง 10/6 แล้วนำไปเทียบความถี่ ต้องหาจำนวนรอบที่เพิ่มด้วย

  1. CyclesA = TimeA × RateA = 10 s × 2 × 109 รอบ/s = 20 × 109 รอบ
  2. CyclesB = 1.2 × 20 × 109 = 24 × 109 รอบ
  3. RateB = CyclesB / TimeB = (24 × 109) / 6 = 4 × 109 รอบ/s = 4 GHz
  4. แทนกลับ: TimeB = 24 × 109 / 4 × 109 = 6 s ตรงเป้าหมาย

[อธิบายเสริม] แม้ clock เพิ่มจาก 2 เป็น 4 GHz หรือสองเท่า แต่เวลาลดจาก 10 เป็น 6 s จึงเร็วขึ้น 10/6 ≈ 1.667 เท่า เพราะ B ต้องทำจำนวนรอบมากกว่า A อยู่ 20%

3.24 · Instruction Count and CPI (งานมีกี่คำสั่ง และคำสั่งเฉลี่ยกินกี่รอบ)

ทำไม CPI ต่ำกว่าหรือ clock สูงกว่าเพียงตัวเดียวจึงยังตัดสินว่าเร็วกว่าไม่ได้?

Instruction Count: IC (จำนวนคำสั่งที่ถูกทำจริง) คือจำนวนคำสั่งเครื่องที่งานนั้นทำ ไม่ใช่จำนวนบรรทัดในไฟล์ซอร์ส และขึ้นกับโปรแกรม ISA และ compiler CPI: Cycles Per Instruction (จำนวนรอบเฉลี่ยต่อคำสั่ง) ขึ้นกับฮาร์ดแวร์และ Instruction Mix (สัดส่วนชนิดคำสั่งที่รัน) เพราะคำสั่งต่างชนิดอาจใช้รอบต่างกัน

สมการหน้า 41 คือ Clock Cycles = IC × CPI และ CPU Time = IC × CPI × Cycle Time = IC × CPI / Clock Rate ดังนั้นต้องดูทั้งจำนวนคำสั่ง ค่าเฉลี่ยรอบ และเวลาต่อรอบ ไม่ใช่เลือกค่าหนึ่งที่ดูดี

หน้า 42 เทียบ A: cycle time 250 ps, CPI 2.0 กับ B: cycle time 500 ps, CPI 1.2 ภายใต้จำนวนคำสั่งเดียวกัน I ได้ TimeA = I × 2.0 × 250 = I × 500 ps และ TimeB = I × 1.2 × 500 = I × 600 ps ดังนั้น A เร็วกว่า B ด้วยอัตรา 600/500 = 1.2 เท่า แม้ CPI ของ A จะสูงกว่า เพราะรอบของ A สั้นกว่ามาก

[อธิบายเสริม: ข้อสมมติที่ต้นฉบับย่อไว้] สไลด์เขียน Same ISA แต่ตอนตัด I ต้องสมมติด้วยว่ารันโปรแกรม/เส้นทางคำสั่งเดียวกันจน IC เท่ากัน ISA เดียวกันเพียงอย่างเดียวไม่ได้บังคับให้ compiler หรือโปรแกรมทุกตัวใช้จำนวนคำสั่งเท่ากัน ตัวอย่างทำงานด้านล่างขยายการแทนค่าที่ต้นฉบับย่อไว้

  1. กำหนด TimeA = 10 s และ TimeB = 15 s สำหรับโปรแกรมเดียวกัน

  4. [อธิบายเสริม] หากถาม performance เพิ่มกี่เปอร์เซ็นต์: (1.5 − 1) × 100 = 50%
  5. [อธิบายเสริม] หากถามเวลาลดกี่เปอร์เซ็นต์โดยใช้ B เป็นฐาน: (15 − 10)/15 × 100 = 33.33% คำตอบสองเปอร์เซ็นต์ต่างกันเพราะฐานและตัววัดต่างกัน

Clock Period: 250 ps สอดคล้องกับ 4 GHz ตามหน้า 38

  1. 1 ps = 10−12 s จึงได้ 250 ps = 250 × 10−12 s = 2.5 × 10−10 s
  2. 1 ns = 1000 ps ดังนั้น 250 ps = 250/1000 ns = 0.25 ns
  3. [อธิบายเสริม] ใช้ความถี่ = 1/คาบ: 1/(2.5 × 10−10) = (1/2.5) × 1010 = 0.4 × 1010 = 4 × 109 Hz
  4. 4 × 109 Hz = 4 GHz = 4000 MHz จึงตรงกับคู่ตัวเลขในสไลด์
  5. [อธิบายเสริม] หนึ่งรอบใช้ 0.25 ns ไม่ได้แปลว่าหนึ่ง instruction ต้องเสร็จใน 0.25 ns เพราะยังต้องมี CPI

CPU Design: B ต้องใช้ 4 GHz ตามหน้า 40

ข้อมูล: A มี 2 GHz และ 10 s; B ต้องจบใน 6 s แต่ใช้รอบ 1.2 เท่าของ A

  1. แปลงความถี่ A: 2 GHz = 2 × 109 รอบ/s
  2. CyclesA = 10 s × 2 × 109 รอบ/s = 20 × 109 รอบ
  3. CyclesB = 1.2 × 20 × 109 = 24 × 109 รอบ
  4. ต้องการ TimeB = 6 s จึง RateB = 24 × 109 / 6 = 4 × 109 Hz = 4 GHz
  5. ตรวจโดยหารกลับ: 24 × 109 รอบ ÷ 4 × 109 รอบ/s = 6 s
  6. [อธิบายเสริม] คำตอบ 3.333 GHz ที่มาจาก 2 × 10/6 ลืมจำนวนรอบที่เพิ่ม 1.2 เท่า ถ้าใช้ค่านั้นจริง เวลาจะ 24/3.333 ≈ 7.2 s จึงไม่ถึงเป้าหมาย

CPI Example: CPI ต่ำกว่าแต่ยังช้ากว่าตามหน้า 42

ตามสไลด์ให้ทั้งสองเครื่องทำ I คำสั่ง: A มี 250 ps/cycle และ CPI 2.0; B มี 500 ps/cycle และ CPI 1.2

  1. TimeA = I instructions × 2.0 cycles/instruction × 250 ps/cycle = I × 500 ps
  2. TimeB = I × 1.2 × 500 ps = I × 600 ps
  3. เพราะ I เท่ากัน และ 500 < 600 จึง A ใช้เวลาน้อยกว่า
  4. อัตรา performance ของ A ต่อ B = TimeB/TimeA = (I × 600)/(I × 500) = 1.2
  5. [อธิบายเสริม] ลองกำหนด I = 109: A ใช้ 109 × 500 × 10−12 = 0.5 s; B ใช้ 0.6 s ยืนยันอัตรา 0.6/0.5 = 1.2
  6. [อธิบายเสริม] ตัด I ได้เพราะสมมติ IC เท่ากัน ไม่ใช่เพราะคำว่า same ISA เพียงคำเดียว การเปลี่ยน compiler หรือเส้นทางโปรแกรมอาจเปลี่ยน IC ได้

หน้า 4 ใช้ architecture ในความหมายงานออกแบบจริงที่กว้างกว่า ISA จึงไม่ควรถือว่าความหมาย “เก่า” และ “จริง” เป็นบทขัดแย้งโดยไม่อ่านบริบท

Parallelism คือการทำหลายส่วนพร้อมกันโดยรวม ส่วน pipelining เป็นวิธีให้หลายงานอยู่คนละขั้นพร้อมกัน [อธิบายเสริม] จึงอาจเพิ่มอัตรางานเสร็จโดยไม่ลดทุกขั้นของงานเดี่ยว อย่าแปลว่าทั้งสองจำเป็นต้องหมายถึงหลาย CPU คนละชิป

Clock Rate, CPI และ Performance

Clock rate วัดรอบต่อวินาที CPI วัดรอบต่อคำสั่ง ส่วน performance ในบทนี้สัมพันธ์กับเวลางานทั้งหมด ทั้งสามไม่ใช่สิ่งเดียวกัน ใช้ Time = IC × CPI / Rate เทียบก่อนตัดสิน ตัวอย่างหน้า 42 A มี CPI 2.0 มากกว่า 1.2 ของ B แต่รอบสั้นกว่าจน A เร็วกว่า 1.2 เท่า

เร็วขึ้น 1.5 เท่า กับเวลาลด 50%

[อธิบายเสริม] เวลา 15→10 s ให้ speedup 15/10=1.5 หรือ performance เพิ่ม 50% แต่เวลาลด (15−10)/15=33.33% ถ้าเวลาลด 50% จริงจะเหลือ 7.5 s และ speedup เป็น 2 เท่า ต้องระบุฐานของเปอร์เซ็นต์

Same ISA กับ Same Instruction Count

[อธิบายเสริม] ISA เดียวกันบอกความเข้ากันได้ของคำสั่ง ไม่ได้บังคับว่าโปรแกรมคนละตัวหรือ compiler คนละการตั้งค่าจะใช้ IC เท่ากัน การตัด I ในโจทย์หน้า 42 ใช้ได้เพราะตัวอย่างสมมติจำนวนคำสั่งเดียวกันด้วย

7 · ทบทวนก่อนสอบ

  • Architecture บอกคุณสมบัติที่โปรแกรมเห็น; organization บอกหน่วยปฏิบัติการและการเชื่อมต่อที่ทำให้เกิดขึ้นจริง
  • ภาษา algorithm compiler ISA CPU memory I/O และ OS ล้วนมีผลต่อประสิทธิภาพของโปรแกรม
  • CU ควบคุม ALU คำนวณ register เก็บค่า และเส้นทางเชื่อมต่อทำให้ส่วนต่าง ๆ ใช้ข้อมูลร่วมกันได้
  • PC ถือที่อยู่คำสั่งถัดไป ส่วน IR ถือคำสั่งที่ดึงมา; machine cycle คือ fetch decode execute และเก็บผลตามคำสั่ง
  • แคชใช้พื้นที่เล็กเร็วใกล้ core; core thread chip และ motherboard เป็นคนละระดับของระบบ
  • ระบบฝังตัวต้องคำนึงถึงพลังงาน ต้นทุน และกำหนดเวลา; ภาพ Cortex-M3 แสดงว่าชิปมีทั้ง core memory และอุปกรณ์รอบข้าง
  • Flynn จำแนกสายคำสั่งกับสายข้อมูล; รูปแบบ client–server/distributed/microservices เป็นระดับระบบอีกมุมหนึ่ง
  • Performance = 1/time; อัตราความเร็ว X ต่อ Y = TimeY/TimeX สำหรับงานและเงื่อนไขที่เทียบกันได้
  • CPU time = cycles/rate = IC×CPI/rate; ดู CPI หรือ GHz ค่าเดียวไม่พอ
  • แยก elapsed กับ CPU time และตรวจหน่วย ข้อสมมติ IC และจุดย่อความในภาพก่อนสรุป

[อธิบายเสริม] แนวตอบพร้อมเหตุผล ใช้ตรวจวิธีคิดหลังลองทำด้วยตัวเอง

1. [อธิบายเสริม] เครื่องที่รองรับ ISA เดียวกันมีประสิทธิภาพต่างกันได้อย่างไร?

ISA กำหนดว่าคำสั่งหมายถึงอะไรและโปรแกรมใช้ความสามารถใดได้ แต่ organization เลือก cache pipeline หน่วยทำงาน และการเชื่อมต่อได้ต่างกัน จึงมี CPI จำนวนรอบที่รอข้อมูล หรือ clock rate ต่างกัน แม้รันคำสั่งชุดเดียวกันได้ CPU time ก็อาจต่างตาม IC×CPI/rate ต้องกำหนดงานและวัดหรือคำนวณเวลา ไม่สรุปจากชื่อ ISA อย่างเดียว

2. [อธิบายเสริม] ภาพวงซอฟต์แวร์กับภาพการแปลโค้ดอธิบายต่างมุมอย่างไร?

ภาพวงซ้อนอธิบายชั้นการพึ่งบริการ: application ใช้ system software ซึ่งอาศัย hardware ส่วนภาพลูกศรอธิบายการแปลงรูปโปรแกรมจากภาษาระดับสูงผ่าน compiler เป็น assembly แล้วผ่าน assembler เป็น machine code OS อยู่ในชั้น system software แต่ไม่ได้ทำหน้าที่แทน compiler หรือ assembler การแยกสองมุมนี้ช่วยไม่เข้าใจผิดว่า CPU ต้องอ่านภาษา C โดยตรง

3. [อธิบายเสริม] อธิบายหนึ่งวงรอบคำสั่งโดยใช้ PC, IR, CU, ALU และ memory

PC ระบุที่อยู่ที่จะดึงคำสั่งจาก memory คำสั่งที่อ่านมาถูกเก็บใน IR แล้ว CU ถอดรหัสเพื่อสร้างการควบคุม หากเป็นคำสั่งคำนวณก็เตรียมข้อมูลให้ ALU ทำงาน เก็บผลในตำแหน่งที่คำสั่งกำหนด และอาจปรับสถานะ จากนั้น PC ทำให้รู้ว่าจะดึงคำสั่งใดต่อ ลูกศรในภาพเป็นภาพย่อ: ไม่ใช่ทุกคำสั่งต้องทำเลขใน ALU แบบเดียวหรือเขียนผลลง memory ทุกครั้ง

4. [อธิบายเสริม] Multicore ต่างจาก SMT และแคชเกี่ยวข้องอย่างไร?

Multicore เพิ่มหน่วยประมวลผลทางกายภาพ ส่วน SMT ให้ core เดียวรองรับหลายบริบทเธรดและใช้ทรัพยากรประมวลผลร่วมกัน จึงไม่ให้ core ใหม่เต็มตัวต่อ thread ภาพแคชแสดงว่าแต่ละ core อาจมี L1 ส่วนตัวและมี L2/L3 ที่ใช้ร่วมกัน ทำให้ทั้งความสามารถประมวลผลและทางหาข้อมูลมีส่วนกำหนดผล การเพิ่มเธรดจึงไม่รับประกันเพิ่มความเร็วเป็นสัดส่วนตรง

5. [อธิบายเสริม] อ่านภาพ Cortex-M3 ให้เห็นเหตุผลที่เหมาะกับงานควบคุมอย่างไร?

งานควบคุมต้องอ่านสัญญาณ จับเวลา ตอบเหตุการณ์ สื่อสาร และสั่งอุปกรณ์ ภาพจึงไม่ได้มีเพียง ALU แต่มี analog interfaces, GPIO, timers, interrupt control, serial interfaces, flash/SRAM, DMA และการจัดพลังงาน/clock พร้อม debug/trace สำหรับตามการทำงาน ข้อกำหนด real-time เน้นตอบให้ทันกำหนด ส่วน Cortex-M3 เป็นแกน 32 บิตที่รองรับ encoding คำสั่ง Thumb/Thumb-2 16/32 บิต ไม่ใช่แกนสองความกว้างสลับกัน

6. [อธิบายเสริม] จะแยก DLP, ILP, thread-level และ request-level ด้วยสถานการณ์ได้อย่างไร?

DLP มองว่าการกระทำเดียวทำกับข้อมูลหลายค่าได้ ILP มองว่าคำสั่งหลายคำสั่งมีส่วนทำงานทับซ้อนกันได้ thread-level มองหลายสายคำสั่งของงานที่มีบริบทแยกกัน และ request-level มองคำขอบริการหลายรายการที่ตอบแยกกันได้ ข้อมูลหรืองานต้องแบ่งได้ และเครื่องต้องมีทรัพยากรรองรับจึงเกิดประโยชน์ Flynn เป็นอีกวิธีที่ถามจำนวนสายคำสั่งและข้อมูล ไม่ควรจับคำว่า parallel ทุกแบบเท่ากับ MIMD โดยทันที

7. [อธิบายเสริม] ทำไมโจทย์ A 2 GHz 10 s กับ B 6 s จึงตอบ 4 GHz?

A ใช้ 10×2×10^9 = 20×10^9 รอบ B มีข้อแลกเปลี่ยนว่าต้องใช้ 1.2 เท่าจึงเป็น 24×10^9 รอบ ต้องหารด้วยเป้าหมาย 6 s ได้ 4×10^9 รอบ/s หรือ 4 GHz ถ้าคิดจากอัตราเวลาอย่างเดียวจะได้ 3.333 GHz และพลาดผลของรอบที่เพิ่ม การแทนกลับ 24×10^9/4×10^9=6 s ยืนยันคำตอบ

8. [อธิบายเสริม] ในหน้า 42 ทำไม A ที่ CPI สูงกว่าจึงเร็วกว่า และตัด I ได้เมื่อใด?

A ใช้ 2×250=500 ps ต่อคำสั่งเฉลี่ย ส่วน B ใช้ 1.2×500=600 ps เมื่องานมี I คำสั่งเท่ากัน เวลารวมเป็น I×500 กับ I×600 ps จึง A เร็วกว่า 600/500=1.2 เท่า ตัด I ได้เพราะ IC เท่ากันซึ่งเป็นข้อสมมติของตัวอย่าง คำว่า same ISA เพียงอย่างเดียวไม่รับประกัน IC เท่ากันสำหรับทุกโปรแกรมและ compiler
