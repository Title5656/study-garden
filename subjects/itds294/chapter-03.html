ศัพท์ตั้งต้น: Internet คือเครือข่ายที่เชื่อมเครือข่าย; Web คือบริการหน้าและข้อมูลที่เข้าถึงผ่านเครือข่าย; Browser คือโปรแกรมเปิดเว็บ; Client คือฝั่งขอใช้บริการและ server คือฝั่งตอบบริการ; Database คือที่จัดเก็บข้อมูลอย่างเป็นระบบ; DNS คือระบบค้นข้อมูลชื่อโดเมนเพื่อหาปลายทาง; HTTPS คือการสื่อสารเว็บที่ปกป้องข้อมูลระหว่างทาง; SaaS คือซอฟต์แวร์ที่ใช้เป็นบริการจากผู้ให้บริการ; Host คือที่ให้ระบบทำงาน; Cloud คือทรัพยากรคอมพิวเตอร์ที่ใช้จากผู้ให้บริการผ่านเครือข่าย

01 / ITDS294

Internet เป็นเครือข่าย ส่วน Web เป็นบริการบนเครือข่าย

ส่งอีเมลได้แต่เปิดเว็บร้านไม่ได้ แปลว่าอินเทอร์เน็ตทั้งหมดเสียหรือไม่? เปรียบเครือข่ายเป็นทางเชื่อม ส่วนเว็บเป็นบริการหนึ่งที่เดินทางบนทางนั้น

ลองมอง Internet เป็นระบบถนนที่เชื่อมสถานที่ต่าง ๆ ส่วน Web เป็นบริการหนึ่งที่ใช้ถนนนั้นเพื่อขอและส่งหน้าเว็บ E-mail และการสื่อสารเสียงผ่าน IP ก็ใช้เครือข่ายได้โดยไม่ใช่หน้าเว็บทั้งหมด

พัฒนาการในสไลด์แบ่งได้เป็นช่วงสร้างนวัตกรรมเครือข่าย ช่วงขยายเป็นสถาบันและโครงสร้างร่วม และช่วงเปิดสู่การใช้งานเชิงพาณิชย์ สิ่งสำคัญต่อร้านออนไลน์คือเครือข่ายและมาตรฐานร่วมทำให้เชื่อมลูกค้า ผู้ขาย และบริการอื่นได้ในวงกว้าง

คำหน้าที่โดยย่อเมื่อขัดข้องจะเห็นอะไร
Internetเครือข่ายเชื่อมอุปกรณ์และเครือข่ายย่อยติดต่อบริการหลายประเภทไม่ได้
Web / WWWทรัพยากรเชื่อมโยงที่เข้าถึงด้วยเบราว์เซอร์หน้าเว็บหรือทรัพยากรบางอย่างเปิดไม่ได้
DNSช่วยแปลงชื่อโดเมนไปยังข้อมูลที่ใช้ค้นหาปลายทางจำชื่อเว็บได้แต่หาปลายทางไม่เจอ
HTTPSHTTP ผ่านช่องทาง TLS ที่ปกป้องการสื่อสารต้องตรวจการเชื่อมต่อและใบรับรอง
APIข้อตกลงให้ซอฟต์แวร์คุยและแลกข้อมูลหน้าร้านยังอยู่แต่บริการบางส่วนใช้ไม่ได้
DNS, HTTPS และ API เป็นคำอธิบายเสริมเพื่อให้เห็นการเชื่อมระบบ ไม่ใช่รายชื่อสินค้าที่ต้องซื้อ และ HTTPS เพียงอย่างเดียวไม่ได้รับรองความสุจริตของร้าน

ตัวอย่างคิดตามทีละขั้น

แยกสามชั้น: Internet เชื่อมเครื่อง → Web ใช้การขอและส่งหน้า/ข้อมูล → browser เป็นโปรแกรมเปิดบริการนั้น การที่เว็บหนึ่งเสียจึงไม่ได้พิสูจน์ว่าทุกบริการบนเครือข่ายเสีย

02 / ITDS294

กดสั่งซื้อหนึ่งครั้ง มีใครทำงานบ้าง

คลิกสั่งซื้อแล้วจอหมุนค้าง งานหยุดอยู่ที่ไหน? ต้องเห็นการเดินทางของคำขอจากเครื่องลูกค้าไปยังผู้ประมวลผลและกลับมา จึงจะถามหาจุดผิดพลาดได้

อ่านลำดับก่อนทดลอง: ก่อนกด แยกเครื่องลูกค้าออกจากเครื่องที่ตรวจราคา ระหว่างกดตามข้อมูลที่ส่งต่อและผู้ตรวจสอบในแต่ละขั้น; cache คือข้อมูลที่จำไว้ใช้ซ้ำ หลังกด ลองระบุว่าหน้ายืนยันอย่างเดียวพิสูจน์การชำระเงินได้หรือไม่ ปุ่มเริ่มใหม่กลับขั้นแรกเพื่อทวนเหตุผลได้

  1. หาปลายทาง: เบราว์เซอร์ใช้ชื่อโดเมนและข้อมูลจาก DNS เพื่อช่วยติดต่อปลายทาง อาจมีการใช้ค่าที่จำไว้เพื่อลดการค้นซ้ำ
  2. ขอหน้าร้าน: เบราว์เซอร์ติดต่อเว็บผ่าน HTTPS และขอทรัพยากรมาแสดง เมื่อมีการใช้ cache บางทรัพยากรอาจไม่ต้องโหลดใหม่
  3. ส่งคำสั่งซื้อ: ลูกค้าเลือกเมนูแล้วส่งข้อมูล ระบบฝั่งเซิร์ฟเวอร์ต้องตรวจสินค้า ราคา และเงื่อนไขใหม่ ไม่เชื่อยอดที่แก้ได้จากหน้าจอ
  4. ตรวจและบันทึก: ส่วนแอปตรวจความจุ/สต็อก แล้วบันทึกรายการพร้อมสถานะ เพื่อไม่ให้สัญญากับลูกค้าเกินสิ่งที่ส่งมอบได้
  5. เชื่อมการจ่าย: ระบบเชื่อมผู้ให้บริการชำระเงิน และรับสถานะที่ตรวจสอบได้ การเปิดหน้ายืนยันเพียงอย่างเดียวไม่พอพิสูจน์การจ่าย
  6. คืนผลและดำเนินงาน: ลูกค้าเห็นเลขรายการและสถานะ ร้านได้รับข้อมูลเตรียมสินค้า แล้วติดตามการส่งมอบต่อ

ก่อนทดลอง: คิดว่าการคลิกซื้อเป็นเพียงการส่งรูปปุ่มไปที่ร้านหรือไม่ ระหว่างทดลอง: ตาม browser → server → ข้อมูล/การตอบกลับ แล้วสังเกตว่าจุดไหนต้องตรวจคำสั่งซื้อ

อ่านผลและวิธีคิดโดยไม่ต้องเปิดกิจกรรม

การเห็นหน้าสำเร็จไม่ได้แปลว่าฐานข้อมูลบันทึกเสมอ ต้องให้ระบบยืนยันผล ธุรกรรมต้องอาศัยทั้งเครือข่าย แอปพลิเคชัน และข้อมูล

เส้นทางคำสั่งซื้อผ่านระบบ

กดแต่ละขั้น หรือใช้ปุ่มก่อนหน้าและถัดไปเพื่อดูเหตุและผล

แยกปัญหาให้ถูกชั้น: รูปสินค้าไม่โหลดอาจอยู่ที่การส่งไฟล์ การคำนวณยอดผิดอาจอยู่ที่กฎธุรกิจ ส่วนสินค้าคงเหลือติดลบอาจอยู่ที่การจัดการข้อมูล การเห็นเส้นทางช่วยให้กำหนดเจ้าของปัญหาได้ถูกต้อง

ตัวอย่างคิดตามทีละขั้น

ชื่อร้านต้องหาเส้นทางผ่าน DNS ก่อน → browser ส่งคำขอ → server ตรวจสินค้าและราคา → ฐานข้อมูลบันทึกรายการ → ส่งคำตอบกลับ ถ้าจอไม่ตอบแต่ข้อมูลบันทึกแล้ว การกดซ้ำอาจสร้างรายการซ้ำ จึงควรตรวจสถานะเดิม

03 / ITDS294

บริการเครือข่ายช่วยอะไรกับ E-Commerce

ลูกค้าต้องการเห็นว่าโซฟาพอดีกับห้องหรือไม่ ควรส่งอีเมลยาวหรือให้ลองวางภาพสินค้า? เลือกบริการจากสิ่งที่ช่วยตัดสินใจ มิใช่ใช้ทุกเทคโนโลยีพร้อมกัน

กลุ่มบริการประโยชน์ข้อควรออกแบบ
E-mail / IMยืนยันรายการและสนทนาช่วยตัดสินใจสถานะข้อความต้องไม่สับสนกับสถานะจ่ายเงิน
Forum / social / blogสร้างความรู้ รีวิว และชุมชนข้อมูลต้องมีบริบทและตรวจความน่าเชื่อถือ
VoIP / video conferenceช่วยแนะนำหรือให้คำปรึกษาระยะไกลคุณภาพเครือข่ายมีผลต่อประสบการณ์
Search engineช่วยให้คนค้นพบสินค้าและบริการหน้าและข้อมูลต้องเข้าใจได้ง่าย
Download / streaming / podcastส่งเนื้อหาดิจิทัลให้บริโภคดาวน์โหลดต้องเก็บไฟล์ ส่วนสตรีมเล่นระหว่างรับข้อมูล
VR / AR / MRช่วยสำรวจหรือทดลองสินค้าด้วยภาพจำลองVR พาเข้าโลกจำลอง; AR ซ้อนสิ่งเสมือน; MR เน้นปฏิสัมพันธ์กับสภาพจริง

มือถือเพิ่มทั้งความสะดวกและข้อจำกัด: เข้าถึงลูกค้าได้ในบริบทการเดินทาง แต่จอเล็ก เครือข่ายไม่นิ่ง และผู้ใช้มักมีเวลาจำกัด จึงต้องลดขั้นตอนที่ไม่จำเป็น

ตัวอย่างคิดตามทีละขั้น

AR วางภาพโซฟาจำลองซ้อนห้องจริง จึงช่วยเทียบตำแหน่ง; VR พาเข้าโลกจำลองเป็นหลัก จึงเหมาะกับสำรวจพื้นที่เสมือน ส่วน streaming ส่งวิดีโอเป็นช่วงให้เริ่มดูก่อนรับครบ ทั้งสามแก้คนละงาน

04 / ITDS294

กิจกรรมจากสไลด์: สร้างเอง ใช้สำเร็จรูป หรือขายผ่านตลาดกลาง

ร้านมีสองสัปดาห์และทีมเล็ก จะใช้เวลาไปกับระบบที่ลูกค้าไม่เห็นหรือเริ่มทดสอบการขายก่อน? เปรียบเทียบเวลาเริ่ม ความยืดหยุ่น และภาระดูแลร่วมกัน

ทางเลือกสิ่งที่ได้ภาระหรือข้อแลกเปลี่ยน
Build เองควบคุมประสบการณ์และกฎเฉพาะได้มากพัฒนา ดูแลความปลอดภัย และรักษาระบบต่อเนื่อง
SaaS / ร้านสำเร็จรูปเริ่มได้ไวและมีความสามารถมาตรฐานมีค่าใช้บริการและข้อจำกัดของผู้ให้บริการ
Marketplaceเริ่มขายในที่ที่มีผู้ซื้ออยู่แล้วพึ่งกฎ การมองเห็น ค่าธรรมเนียม และข้อมูลที่แพลตฟอร์มให้

ก่อนเลือก ระบุเวลาเริ่มและกำลังทีม ระหว่างสลับดูภาระที่ยังต้องรับผิดชอบ แล้วเลือกทางหนึ่งพร้อมข้อแลกเปลี่ยน ตารางทางเลือกและแนวคำตอบถัดไปใช้อ่านแทนได้เมื่อไม่ใช้ JavaScript ใช้เริ่มใหม่เพื่อกลับหัวข้อแรก

ก่อนทดลอง: สมมติทีมมีสองคนและเวลาสองสัปดาห์ จะเลือกจากความนิยมอย่างเดียวได้ไหม ระหว่างทดลอง: เปลี่ยนสถานการณ์แล้วสังเกตเงื่อนไขเรื่องเวลา กฎงาน และหลายช่องทาง

อ่านผลและวิธีคิดโดยไม่ต้องเปิดกิจกรรม

ทีมเล็กอาจเริ่มทดสอบด้วยบริการพร้อมใช้ แต่ระบบกฎอนุมัติหลายฝ่ายต้องดูการต่อยอดและการดูแล ไม่มีตัวเลือกดีที่สุดสำหรับทุกกรณี

เลือกสถานการณ์ แล้วดูเหตุผลของทางเลือก

แนวคำตอบกิจกรรม · ร้านเริ่มต้นกับธุรกิจที่มีกฎเฉพาะควรคิดต่างกันอย่างไร

ร้านเริ่มต้นที่ทีมเล็กควรทดสอบตลาดผ่านช่องทางที่เริ่มง่ายก่อน ธุรกิจที่มีกฎราคา/การอนุมัติซับซ้อนอาจต้องเชื่อมระบบหรือพัฒนาเฉพาะมากขึ้น การตัดสินใจต้องดูเวลา งบ ทีม ข้อมูลที่ต้องควบคุม และต้นทุนรวมตลอดการใช้งาน สามารถใช้หลายช่องทางร่วมกันได้ ไม่จำเป็นต้องเลือกทางเดียวตลอดไป

ตัวอย่างคิดตามทีละขั้น

เริ่มจากต้องการขายสินค้ามาตรฐาน → ตรวจบริการสำเร็จรูปและ marketplace → เทียบค่าธรรมเนียมกับข้อมูลที่นำออกได้ ถ้ามีกฎอนุมัติเฉพาะจึงค่อยประเมินส่วนที่ต้องพัฒนาเอง การเลือก host เป็นอีกเรื่องหนึ่งจากการเลือกคนสร้างระบบ

05 / ITDS294

นวัตกรรมใหม่จะเป็น infrastructure ได้เมื่อไร

เทคโนโลยีใหม่มีชื่อดัง แต่ลูกค้าจะทำงานเดิมได้ดีขึ้นตรงไหน? Infrastructure หมายถึงโครงสร้างพื้นฐานที่บริการอื่นพึ่งพา ต้องพิจารณาความพร้อมและการเชื่อมต่อด้วย

สไลด์ยก blockchain, cryptocurrency, NFT และ metaverse เป็นหัวข้อชวนคิด ควรแยกว่าตัวใดเป็นเทคโนโลยีพื้นฐาน ตัวใดเป็นสินทรัพย์หรือรูปแบบการใช้ และลูกค้ามีปัญหาอะไรที่ต้องแก้จริง

ก่อนเพิ่มเทคโนโลยี ให้ถามว่ามาตรฐานและระบบนิเวศพร้อมหรือไม่ เชื่อมของเดิมได้แค่ไหน มีผู้ใช้ยอมใช้จริงไหม และต้นทุนดูแลเป็นอย่างไร ความใหม่ของชื่อไม่ใช่หลักฐานว่าเหมาะกับธุรกิจ

การสร้างเว็บกับการโฮสต์เป็นคนละการตัดสินใจ: พัฒนาเองแต่ใช้โครงสร้างพื้นฐานจากผู้ให้บริการได้ การเลือกแบบนี้ยังต้องแบ่งหน้าที่ดูแลให้ชัด

ตัวอย่างคิดตามทีละขั้น

ถ้าปัญหาคือเมนูไม่อัปเดต ให้แก้เจ้าของข้อมูลและการส่งสถานะก่อน การเพิ่ม blockchain ซึ่งเป็นวิธีบันทึกร่วมแบบกระจายไม่ได้ทำให้ข้อมูลตั้งต้นถูกต้องเอง; cryptocurrency คือสินทรัพย์ดิจิทัลชนิดการใช้งานหนึ่ง ส่วน NFT ใช้โทเคนแยกเอกลักษณ์และไม่ได้รับรองมูลค่า

สรุปบท: เชื่อมแนวคิดให้เป็นเหตุผล

Internet เชื่อมเครื่อง Web เป็นบริการ และคำขอเดินผ่านหลายส่วนก่อนกลับมาเป็นผลบนจอ เมื่อเข้าใจหน้าที่แต่ละส่วนจึงเลือกบริการ แพลตฟอร์ม และการโฮสต์ได้ตามงาน ความใหม่ของเทคโนโลยีไม่แทนการประเมินความต้องการ ต้นทุน และภาระดูแล บทถัดไปนำทางเลือกเหล่านี้เข้าแผนพัฒนาระบบ

ลองตอบก่อนอ่านเฉลย: เว็บใช้ HTTPS แล้วสรุปได้หรือไม่ว่าร้านส่งสินค้าครบแน่นอน?
