01 / ITDS294

เริ่มด้วยผลลัพธ์ทางธุรกิจ

ก่อนเลือกเครื่องมือ ต้องรู้ว่าหน้าร้านช่วยใครทำอะไร เช่น CampusMeal ต้องการให้ลูกค้าสั่งก่อนพักเที่ยงและรับอาหารตรงเวลา เป้าหมายนี้นำไปสู่ความสามารถเรื่องเวลาปิดรับออร์เดอร์ จำนวนอาหารที่ขายได้ และสถานะการเตรียม ไม่ใช่เริ่มจากเลือกเฟรมเวิร์กแล้วค่อยหาปัญหามารองรับ

สิ่งที่กำหนดตัวอย่างสมมติ
Mission / audienceลดเวลารออาหารให้คนที่มีเวลาพักสั้น
Revenue modelค่าบริการต่อออร์เดอร์ที่สำเร็จ
Contentเมนู ราคา ส่วนผสม จุดรับ และเวลา
Presence mapเว็บสำหรับสั่ง + สื่อสังคมเพื่อค้นพบ + ข้อความแจ้งสถานะ
Timeline / budgetเริ่มทดสอบร้านเดียวก่อนขยายจำนวนร้าน

ใช้ SWOT แยกปัจจัยภายในและภายนอก: จุดแข็งและจุดอ่อนเป็นสิ่งในทีม/ธุรกิจ เช่น รู้จักร้านแต่ทีมพัฒนามีน้อย โอกาสและภัยคุกคามมาจากสภาพแวดล้อม เช่น คนต้องการประหยัดเวลาหรือมีคู่แข่งใหม่ การวิเคราะห์ควรลงท้ายด้วยการตัดสินใจ ไม่ใช่รายชื่อสี่ช่อง

02 / ITDS294

SDLC: เปลี่ยนเป้าหมายให้เป็นระบบทีละขั้น

ลองเดินผ่านวงจรพัฒนาระบบ

กดแต่ละขั้น หรือใช้ปุ่มก่อนหน้าและถัดไปเพื่อดูเหตุและผล

ระดับตัวอย่าง “ลดการรอรับอาหาร”
Business objectiveลูกค้าได้รับอาหารในเวลานัด
System functionalityจำกัดจำนวนออร์เดอร์ต่อช่วงเวลาและแจ้งสถานะ
Information requirementรายการอาหาร เวลารับ ความจุร้าน และสถานะออร์เดอร์

Logical design วาดหน้าที่ กระบวนการ และข้อมูลที่ต้องเชื่อมกัน ส่วน physical design ระบุการนำไปใช้จริง เช่น โครงสร้างเครื่อง ซอฟต์แวร์ และวิธีสำรอง ทั้งสองต้องสอดคล้องกับความต้องการเดียวกัน

03 / ITDS294

ซอฟต์แวร์แต่ละชั้นรับผิดชอบต่างกัน

ชั้นหน้าที่สิ่งที่ไม่ควรฝากให้ชั้นนี้ลำพัง
Web server / presentationส่งทรัพยากรและแสดงหน้าร้านการตรวจยอดเงินจากค่าที่ผู้ใช้ส่งมาอย่างเดียว
Application serverประมวลกฎธุรกิจ เช่น ส่วนลดและสถานะออร์เดอร์การเก็บข้อมูลทั้งหมดเฉพาะในหน้าจอ
Database / backend systemsเก็บสินค้า ลูกค้า ราคา และรายการการคิดว่ามีฐานข้อมูลแล้วข้อมูลจะถูกต้องเอง

สไลด์เปรียบเทียบสถาปัตยกรรมสองชั้นกับหลายชั้น การแยกชั้นช่วยแยกภาระและความรับผิด แต่เพิ่มการเชื่อมต่อที่ต้องดูแล เลือกตามความซับซ้อนและขนาดจริง พร้อมพิจารณา CMS หรือแพลตฟอร์มร้านสำเร็จรูปเมื่อฟังก์ชันมาตรฐานตอบโจทย์

เกณฑ์เลือกแพลตฟอร์มควรครอบคลุมฟังก์ชัน โมเดลธุรกิจ การเชื่อมระบบ ประสิทธิภาพ การขยายตัว ภาษา/พื้นที่ และต้นทุนรวม การทำเองหรือจ้างพัฒนาต่างต้องมีแผนและเจ้าของความต้องการ

04 / ITDS294

ทดสอบให้ตรงคำถาม และดูแลหลังเปิดใช้

การทดสอบใช้ตอบคำถามใดตัวอย่าง
Unitส่วนย่อยทำงานถูกไหมสูตรส่วนลดคำนวณถูก
Systemส่วนต่าง ๆ ทำงานร่วมกันได้ไหมสั่ง → จ่าย → ร้านรับออร์เดอร์ได้
Acceptanceตรงกับเป้าหมายธุรกิจไหมร้านและลูกค้าทดลองใช้แล้วรับอาหารตามเวลานัดได้
A/Bทางเลือกใดให้ผลดีกว่าในกลุ่มที่เปรียบเทียบได้ทดสอบข้อความปุ่มสองแบบด้วยเกณฑ์เดียวกัน

หลังเปิดใช้ต้องติดตามข้อผิดพลาด ความเร็ว ลิงก์ ราคา เนื้อหา และข้อเสนอแนะ การปรับประสิทธิภาพมองได้ทั้งเนื้อหา การสร้างหน้า และการส่งหน้า ไม่ใช่อัปเกรดเครื่องอย่างเดียว

ลองคิด: ปุ่มใหม่ทำให้ยอดคลิกเพิ่ม แปลว่าขายดีขึ้นหรือไม่

ยังสรุปไม่ได้ ต้องดูว่าคลิกนำไปสู่รายการที่สำเร็จเพิ่มหรือไม่ ตรวจว่ากลุ่มทดลองและช่วงเวลาเทียบกันได้ และดูผลข้างเคียง เช่น การยกเลิกหรือคำร้องเรียนด้วย

05 / ITDS294

Mobile presence: เลือกจากงานของลูกค้า

รูปแบบจุดเด่นข้อแลกเปลี่ยน
Mobile websiteเปิดผ่านลิงก์และปรับหน้าให้เหมาะกับจอต้องออกแบบให้ใช้ง่ายบนจอเล็ก
Mobile web appงานโต้ตอบผ่านเบราว์เซอร์ความสามารถขึ้นกับเบราว์เซอร์และอุปกรณ์
Native appใช้ความสามารถของระบบปฏิบัติการได้ลึกต้องดูแลการพัฒนาและการแจกจ่ายแอป
Hybrid appเว็บอยู่ในตัวหุ้มแอป ใช้ส่วนเชื่อมกับอุปกรณ์ต้องดูแลทั้งเนื้อหาเว็บและตัวแอป

อ่านราคาและเงื่อนไขได้ทันที ปุ่มแตะง่าย แบบฟอร์มสั้น และสถานะชัดเจน มักสำคัญต่อการซื้อกว่าการมีเอฟเฟกต์มาก การทำ personalization คือปรับข้อเสนอให้บุคคล ส่วน customization คือให้ปรับสินค้าหรือประสบการณ์ตามความต้องการ

06 / ITDS294

กรณีศึกษา Skyscanner: โครงสร้างพื้นฐานต้องรองรับคุณค่า

กรณีศึกษาอธิบายการรวมข้อมูลเที่ยวบิน โรงแรม และรถเช่าให้วางแผนทริปง่ายขึ้น พร้อมบริการข้อมูลให้ผู้เล่นในอุตสาหกรรม ความท้าทายจึงมีทั้งความถูกต้อง ความเร็ว การขยายตามผู้ใช้ และการเชื่อมหลายแหล่ง

แนวคำตอบ 1 · ทำไมเลือก AWS

เอกสารระบุการเพิ่ม/ลดทรัพยากรตามปริมาณใช้งาน ประสิทธิภาพ และการบริหารต้นทุนเป็นเหตุผลหลัก การใช้ cloud สอดคล้องกับบริการที่มีโหลดเปลี่ยนแปลง แต่ยังต้องติดตามค่าใช้จ่ายและออกแบบให้เหมาะสม

แนวคำตอบ 2 · การตัดสินใจเชิงกลยุทธ์ที่สำคัญ

ขยายต่างประเทศ เพิ่มโรงแรมและรถเช่าจากบริการเที่ยวบิน และพัฒนาแอปที่รวมงานวางแผนทริปเข้าด้วยกัน การซื้อกิจการที่เกี่ยวข้องช่วยเติมความสามารถและความสัมพันธ์ที่ยังขาด

แนวคำตอบ 3 · แอปสร้างประโยชน์อย่างไร

ช่วยค้นและเปรียบเทียบหลายบริการในบริบทการเดินทาง กลับมาทำต่อจากการค้นล่าสุดได้ และลดการสลับหลายเว็บไซต์ คุณค่าคือความต่อเนื่องและความสะดวก ไม่ใช่เพียงการมีไอคอนบนมือถือ

แนวคำตอบ 4 · รองรับผู้ใช้ต่างประเทศอย่างไร

ใช้เว็บไซต์หลายประเทศและหลายภาษา พร้อมเครือข่ายผู้ให้บริการท่องเที่ยว การขยายตลาดต้องดูความเข้าใจของผู้ใช้และการส่งมอบจริง ไม่ใช่แปลปุ่มอย่างเดียว

แนวคำตอบ 5 · แข่งขันได้ด้วยอะไร

รวมตัวเลือกให้เปรียบเทียบง่าย ออกแบบใช้งานสะดวก และดูแลเทคโนโลยีให้รวดเร็วปรับขนาดได้ เอกสารยังกล่าวถึงข้อมูลการปล่อยคาร์บอนและการพัฒนาซอฟต์แวร์ร่วมกัน การได้เปรียบเป็นผลรวมของคุณค่า ข้อมูล และการปฏิบัติงาน ไม่ใช่ชื่อบริการ cloud เพียงตัวเดียว
