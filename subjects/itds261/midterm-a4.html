1 · SE และ Project

Software: คำสั่ง + โครงสร้างข้อมูล + เอกสาร

Business need: ทำไมต้องเปลี่ยน
Business process: งานสำเร็จอย่างไร

4P: People, Problem, Process, Project
POMA: Planning, Organizing, Monitoring, Adjusting

WBS แตกงาน · พิจารณา scope / time / cost / quality
ทีม n คน: ช่องทางสื่อสาร n(n−1)/2

4 · Use Case

กำหนด boundary → actors → เป้าหมาย → associations → ความสัมพันธ์ที่มีเหตุผล

Actor: บทบาท ไม่ใช่ชื่อบุคคล
Use case: เป้าหมายงาน ใช้ชื่อกริยา

include: base → included
extend: extension → base
Association ไม่ใช่ลำดับเวลา

ฐานข้อมูลภายในไม่ใช่ external actor โดยอัตโนมัติ

2 · เลือก Process

Waterfall: requirements ชัดและคงที่ จัดงานเป็นระยะ

Incremental: ส่งมอบความสามารถทีละชุด

Spiral: ความเสี่ยงนำรอบ ทดลองจุดเสี่ยง

Agile: feedback สม่ำเสมอและนำมาปรับงาน

อธิบายเหตุผลจากเงื่อนไขของโจทย์

4 · Narrative

ชื่อเดียวกับ diagram · primary actor · goal
precondition · trigger · main flow · exception · postcondition

Precondition: สิ่งที่เป็นจริงก่อนเริ่ม
Trigger: สิ่งที่เริ่ม use case

Main flow สลับ actor / system
Exception ระบุจุดเบี่ยงและผลลัพธ์
Success กับ failure ต้องให้ผลสอดคล้องกัน

3 · Requirements

User / system: แกนระดับรายละเอียด
FR / NFR: แกนชนิด — ทำอะไร / คุณภาพและข้อจำกัด

Elicit → วิเคราะห์ / ต่อรอง → specification → validation → change management

Validation: validity, consistency, completeness, realism, clarity, verifiability, traceability

NFR ต้องมีงานที่วัด เกณฑ์ และบริบท
Requirement ID → design → test

5 · Context DFD

Process 0: หนึ่ง process แทนทั้งระบบ
External entities อยู่ภายนอก · ไม่เปิด stores ภายใน

Process: กริยา · Flow: ข้อมูล/นาม
Store: ข้อมูลคงอยู่
ทุก flow มี process อย่างน้อยหนึ่งปลาย

ข้อมูลเข้าเพียงพอสร้างข้อมูลออกหรือไม่
Boundary ตรงกับ scenario / narrative หรือไม่
รักษาความหมายของ parent / child ให้ balance

7 · Interface Design

เข้าใจ user / task / environment
Analysis → design → construction → validation

Mandel: ผู้ใช้ควบคุมได้ · ลดภาระจำ · สม่ำเสมอ

Low fidelity ถามโครงและ flow
High fidelity ถามคำและ interaction ละเอียด

ตรวจสามหลักฐานร่วมกัน

ตัวอย่างซื้อตั๋ว: actor ซื้อและจ่าย → ระบบตรวจผล → ออกตั๋วเมื่อสำเร็จ

Diagram มีเป้าหมาย · narrative มีเงื่อนไข/ข้อผิดพลาด · context มีรายการซื้อ ผลชำระ ตั๋ว และข้อความผิดพลาด

ตรวจชื่อ ขอบเขต และข้อมูลเข้าออกให้ตรงกัน
