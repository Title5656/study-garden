คำอธิบายและตัวอย่างสถานการณ์ในบทนี้เรียบเรียงเพิ่มเพื่อช่วยเรียนรู้จากเอกสารรายวิชา ไม่ใช่เฉลยข้อสอบทางการ แหล่งต้นฉบับระบุไว้ท้ายบท

คำศัพท์ที่ใช้ในบทนี้

ECMAScript / JavaScript / engine
ECMAScript คือมาตรฐานกติกาของภาษา JavaScript ใช้กติกานี้ ส่วน engine คือโปรแกรมที่นำกติกาไปประมวลผลโค้ด การอยู่ในสไลด์ไม่ได้ยืนยันว่า engine ทุกตัวรองรับ
Syntax / feature / proposal
Syntax คือรูปแบบการเขียนคำสั่ง Feature คือความสามารถของภาษา Proposal คือข้อเสนอที่ต้องแยกจากความสามารถที่บรรจุในมาตรฐานแล้ว
Synchronous / asynchronous
Synchronous คือทำงานตามลำดับในช่วงการเรียกนั้น Asynchronous คือจัดการงานที่ผลอาจพร้อมภายหลัง ทำให้โค้ดส่วนอื่นดำเนินต่อระหว่างรอได้
Promise / pending / fulfilled / rejected
Promise คือ object ที่แทนผลสำเร็จหรือความล้มเหลวของงาน Pending คือยังรอ Fulfilled คือสำเร็จพร้อมค่า และ rejected คือล้มเหลวพร้อมเหตุผล สองอย่างหลังเรียกรวมว่า settled
Callback / async / await
Callback คือฟังก์ชันที่ส่งให้โค้ดอื่นเรียก async ทำให้ฟังก์ชันคืน Promise และ await พักการทำงานของฟังก์ชัน async ณ จุดนั้นจน Promise จบ โดยไม่หยุดทั้งหน้าเว็บ
Nullish / default / shallow copy
Nullish หมายถึง null หรือ undefined Default คือค่าที่ใช้เมื่อไม่มีค่าตามเงื่อนไข ส่วน shallow copy คือสำเนาชั้นนอกที่อาจยังอ้าง object ชั้นในร่วมกัน

01 · มาตรฐานภาษา ≠ การรองรับ

ถ้าโค้ดตัวอย่างใช้ได้ในเครื่องเพื่อน แต่เครื่องเราแจ้งว่าไม่มี method ต้องโทษโค้ดหรือมาตรฐาน? ต้องตรวจสองเรื่องแยกกัน คือภาษากำหนดความสามารถนี้หรือยัง กับโปรแกรมที่กำลังรันมีความสามารถนั้นหรือยัง Runtime คือสภาพแวดล้อมขณะรัน; polyfill คือโค้ดเสริมพฤติกรรม API ที่ขาด; transpilation คือการแปลงรูปแบบโค้ดก่อนรัน การเพิ่มฟังก์ชันไม่ช่วยให้ parser เก่าอ่าน syntax ใหม่ออกเอง

ECMAScript (ES) คือข้อกำหนดว่าภาษาทำงานอย่างไร ส่วน JavaScript engine เป็นผู้ทำให้ข้อกำหนดนั้นทำงานจริง HTML DOM และ API ของเบราว์เซอร์เป็นอีกชั้นหนึ่ง การรู้ว่าฟีเจอร์อยู่ใน ES รุ่นใดจึงไม่ใช่หลักฐานว่าใช้ได้ในทุกเครื่อง

ES6 คือชื่อรุ่นเดียวกับ ES2015 จากนั้นมีการตั้งชื่อรุ่นตามปี จำเส้นทางแบบ “ปัญหาที่ฟีเจอร์ช่วยแก้” จะเข้าใจง่ายกว่าท่องรายการคำศัพท์อย่างเดียว

อ่านสไลด์อย่างมีบริบท
ไฟล์นี้รวมฟีเจอร์หลายปีและข้อเสนอทดลองไว้ด้วยกัน เว็บแยกแนวคิดออกจากสถานะมาตรฐาน และมีหมายเหตุแก้จุดคลาดเคลื่อนท้ายบท ตรวจเอกสารอ้างอิงเมื่อ 18 ตุลาคม 2026
สิ่งที่ต้องแยก คำถามที่ควรถาม
มาตรฐาน (specification) ภาษาได้กำหนดพฤติกรรมนี้อย่างเป็นทางการหรือยัง?
ข้อเสนอ (proposal) กำลังพัฒนา เปลี่ยนแปลง หรือถูกยุติไปหรือไม่?
Runtime support browser ที่ใช้อยู่มี API นี้จริงไหม?
Polyfill / Transpilation ขาด method ที่เสริมได้ หรือ syntax ที่ต้องแปลงก่อนรัน?

สำหรับเว็บนี้ ทุกกิจกรรมใช้ JavaScript ที่รองรับแพร่หลาย ส่วนฟีเจอร์ใหม่บางตัวเป็นตัวอย่างให้อ่าน ไม่ได้เรียก API รุ่นใหม่โดยไม่มีการตรวจ

ถ้าเบราว์เซอร์เก่าอ่านเครื่องหมาย syntax ใหม่ไม่ออก การเขียน if ครอบบรรทัดนั้นเพียงอย่างเดียวพอไหม?

ไม่พอ เพราะต้อง parse โค้ดก่อนเริ่มทำ if กรณี syntax ต้องแปลงโค้ดก่อนส่งหรือแยกไฟล์ให้เหมาะกับเครื่อง ส่วนการขาด method ที่ยังใช้ syntax เดิมอ่านได้จึงค่อยตรวจ typeof ก่อนเรียกได้

02 · ES2015: เขียนให้น้อย แต่ชัดขึ้น

ถ้าข้อมูลผู้ใช้มีหลายช่อง แต่ต้องการแค่ชื่อกับรายการที่เหลือ เราจะเขียนให้เห็นเจตนานี้โดยตรงได้อย่างไร? Destructuring คือการแยกค่ามาผูกกับชื่อ; rest รวบรวมส่วนที่เหลือ; spread กระจายสมาชิกออกไป ส่วน iterable คือค่าที่ขอสมาชิกทีละตัวผ่านกติกาการวนได้ และ iterator คือ object ที่ทำหน้าที่ส่งสมาชิกเหล่านั้น คำว่า key–value คือคู่ของกุญแจค้นหากับข้อมูลที่ผูกไว้

ES2015 ทำให้การจัดข้อมูลและฟังก์ชันคล่องขึ้น: let/const จำกัดขอบเขต, arrow ย่อ callback, class จัดแบบแผน object, template literal แทรกค่าในข้อความ และ default parameter ลดการตรวจค่าซ้ำ

JAVASCRIPT
const topic = "JavaScript";
const greeting = `วันนี้อ่าน ${topic}`;
const welcome = (name = "เพื่อน") => `สวัสดี ${name}`;
const scores = [5, 8, 10];
const [first, ...others] = scores; // destructuring + rest
const copy = [...scores, 12];     // spread → [5, 8, 10, 12]
const user = { name: "Mint", level: 2 };
const { name } = user;
for (const score of scores) { console.log(score); }
เครื่องมือ จำเป็นภาพ ระวัง
Template literal ข้อความที่มีช่อง ${expression} ใช้ backtick; tagged template ส่งส่วนข้อความกับค่าให้ฟังก์ชันจัดการ
Default parameter ค่าเริ่มต้นของช่องรับค่า ใช้เมื่อ argument เป็น undefined หรือไม่ได้ส่ง ไม่แทน null
Spread (...) กระจายสมาชิกออก สำเนาเป็น shallow copy; object spread มาตรฐานใน ES2018
Rest (...) รวบรวมค่าที่เหลือ rest parameter ต้องอยู่ท้ายพารามิเตอร์
Destructuring หยิบข้อมูลตามตำแหน่งหรือชื่อ ไม่ได้ deep clone object
for…of หยิบค่าทีละตัวจาก iterable plain object ไม่ iterable โดยอัตโนมัติ

Map / Set และกลุ่ม Weak

โครงสร้าง สิ่งที่เก็บ เมื่อไรควรใช้
Map key–value; key เป็นค่าได้หลายชนิด ต้องวนรายการหรืออ่าน size
Set ค่าที่ไม่ซ้ำ ตัดค่าซ้ำหรือเช็กสมาชิก
WeakMap key แบบ weak reference ผูก metadata กับ object โดยไม่ยืดอายุ object เพราะ key นี้เพียงอย่างเดียว
WeakSet สมาชิกที่ถือแบบ weak reference ติดตาม object โดยไม่ต้องไล่สมาชิกทั้งหมด

WeakMap ไม่มี size หรือ iterator สำหรับไล่รายการ key ปัจจุบันใช้ object และ non-registered symbol เป็น key ได้ (การรองรับ symbol เป็นส่วนเพิ่มใน ES2023) อย่าสรุปว่า Map “เร็วกว่าเสมอ” เพราะความเร็วขึ้นกับงานและ engine

JAVASCRIPT
const unique = [...new Set(["DOM", "JS", "DOM"])]; // ["DOM", "JS"]
const points = new Map();
points.set("Mint", 10);
points.get("Mint"); // 10
"ha".repeat(2); // "haha"
[4, 9, 12].find(n => n > 5);      // 9
[4, 9, 12].findIndex(n => n > 5); // 1
Object.is(NaN, NaN);              // true ต่างจาก NaN === NaN

คำถาม · const a = [{x: 1}]; const b = [...a]; b[0].x = 9; a เปลี่ยนไหม?

a[0].x เป็น 9 เพราะ array ใหม่ยังเก็บการอ้างอิง object ก้อนเดิม spread คัดลอกเพียงชั้นนอก

ตาม const [first, ...others] = [5, 8, 10]: first รับสมาชิกตำแหน่ง 0 คือ 5 ส่วน others รวบรวมที่เหลือเป็น [8, 10] ต่อมา [...others, 12] กระจาย 8 กับ 10 แล้วเติม 12 เป็น [8, 10, 12] เครื่องหมาย ... เหมือนกัน แต่ดูตำแหน่งว่ากำลังรับค่าหรือสร้างค่า

JSON คือรูปแบบข้อความสำหรับแลกข้อมูล ส่วน JSON.stringify แปลงค่าตัวอย่างเป็นข้อความรูปแบบ JSON เพื่อให้เห็นวงเล็บและสมาชิกชัดเจนใน Console ไม่ได้เปลี่ยน array ต้นฉบับ

const [first, ...others] = [5, 8, 10];
const expanded = [...others, 12];
console.log(first);
console.log(JSON.stringify(expanded));
welcome(null) ใช้ชื่อ default เหมือน welcome() หรือไม่?

ไม่เหมือน default parameter ใช้เมื่อไม่ได้ส่งค่าหรือส่ง undefined ส่วน null เป็นค่าที่ส่งมาอย่างชัดเจน จึงต้องกำหนดเงื่อนไขเพิ่มเองหากต้องการให้ null ใช้ค่า default ด้วย

03 · Promise และ async/await

ระหว่างรอข้อมูล ถ้าหน้าเว็บหยุดตอบสนองทั้งหมด ผู้ใช้จะกดอย่างอื่นไม่ได้ เราจึงต้องแยก “เริ่มงาน” ออกจาก “ใช้ผลเมื่อพร้อม” Asynchronous operation คืองานที่ผลพร้อมภายหลัง ส่วน Promise คือ object ที่แทนการสำเร็จหรือความล้มเหลวพร้อมผลของงานนั้น ตามเอกสาร ECMAScript หน้า PDF 10–12

งานอย่างขอข้อมูลใช้เวลาจบไม่เท่ากัน Promise เป็นตัวแทนผลลัพธ์ที่ยังไม่มาถึง คล้ายใบรับงาน: ตอนรับงานยัง pending แล้วเปลี่ยนเป็น fulfilled เมื่อสำเร็จ หรือ rejected เมื่อล้มเหลว สองสถานะหลังเรียกรวมว่า settled

Promise เดิม settled ได้ครั้งเดียว; then รับผลสำเร็จ catch รับข้อผิดพลาด และ finally ทำงานปิดท้ายโดยทั่วไปไม่ว่าผลจะเป็นอย่างไร โดย finally เป็นส่วนเพิ่มภายหลัง ES2015

ตามลำดับก่อนใช้ async/await

ตัวอย่างสมมตินี้ใช้ Promise.resolve สร้าง Promise ที่สำเร็จแล้ว เพื่อแยกเรื่อง “ค่าพร้อม” ออกจาก “ฟังก์ชันรับผลเริ่มทำงานเมื่อไร” ไม่ส่งคำขอไปเว็บไซต์อื่น

console.log("เริ่ม");
Promise.resolve("ข้อมูลพร้อม").then(function (message) {
  console.log(message); // รับผลหลังคำสั่งต่อเนื่องชุดนี้จบ
});
console.log("ทำงานอื่นต่อ");

ผลใน Console ตามลำดับ: เริ่ม → ทำงานอื่นต่อ → ข้อมูลพร้อม

  1. บรรทัดแรกพิมพ์ “เริ่ม” ทันที
  2. Promise.resolve ทำให้ผลสำเร็จพร้อมค่า “ข้อมูลพร้อม” ส่วน then ลงทะเบียน callback หรือฟังก์ชันรับผลไว้ ยังไม่เรียกมันตรงบรรทัดนี้
  3. โปรแกรมจึงพิมพ์ “ทำงานอื่นต่อ” ให้จบก่อน
  4. เมื่อคำสั่งต่อเนื่องชุดปัจจุบันจบ จึงเรียกฟังก์ชันรับผลและพิมพ์ “ข้อมูลพร้อม” แม้ Promise จะสำเร็จอยู่ก่อนแล้ว
Promise สำเร็จแล้ว แปลว่า then ทำงานแทรกทันทีหรือไม่?

ไม่ใช่ ความพร้อมของผลกับลำดับการเรียก callback เป็นคนละเรื่อง ในตัวอย่างนี้ then ทำงานหลังคำสั่ง console.log สุดท้าย จึงไม่ควรเขียนโค้ดที่อ่านตัวแปรผลลัพธ์ทันทีแล้วคาดว่ารับค่าจาก then แล้ว

เมื่อผลอาจสำเร็จหรือล้มเหลว

JAVASCRIPT
function loadNote(ok) {
  return new Promise((resolve, reject) => {
    if (ok) resolve("บทเรียนพร้อมแล้ว");
    else reject(new Error("โหลดไม่สำเร็จ"));
  });
}
loadNote(true)
  .then(note => console.log(note))
  .catch(error => console.log(error.message))
  .finally(() => console.log("หยุดแสดงตัวหมุน"));

Promise lab · เลือกผลของงาน

ลองเลือกผลสำเร็จหรือล้มเหลว แล้วสังเกตว่าปุ่มอีกทางถูกปิด เพราะ Promise เดิมจบได้ครั้งเดียว แบบจำลองสถานะเพื่อการเรียนรู้ ไม่มีการส่งคำขอเครือข่ายจริง กดสร้างใหม่เพื่อเริ่มจาก pending อีกครั้ง

pending …

สร้าง Promise ใหม่ ยังไม่มีผลลัพธ์ เลือกจำลองผลสำเร็จหรือล้มเหลว

async/await อ่านเหมือนลำดับงาน แต่ไม่หยุดทั้งเว็บ

async function คืน Promise เสมอ ส่วน await พักการทำงานต่อของฟังก์ชันนั้นจน Promise settled ถ้า rejected จะ throw ที่จุด await จึงใช้ try…catch ได้ งานส่วนอื่นของเว็บยังทำต่อได้เมื่อไม่ถูกโค้ด synchronous ที่หนักบล็อกไว้

JAVASCRIPT
async function readNote() {
  try {
    const note = await loadNote(true);
    console.log(note);
  } catch (error) {
    console.log(error.message);
  }
}
readNote();
console.log("ข้อความนี้ไม่ต้องรอ readNote จบ");

for await…of วนค่าจาก async iterable โดยรอค่าที่ได้ในแต่ละรอบ แต่ถ้าภายใน body เรียกฟังก์ชัน async อีกตัวแล้วไม่ await งานนั้น ก็ไม่ได้แปลว่าจะรอให้งานนั้นเสร็จก่อนรอบถัดไป

คำถาม · async function f() { return 3; } แล้ว f() === 3 เป็น true ไหม?

เป็น false เพราะ f() คืน Promise ไม่ใช่เลข 3 โดยตรง ต้องใช้ await f() ภายในบริบทที่อนุญาต หรือ f().then(...) เพื่ออ่านค่า

04 · แผนที่ฟีเจอร์ ES2016–ES2023

เมื่อเห็น method ใหม่ ให้ถามก่อนว่าต้องการ “ค้นหา” “แปลง” หรือ “ทำสำเนา” เช่น จะเรียงคะแนนแล้วรักษาลำดับเดิมไว้หรือไม่? ตารางรุ่นด้านล่างช่วยค้นเครื่องมือ แต่การทำนายค่าก่อนและหลังเรียกต่างหากที่ยืนยันว่าใช้เป็น Own property คือ property ของ object นั้นเอง; inherited property มาจากต้นแบบ; enumerable คือมีสิทธิ์ปรากฏในการไล่รายการบางแบบ และ descriptor คือข้อมูลกำกับ property เช่นแก้ค่าได้หรือไม่

ตารางนี้จับคู่รุ่นกับปัญหาที่แก้ ใช้เป็นจุดทวนก่อนทำโจทย์ ไม่ใช่รายการฟีเจอร์ทั้งหมดของแต่ละมาตรฐาน

รุ่น เครื่องมือในสไลด์ ภาพจำ / ตัวอย่าง
2016 includes, ** [2, 4].includes(4) → true; 2 ** 3 → 8
2017 padStart/padEnd, Object.values/entries, descriptors, async/await "7".padStart(2, "0") → "07"; entries ได้คู่ [key, value]
2018 Object rest/spread, for await…of แยก/รวม property และวนข้อมูลที่มาภายหลัง
2019 flat, flatMap, fromEntries, trimStart/trimEnd [1, [2]].flat() → [1, 2]; flatMap ทำ map แล้ว flatten หนึ่งระดับ
2020 BigInt, ??, ?., matchAll เก็บจำนวนเต็มใหญ่; เลือก fallback; อ่าน property ที่อาจไม่มี
2021 1_000, replaceAll, &&= / ||= / ??=, WeakRef คั่นหลักเลขเพื่ออ่านง่าย; แทนข้อความทุกตำแหน่ง; กำหนดค่าตามเงื่อนไข
2022 at, Object.hasOwn, Error cause, top-level await at(-1) อ่านตัวท้าย; hasOwn ไม่รวม property ที่สืบทอด; await ระดับบนใน module
2023 findLast/findLastIndex, symbol WeakMap keys, change-by-copy ค้นย้อนจากท้าย และแก้ array ผ่านสำเนาใหม่

รายละเอียดสั้น ๆ ที่ช่วยอ่านโจทย์

  • Object.entries() คืนคู่ key–value ของ own enumerable string-keyed properties ส่วน Object.fromEntries() ประกอบคู่กลับเป็น object ใหม่ และ Object.getOwnPropertyDescriptors() อ่านรายละเอียดอย่าง writable/get/set
  • Trailing comma ในพารามิเตอร์/อาร์กิวเมนต์ช่วยจัดหลายบรรทัด แต่ JSON ไม่อนุญาต trailing comma
  • matchAll() คืน iterator ของผล match; ถ้าส่ง RegExp ให้ใช้ flag g เมื่อต้องการจับทุกตำแหน่ง
  • WeakRef และ finalization ไม่รับประกันเวลาที่ garbage collection จะเกิด อย่าใช้เป็นกำหนดเวลางานสำคัญ
  • toSorted() และ toReversed() คืน array ใหม่ ขณะที่ sort/reverse แก้ต้นฉบับ แต่การคัดลอกยังไม่ใช่ deep copy
JAVASCRIPT
const original = [30, 2, 10];
const sorted = original.toSorted((a, b) => a - b);
// original: [30, 2, 10]   sorted: [2, 10, 30]
const last = original.at(-1); // 10
const latest = [3, 8, 12].findLast(n => n < 10); // 8

อ่านการเรียงตัวเลขทีละขั้น: original เป็น [30, 2, 10]; callback (a, b) => a - b บอกลำดับเชิงตัวเลข; toSorted สร้าง array อีกชุดเป็น [2, 10, 30]; original ยังเรียงเหมือนเดิม หากใช้ sort จะเปลี่ยน original ด้วย ส่วนการไม่ส่ง comparator จะเทียบตามรูปข้อความ จึงไม่ใช่ลำดับจำนวนที่ต้องการเสมอ

ถ้า array มี object อยู่ข้างใน toSorted ทำให้แก้ object ในสำเนาได้โดยไม่กระทบต้นฉบับหรือไม่?

ไม่รับประกัน เพราะเป็นสำเนาชั้นนอกและสมาชิกยังอ้าง object เดียวกัน หลัก shallow copy เดียวกับ spread ในหัวข้อก่อนหน้า

05 · เลือกค่า default ให้ถูก

ถ้าลูกค้าใช้คูปองแล้วต้องจ่าย 0 บาท ศูนย์คือคำตอบที่ถูกต้องหรือข้อมูลหาย? ตัวเลือกค่า default ต้องรักษาความหมายของข้อมูล คำว่า fallback คือค่าสำรองที่เลือกเมื่อเงื่อนไขเข้าเกณฑ์ ส่วน short-circuit คือหยุดประเมินเมื่อรู้ผลแล้ว จึงอาจไม่เรียกโค้ดฝั่งขวาเลย

ค่า 0 อาจหมายถึงคะแนนจริง ไม่ใช่ข้อมูลที่หายไป การใช้ || จึงอาจแทนค่าที่ตั้งใจเก็บด้วย fallback โดยไม่รู้ตัว ส่วน ?? ถามเฉพาะว่าเป็น null หรือ undefined หรือไม่

ลองเปลี่ยนค่า แล้วเทียบ || กับ ??

value || "สำรอง"

value ?? "สำรอง"

JAVASCRIPT
const user = { score: 0 };
const score = user.score ?? 10;        // 0
const city = user.address?.city ?? "ยังไม่ระบุ";
let settings = { volume: 0 };
settings.volume ??= 50;                // ยังคงเป็น 0
settings.language ??= "th";           // เพิ่ม language
Operator จะใช้/กำหนดค่าฝั่งขวาเมื่อ รักษาค่า 0 ไหม
|| / ||= ฝั่งซ้ายเป็น falsy ไม่รักษา
?? / ??= ฝั่งซ้ายเป็น null หรือ undefined รักษา
&& / &&= ฝั่งซ้ายเป็น truthy กรณี 0 ไม่ประเมินฝั่งขวา

?. ช่วยเมื่อฐานของการเข้าถึงเป็น null/undefined แต่ไม่ได้ทำให้ตัวแปรที่ไม่เคยประกาศใช้ได้ และไม่ได้ดักทุก exception เช่น missingVariable?.name ยัง ReferenceError ได้

คำถาม · 9007199254740993n + 1 ทำได้ไหม?

ไม่ได้ เป็น TypeError เพราะกำลังบวก BigInt กับ Number ต้องใช้ 1n ให้ชนิดตรงกัน การแปลง BigInt ใหญ่เป็น Number อาจสูญเสียความแม่นยำ

ทดลองเลือก 0, ข้อความว่าง และ null ตามลำดับ ผลของ || เป็น “สำรอง” ทั้งสามครั้ง แต่ ?? ให้ 0, ข้อความว่าง, “สำรอง” ตามลำดับ สังเกตว่าความต่างอยู่ที่เกณฑ์ข้อมูลหาย ไม่ใช่การเลือกตัวดำเนินการที่ใหม่กว่า กดเริ่มใหม่เพื่อกลับไปกรณี 0

const value = 0;
console.log(value || 10);
console.log(value ?? 10);
ถ้าชื่อ address ไม่มีอยู่ใน user แต่ตัวแปร user ถูกประกาศแล้ว user.address?.city ได้อะไร?

ได้ undefined จึงใช้ ?? ต่อเพื่อเลือกข้อความสำรองได้ แต่ถ้าไม่เคยประกาศตัวแปร user การเข้าถึง user?.address ยังทำให้เกิด ReferenceError ได้ optional chaining ไม่ได้ประกาศตัวแปรให้

06 · ES2024–2026 และจุดที่ต้องแยกให้ออก

คำศัพท์สำหรับอ่านตาราง: Unicode เป็นมาตรฐานแทนตัวอักษร ส่วน surrogate เป็นหน่วยรหัสที่ใช้เป็นคู่แทนอักขระบางตัว; lone surrogate คือหน่วยที่ขาดคู่ Shared memory คือหน่วยความจำที่หลายงานใช้ร่วมกัน; thread คือทางเดินการประมวลผล; Atomics เป็นชุดปฏิบัติการประสานการอ่านเขียนนั้น; RegExp คือรูปแบบค้นข้อความ และ capture คือส่วนที่เก็บข้อความที่จับคู่ได้ JSON เป็นรูปแบบข้อความสำหรับแลกข้อมูล; raw หมายถึงข้อความรูปแทนที่ส่งผ่านตามกติกา แทนการสร้างจาก Number ที่ปัดค่าไปแล้ว

ถ้าต้องรวมคะแนนที่มีค่ามากกับค่าน้อยปนกัน หรือส่งไบต์เป็นข้อความ ควรเลือก API จากปัญหาแทนการจำชื่ออย่างเดียว Byte คือข้อมูลขนาด 8 บิต; encoding คือกติกาแปลงรูปแทนข้อมูล ไม่ได้ซ่อนข้อมูลแบบ encryption; precision คือความละเอียดที่แทนตัวเลขได้; realm คือสภาพแวดล้อมที่มีชุด object พื้นฐานของตน เช่น iframe และ lazy คือคำนวณเมื่อขอผล ไม่เตรียมผลทั้งหมดทันที

หัวข้อช่วงท้ายของสไลด์ควรอ่านทั้งแนวคิดและหมายเหตุประกอบ โดยเฉพาะเรื่องชื่อ API ปีมาตรฐาน และ syntax ทดลอง

ฟีเจอร์ช่วงใหม่ที่ปรากฏในเอกสาร

กลุ่ม แนวคิดหลัก ข้อควรระวัง
Unicode ที่สมบูรณ์ isWellFormed / toWellFormed ตรวจหรือแก้ lone surrogate ใน string toWellFormed ไม่ใช่การ normalize หรือแปลภาษา
Shared memory Atomics.waitAsync รอเงื่อนไขแบบไม่บล็อก thread ชื่อ Atomics.waitSync ในสไลด์ไม่ใช่ API มาตรฐาน; แบบบล็อกชื่อ Atomics.wait
JSON modules import … with { type: "json" } ระบุชนิดข้อมูล ตัวอย่างเป็น module; ขึ้นกับ browser/server support
Iterator helpers map/filter/take บน iterator ช่วยประมวลผลตามที่ขอ lazy ต่างจาก array.map ที่สร้าง array ทันที
Set methods union, intersection, difference, symmetricDifference และการตรวจความสัมพันธ์ เช่น A={1,2}, B={2,3}: union={1,2,3}; intersection={2}
RegExp รุ่นใหม่ escape ข้อความ literal, modifier เฉพาะส่วน, ชื่อ capture ซ้ำในทางเลือกที่อนุญาต อย่าใช้ RegExp.escape เป็นการ escape HTML
Promise.try เรียกงานที่อาจ throw หรือคืน Promise แล้วจัดผลเป็น Promise ช่วยรวมเส้นทางจัดการข้อผิดพลาด
Float16Array เก็บ float ขนาด 16 บิต ใช้พื้นที่น้อยลงแต่ precision และช่วงค่าลดลง
Math.sumPrecise ลดความคลาดเคลื่อนจากการรวม Number ทีละค่า ผลสุดท้ายยังเป็น floating point; ไม่ได้แก้ปัญหาทศนิยมทั้งหมด
Error.isError ตรวจ Error ข้าม realm เช่น iframe ต่างจาก instanceof ที่อาจไม่ผ่านข้าม realm
Array.fromAsync รวบรวมค่าจาก iterable/async iterable เป็น array คืน Promise; ต้อง await เมื่อต้องการ array
Map.getOrInsert อ่านค่าหรือใส่ค่าเริ่มต้นถ้ายังไม่มี key รับค่าโดยตรง; แบบคำนวณผ่าน callback คือ getOrInsertComputed
JSON.rawJSON เก็บ raw JSON text เพื่อใช้ขณะ stringify ไม่ย้อนแก้ Number ที่เสีย precision ไปแล้ว และไม่ทำให้การ parse ฝั่งรับแม่นยำอัตโนมัติ
Uint8Array encodings toBase64/toHex และ fromBase64/fromHex ทำงานกับ byte; Base64 เป็น encoding ไม่ใช่ encryption

ชื่อ API และข้อจำกัดเสริมตรวจจาก MDN: Atomics.waitAsync, MDN: Math.sumPrecise และ TC39: Finished proposals

หมายเหตุแก้ความคลาดเคลื่อนจากสไลด์

  • Top-level await อยู่ใน ES2022 และใช้ใน module ไม่ใช่ฟีเจอร์ที่เพิ่งมีใน ES2024
  • Pipeline operator และ decorators ไม่ควรถูกจำรวมว่าเป็นฟีเจอร์ ES2024 ทั้งหมด ต้องตรวจสถานะข้อเสนอและ syntax ที่ใช้จริง
  • Records / Tuples รูปแบบ #{…} และ #[…] ในสไลด์ไม่ใช่ syntax มาตรฐานที่นำไปเปิดใน browser ได้ตามปกติ
  • Temporal จัดการวัน เวลา และเขตเวลาได้ละเอียดกว่า Date; รายการ TC39 ที่ตรวจระบุเป็นข้อเสนอที่เสร็จแล้วและคาดเผยแพร่ปี 2027 จึงไม่ควรยึดหมายเหตุ Stage 3 ในสไลด์เป็นสถานะปัจจุบัน

ตรวจสถานะได้จาก TC39 Active proposals, Inactive proposals และ Finished proposals สถานะข้อเสนอเปลี่ยนตามเวลา

JAVASCRIPT
// ตรวจความสามารถก่อนใช้ method ใหม่
if (typeof Math.sumPrecise === "function") {
  console.log(Math.sumPrecise([1e16, 1, -1e16])); // 1
} else {
  console.log("เครื่องนี้ยังไม่มี Math.sumPrecise");
}
// ไม่ใช้การบวกธรรมดาเป็น fallback ที่อ้างว่าแม่นยำเท่ากัน
เวลาอ่านสอบ: จำวัตถุประสงค์และตัวอย่างของแต่ละฟีเจอร์ก่อน แล้วใช้หมายเหตุแยก “เนื้อหาในสไลด์” จาก “ข้อกำหนดและการรองรับจริง” หากข้อสอบถามอิงปีหรือ syntax ที่คลาดเคลื่อน ควรสอบถามผู้สอนให้ชัด
ต้องส่งไบต์รูปภาพเป็น Base64 จึงบอกได้ไหมว่าคนอื่นอ่านข้อมูลไม่ได้?

ไม่ได้ Base64 เป็น encoding ที่ถอดกลับได้โดยไม่มีกุญแจ ไม่ใช่ encryption เลือกเครื่องมือตามหน้าที่ เช่นเดียวกับ RegExp.escape ที่ช่วยสร้างรูปแบบค้นข้อความ ไม่ได้ทำให้ข้อความปลอดภัยเมื่อนำไปใส่ HTML
