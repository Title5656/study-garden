1.2 Client-side vs Server-side

  • Client-side code = HTML, CSS, JavaScript ที่ รันในเว็บเบราว์เซอร์
  • Server-side code = เขียนด้วยภาษาอะไรก็ได้ เช่น PHP, Python, Ruby, C#, Node.js (JavaScript) และ เข้าถึงระบบปฏิบัติการและไฟล์ตามสิทธิ์ของ process ที่รัน
  • งานหลักของ server-side คือ เลือกว่าจะส่งเนื้อหาอะไรกลับไปให้เบราว์เซอร์ ตาม request ที่เข้ามา
ต้องจำ

Node.js รัน JavaScript นอกเบราว์เซอร์ เช่น ฝั่งเซิร์ฟเวอร์หรือเครื่องมือ command line

1.3 วงจร Request / Response (6 ขั้น)

  1. Client ส่ง HTTP (GET) request ไปยัง Web Server
  2. Web Server รับ request แล้ววิเคราะห์ว่าจะไปเอา resource จากไหน — ถ้าเป็น static resource (ไฟล์สำเร็จรูป) ข้ามไปขั้น 5
  3. ถ้าเป็น dynamic resource จะส่งต่อให้ Web Application (โค้ดฝั่งเซิร์ฟเวอร์) ซึ่งอ่านข้อมูลที่ต้องการจาก Database
  4. เซิร์ฟเวอร์เอาข้อมูลมา รวมกับ HTML template
  5. ส่ง response ที่มี HTML ที่สร้างแล้วกลับไป
  6. Client ได้รับหน้า HTML

1.4 Server, IP Address, Port

  • IP Address ระบุว่าเครื่องไหน เช่น 10.34.111.111 หรือชื่อพิเศษ localhost (= เครื่องตัวเอง)

บท 2 · Node.js คืออะไร และสถาปัตยกรรม

2.1 นิยาม

Node.js คือ JavaScript runtime แบบ asynchronous ที่สร้างบน V8 JavaScript engine ของ Chrome — "สภาพแวดล้อมเซิร์ฟเวอร์แบบ open-source"

  • V8 = ตัวรัน JavaScript (เอนจิน)
  • Node = ห่อ V8 ไว้แล้วเพิ่ม module ให้ใช้ เช่น File system, HTTP, Utilities

2.2 Node.js ต่างจาก JS ในเบราว์เซอร์อย่างไร

JS ในเบราว์เซอร์ Node.js

มี Cookies ไม่มี cookie store แบบเบราว์เซอร์ แต่รับ/ส่ง Cookie ผ่าน HTTP headers ได้

บท 2 · Node.js คืออะไร และสถาปัตยกรรม

2.3 สถาปัตยกรรม: Single-thread Event Loop (Non-blocking)

  1. Request เข้ามา → main thread (เธรดเดียว) รับเรื่อง แล้ว ส่งต่อให้หน่วยที่เหมาะสม (File System / Database / งานอื่นที่ไม่บล็อก)
  2. เธรด ไม่ต้องรอ หน่วยนั้นทำเสร็จ → พร้อมรับ Request 2 ต่อทันที (non-blocking)
  3. เมื่อหน่วยทำงานเสร็จ เธรดจะ ตอบกลับ request นั้น แล้วทำเช่นนี้ต่อไป

เปรียบเทียบ: พนักงานรับออเดอร์คนเดียวในร้านอาหาร รับออเดอร์แล้วส่งให้ครัว (ไม่ยืนรอครัวทำเสร็จ) ไปรับโต๊ะต่อไป พอครัวเสร็จก็มาเสิร์ฟ

  • ✅ เหมาะกับ: highly-scalable, data (I/O) intensive, real-time application

บท 4 · Node Module System (สร้าง module เอง)

4.1 หลักการ Modularity

  • ในตัวอย่าง CommonJS นี้ ทุกไฟล์ JS เป็น module แยก scope
  • module หนึ่งมักมีชุดฟังก์ชันที่เราอยากนำไปใช้ในแอป
  • ตัวแปร/ฟังก์ชันใน module เป็น local/private ของไฟล์นั้น → มีฟังก์ชันชื่อเดียวกันในสองไฟล์ได้ โดยไม่ทับกัน

บท 4 · Node Module System (สร้าง module เอง)

4.2 module.exports — "เปิดประตู" ให้ไฟล์อื่นใช้

ใช้ส่งออกได้หลายแบบ:

// msg.js — ส่งออก "ค่าตรงๆ" (literal)
module.exports = "Hello World!";

// ictgreet.js — ส่งออก "property ของ object"
let message = 'Hello ICT';
module.exports.greetICT = message;

// hello.js — ส่งออก "ฟังก์ชัน" ภายใต้ชื่อ sayHi
let message = 'Hello ICT';
function sayHello(){ console.log("Hello"); }
module.exports.sayHi = sayHello;

4.3 require — นำเข้า module

  • ใช้ relative path (ขึ้นต้น ./) ชี้ไปที่ไฟล์ JS (ไม่ต้องใส่ .js ก็ได้)

module.exports.x = ... object ที่มี property x obj.x / obj.x()

7.5 Routing ด้วย req.url · 1/2

  • เว็บเซิร์ฟเวอร์ตอบ หน้าเว็บ ตาม path เช่น http://localhost:8081/homepage
  • Routing = เมื่อ request เข้า → ส่งไปยังโค้ดที่จัดการ (เช่น ส่งหน้าเฉพาะ)
  • req.url ของ http://localhost:8081/bbq คือ "/bbq"
  • ลำดับตรวจ: "/bbq"? → ใช่: เปิด bbq.html / ไม่ → "/shabu"? → ใช่: เปิด shabu.html / ไม่ → 404 Invalid

โครงสร้างไฟล์ตัวอย่าง: (root)/shabu.html, (root)/bbq.html, routing.js

const http = require("http");
const fs   = require("fs");   // ไว้เปิดไฟล์ HTML

const myServer = http.createServer((req, res) => {
  console.log("Req: " + req.url);
  if (req.url === "/") {
    res.statusCode = 200;
    res.setHeader("Content-Type", "text/plain");
    res.write("Greeting");
    res.end();
  }
  else if (req.url === "/shabu") { /* เหมือน /bbq แต่เปิด ./shabu.html */ }
  else if (req.url === "/bbq") {
    fs.readFile("./bbq.html", function(err, data) {
      if (err) {
        res.statusCode = 500;
        res.end("Cannot read file");
        return;
      }
      res.statusCode = 200;
      res.setHeader("Content-Type", "text/html");  // ← html!
      res.write(data);
      res.end();
    });
  }
  else {
    res.statusCode = 404;                           // 404 = ไม่พบ
    res.setHeader("Content-Type", "text/plain");
    res.write("Invalid requested :(");
    res.end();
  }
});
console.log("Listening on the port 8081");
myServer.listen(8081);

response ไม่ถูกปิด เบราว์เซอร์รอ/โหลดค้าง (ต้องจบ response ด้วย end)

Status code ใดสื่อว่า "สำเร็จ" และใดสื่อว่า "ไม่พบ"?

ดูเฉลย

200 = OK, 404 = ไม่พบ

ต้องการส่งไฟล์ `bbq.html` ให้เบราว์เซอร์แสดงเป็นหน้าเว็บ ต้องตั้ง Content-Type เป็น?

ดูเฉลย

`text/html`

เบราว์เซอร์เปิด `http://localhost:8081/shabu` ค่า `req.url` คือ?

ดูเฉลย

`"/shabu"`

ทำไม log ฝั่งเซิร์ฟเวอร์จึงมี `/favicon.ico` ด้วยทั้งที่เราเปิดแค่ `/`?

ดูเฉลย

เบราว์เซอร์ขอไอคอนของแท็บเองอัตโนมัติอีกหนึ่ง request

เติมโค้ด: ให้เซิร์ฟเวอร์ฟังที่ port 8081 และพิมพ์ข้อความเมื่อพร้อม

ดูเฉลย

`myServer.listen(8081, () => { console.log("Listening on the port 8081"); });`

อ่านโค้ด: `else if(req.url==="/bbq")` เมื่อผู้ใช้เข้า `/bbq/` (มี `/` ท้าย) จะตรงเงื่อนไขหรือไม่?

ดูเฉลย

ไม่ตรง (=== เทียบเป๊ะ) จะตกไป else → 404 *(เสริมความเข้าใจ)*

(เรียงลำดับ) สร้าง server ให้ถูกลำดับ: (a) `res.end()` (b) `require("http")` (c) `listen(8081)` (d) `createServer`

ดูเฉลย

b → d → a (อยู่ใน callback ของ createServer) → c

ผลลัพธ์ของ `module.exports.sayHi = sayHello;` เมื่อไฟล์อื่น `require("./hello")` คืออะไร?

ดูเฉลย

object ที่มี property `sayHi` (เรียกด้วย `.sayHi()`)

เปรียบเทียบ `fs.readFile` กับ `fs.readFileSync` (1 ประโยค)

ดูเฉลย

readFile = async non-blocking ใช้ callback / readFileSync = sync blocking คืนค่าทันทีแต่ทำให้ส่วนอื่นต้องรอ

ถ้าต้องการอ่านไฟล์ 3 ไฟล์ตามลำดับแบบไม่ block มีกี่วิธีและคืออะไร?

ดูเฉลย

ซ้อน callback (nested), Promise, async/await (sync ได้ลำดับแต่ block)

ระบุ `protocol`, `port`, `pathname` ของ `https://www.covid19.com:8080/p/a/t/h?country=TH&time=now`

ดูเฉลย

`https:`, `8080`, `/p/a/t/h`

สร้าง server ควรทำอะไรก่อน listen(8081)?

module.exports.sayHi = sayHello ทำให้ require ได้ค่าแบบใด?

  • string เสมอ
  • ชื่อ sayHello เพียงอย่างเดียว
  • object ที่มี property sayHi เป็นฟังก์ชัน
  • HTML document

object ที่มี property sayHi เป็นฟังก์ชัน

fs.readFile ต่างจาก fs.readFileSync อย่างไร?

  • readFile ใช้ callback แบบ async; readFileSync บล็อกและคืนผลโดยตรง
  • ทั้งคู่บล็อกเหมือนกัน
  • readFileSync ใช้ได้เฉพาะใน browser
  • readFile ไม่รับ error
ดูเฉลย

readFile ใช้ callback แบบ async; readFileSync บล็อกและคืนผลโดยตรง

readFile เริ่มงาน I/O แล้วให้ event loop ทำงานต่อ ผลมาใน callback ส่วน readFileSync รออ่านจบก่อนทำบรรทัดต่อไป

อ่านไฟล์ต่อกัน 1 → 2 → 3 โดยไม่บล็อก ใช้วิธีใด?

  • readFileSync สามครั้ง
  • เรียก readFile สามครั้งพร้อมกันแล้วหวังลำดับ
  • เพิ่มเวลารอเท่ากัน
  • await fs.promises.readFile ทีละไฟล์
ดูเฉลย

await fs.promises.readFile ทีละไฟล์

await ทีละงานใน async function รอผลแบบไม่บล็อก event loop; nested callback ก็ทำได้ แต่โค้ดซ้อนมากขึ้น

https://example.com:8080/p/a?country=TH มี protocol, port, pathname อะไร?

  • name=/a/b, base=c.txt

  • name=c, base=c.txt

name ไม่รวมนามสกุล ส่วน base คือชื่อไฟล์พร้อมนามสกุล; dir คือ /a/b

เทียบ req.url === "/bbq" แล้วรับ /BBQ จะได้อะไรในตัวอย่าง?

  • 200 และหน้า BBQ
  • 404 เพราะตัวพิมพ์ต่างกัน
  • 301 โดยอัตโนมัติ
  • เปลี่ยนเป็น /bbq เสมอ
ดูเฉลย

404 เพราะตัวพิมพ์ต่างกัน

งานใดทำให้ event loop ติดค้างได้ แม้แอปใช้ async I/O?

  • รอ callback อ่านไฟล์
  • รอ response จากฐานข้อมูล
  • วนคำนวณ JavaScript หนักบน main thread
  • รับ request ใหม่ขณะที่รอ I/O
ดูเฉลย

วนคำนวณ JavaScript หนักบน main thread
